# 可驗證的 AI 工作流程｜把 Prompt 寫成可執行的工作規格

一個好的進階 Prompt，不只說「幫我完成什麼」，還會交代 AI：**先做什麼、什麼情況要換作法、如何檢查，以及何時停止**。

你可以把它想成用自然語言寫演算法。它不需要真的寫成程式碼，卻能借用程式設計的思維，讓 AI 的工作更有條理、更容易檢查。

> 本章目標：學生能寫出一個包含「多步驟流程、條件判斷、驗證與停止條件」的可複製 Prompt。

---

## 1｜為什麼單一句指令不夠？

簡單任務可以直接交辦，例如「把這段文字摘要成 100 字」。但當任務同時包含規劃、產出、檢查與修正時，只說最終目標，AI 容易自行猜測過程與標準。

例如，這句話太籠統：

```text
幫我設計一份 Python 小考。
```

改成工作流程後，AI 知道要先分析範圍，再出題，最後檢查題目是否符合要求：

```text
請為 Python 初學者設計一份 20 分鐘小考。
先列出本次要評量的觀念，再設計題目與答案；
完成後檢查每一題是否只使用學生已學過的 if、for 與串列。
若有超出範圍的語法，請改寫題目後重新檢查。
```

重點不是 Prompt 寫得很長，而是**工作順序與品質標準明確**。

---

## 2｜多步驟：先規劃，再產出

多步驟 Prompt 要用編號清楚指定先後順序。每一步最好都有可看見的產出，使用者才能知道 AI 是否真的完成該步驟。

### 可直接複製的模板

```text
你是一位［角色］。請協助我完成［總目標］。

請依序進行：
1. 先分析我提供的資料，列出重要資訊、限制與缺漏。
2. 根據分析，提出處理／規劃方向。
3. 產生第一版成果。
4. 依照下方的檢查標準驗證成果。
5. 最後依指定格式交付。

輸出格式：
- 分析結果：
- 處理方向：
- 最終成果：
- 檢查結果：
```

### 教學範例：規劃課堂活動

```text
你是一位有經驗的程式設計教師。請根據我提供的教學主題，
設計一堂 50 分鐘的課程活動。

請依序進行：
1. 判斷學生在這堂課必須先具備哪些先備知識；若資訊不足，列出假設。
2. 規劃暖身、教師示範、學生實作與收尾四個階段。
3. 為學生實作設計一個可在 15 分鐘內完成的小任務。
4. 檢查活動時間總和是否為 50 分鐘。

請用繁體中文輸出表格，欄位為：階段、時間、教師行動、學生行動、預期成果。

教學主題：Python 的串列（list）
學生程度：剛學過變數、if 與 for 迴圈
```

## 3｜決策邏輯：把「如果……就……」說清楚

決策邏輯就是 Prompt 裡的 `if / else`。它能讓 AI 在不同情況下採用不同作法，而不是一律猜測或硬做。

### 可直接複製的模板

```text
處理資料時請依照以下規則判斷：

- 如果［條件 A］，請［行動 A］。
- 如果［條件 B］，請［行動 B］。
- 如果資訊不足以判斷，請不要自行補充事實；
  請列出缺少的資料，並提出最多 3 個需要我決定的問題。
- 如果同時符合多個條件，優先依照［優先順序］處理。
```

### 教學範例：批改學生程式

```text
你是一位 Python 助教。請檢視學生的程式與作業要求，提供回饋。

請依照以下規則：
- 如果程式無法執行，先指出第一個會造成執行失敗的問題，
  說明原因並給最小的修正方向。
- 如果程式可以執行但結果錯誤，請用一組具體輸入說明預期結果與實際結果的差異。
- 如果結果正確但寫法不易閱讀，請提供一項可選擇採用的改善建議。
- 如果作業要求或程式內容不足以判斷，不要猜測；請提出問題。

請勿直接貼出完整重寫答案。回饋格式為：問題類型、位置、原因、提示、下一步。

作業要求：［貼上作業要求］
學生程式：［貼上程式］
```

## 4｜驗證迴圈：不符合標準，就修正再檢查

驗證迴圈類似程式裡的 `while`：先檢查成果，若未達標準則修正，再檢查一次。不過 Prompt 一定要寫出**檢查標準**與**最多次數**，避免無限反覆，或只得到一句「我已檢查」。

### 可直接複製的模板

```text
完成初稿後，請依序檢查以下標準：
1. ［標準 1］
2. ［標準 2］
3. ［標準 3］

如果有任何一項不符合：
- 指出不符合的項目與原因；
- 修正成果；
- 重新檢查全部標準。

最多進行［2 或 3］次修正。若仍無法符合，請停止修正，
清楚說明限制與需要人工決定的地方。
```

### 教學範例：製作學生練習題

```text
你是一位 Python 教材編輯。請依照下列主題製作一題學生練習。

主題：使用 for 迴圈累加串列中的數字
學生程度：初學者

請先產生：題目說明、輸入範例、預期輸出、半成品程式與教師參考答案。

完成後，檢查：
1. 題目是否只使用變數、串列與 for 迴圈。
2. 半成品程式是否可執行，且有明確待學生完成的位置。
3. 教師答案是否能得到題目所列的預期輸出。
4. 題目敘述是否足以讓學生知道要做什麼。

若不符合任一項，請修正後重新檢查；最多修正 2 次。
最後輸出「教材內容」與「檢查紀錄」。
```

## 5｜停止條件：知道何時交付，何時請人決定

AI 不應該在資料不足時編造內容。停止條件相當於工作流程的安全出口：它告訴 AI 何時可以交付，也告訴 AI 何時必須停下來詢問人類。

### 可直接複製的句子

```text
若缺少關鍵資料、存在多種合理解讀，或會影響重要決策，請停止產生最終結論。
請改為列出：
1. 已知資訊；
2. 無法判定的原因；
3. 最多 3 個需要我回答的問題；
4. 每個選項可能造成的影響。
```

### 適合提醒學生的原則

- 金額、日期、法規、個資、成績等重要資訊，不能要求 AI 自行補齊。
- 「不知道時要問」比「請盡量完成」更能降低幻覺與錯誤。
- 檢查不是保證正確；涉及事實、程式執行或重要決策時，仍應由人類複核。

## 6｜整合範例：從資料到可交付的專題提案

下面是一份完整 Prompt，學生可複製後只替換方括號中的內容。它同時使用了多步驟、決策邏輯、驗證迴圈與停止條件。

```text
你是一位［角色，例如：校園活動企劃顧問］。請協助我完成［成果，例如：活動提案初稿］。

背景資料：
［貼上已知資料，例如受眾、日期、預算、目標與限制］

請依序進行：
1. 摘要整理已知資訊，列出目標、限制與尚未確認事項。
2. 提出 2 個可行方案，每個方案各說明做法、優點、風險與所需資源。
3. 依照［選擇標準，例如預算、可行性、學習價值］推薦一個方案，並完成提案初稿。

決策規則：
- 若預算資料缺漏，請提供「低／中／高」三種預算假設，不要自行認定實際金額。
- 若方案可能超過［限制，例如時間或人力］，請標示風險，並提出縮減版本。
- 若資料不足以做推薦，請先提問，不要強行選擇。

完成初稿後，請檢查：
1. 是否回應了目標與所有已知限制。
2. 是否列出可執行的時程與資源需求。
3. 是否把假設、風險與未知資訊明確標示。

若有不符合項目，修正後再檢查；最多修正 2 次。
若兩次後仍無法完成，請停止並說明需要我補充的資料。

最後請依序輸出：
A. 已知資訊與假設
B. 方案比較表
C. 推薦方案與理由
D. 提案初稿
E. 檢查紀錄
F. 待確認事項
```

## 7｜學生送出前檢查表

- [ ] 我有寫清楚最終要交付什麼成果。
- [ ] 我有把複雜工作拆成有順序的步驟。
- [ ] 我有寫出至少一個「如果……就……」的判斷規則。
- [ ] 我有設定可觀察的檢查標準，而不是只寫「請確認正確」。
- [ ] 我有設定最多修正次數。
- [ ] 我有說明資料不足或無法判斷時，AI 應如何處理。
- [ ] 我有指定最後輸出的格式。

> 小提醒：先用小任務練習流程 Prompt。當你能清楚說出「完成的標準」，AI 才更有機會真的幫你把事情做完。
