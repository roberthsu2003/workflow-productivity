# 可驗證的 AI 工作流程｜打造具備工程思維的工作規格書

> **🎯 專題定位：AI Agent Skill 的關鍵先修課**  
> 在學習開發真正的 **AI Agent Skill**（如 `SKILL.md`、SOP 工作規格、自動化 Tool 呼叫）之前，最關鍵的核心能力不是程式語法，而是**將人類模糊的需求轉化為清晰、可驗證、具備分支與安全邊界的演算法規格**。

一個初階的 Prompt 只會說「幫我完成什麼」；  
而一個具備工程思維的規格化 Prompt，會交代 AI：**先做什麼、遇到不同情況如何決策、依據何種標準自我檢查，以及何時必須停止並尋求人類裁決。**

## 💡 思維進化三部曲：從 Prompt 到 Skill

| 維度 | 第一階段：傳統口語 Prompt | 第二階段：可驗證工作規格（本專題） | 第三階段：完整 AI Agent Skill |
|:---|:---|:---|:---|
| **本質** | 隨興對話、問答嘗試 | 自然語言演算法規格書 | 程式化、模組化自動執行單元 |
| **執行流程** | 單次回合，直接要結果 | 多步驟管線（Pipeline），分階段產出 | 狀態機（State Machine）、自主任務鏈 |
| **異常處理** | AI 自行猜測或胡亂編造 | If-Else 分支，缺漏時停止並提問 | 呼叫備援工具（Fallback Tool）、例外中斷 |
| **品質保障** | 靠運氣，人類事後手動挑錯 | 內建 Rubric 驗證迴圈與修正計數器 | 自動化測試（Evals）、審查 Agent 評分 |
| **人類角色** | 疲於奔命來回打字修正 | 設立邊界，擔任關鍵裁決者 | 定義規格與業務規則的架構師 |

## 📋 工作規格送出前自我檢核清單

在將你的工作規格 Prompt 交付給 AI 前，建議花 30 秒核對以下 7 點：

- [ ] **目標明確**：清楚定義最終交付的「實體產物」是什麼。
- [ ] **管線拆解**：將工作拆成有先後相依關係的執行步驟。
- [ ] **分支決策**：至少具備一條「如果……就……否則……」的判斷條件。
- [ ] **客觀指標**：設定具體、可觀察的驗證標準，而非抽象的「請確認正確」。
- [ ] **次數上限**：明確指定自我修正最多進行 2 或 3 次，防止死循環。
- [ ] **防呆煞車**：指定缺少關鍵資訊或超出安全邊界時的具體停止動作。
- [ ] **格式規範**：定義清晰的分段或表格輸出格式。
