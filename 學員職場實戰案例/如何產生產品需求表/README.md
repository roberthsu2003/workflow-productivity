# 🧭 如何產生產品需求表：從零成為「AI 時代產品經理人（AI-PM）」

> 💡 **核心教學願景**：  
> 在生成式 AI 與大型語言模型（LLM）普及的時代，**「寫程式碼」的門檻已被大幅降低，但「精準定義問題與業務規格（Spec-Driven）」成為了企業中最稀缺、最值錢的核心能力！**  
> 
> 本手冊旨在指導學員跳脫「被動丟問題給 AI、結果不合用又重來」的傳統低效迴圈，轉型為具備系統架構思維的 **AI 產品經理人（AI Product Manager / AI-PM）**。透過**「User Story 提案 ➔ AI 一問一答訪談 ➔ 工業級 PRD.md 產出 ➔ 漸進式工作流落地」**的標準閉環，將日常繁瑣的工作痛點轉化為高可靠度的自動化資產！

## 🏗️ AI-PM 規格孵化四部曲（核心教學方法論）

本教材庫的所有職場實戰案例，均嚴格遵循以下四個階段演進：

```text
【階段一：定義問題】              【階段二：深度訪談】                【階段三：工業級規格】             【階段四：自動化落地】
┌────────────────────────┐        ┌─────────────────────────┐         ┌──────────────────────────┐        ┌─────────────────────────┐
│  User Story 提案卡     │ ────▶  │  AI 產品顧問一問一答     │  ────▶  │  標準 PRD.md 規格書       │ ────▶  │  漸進式 RTCCF 工作流    │
│  (輕量填寫，門檻極低)   │        │  (一次 1~2 題深挖細節)   │         │  (人類秒懂、AI 執行零幻覺) │        │  (逐關推進、換批驗證)    │
└────────────────────────┘        └─────────────────────────┘         └──────────────────────────┘        └─────────────────────────┘
```

1. **階段一：極簡 User Story 提案（定義人事物與商業價值）**
   - 學員不必一開始就硬刻大部頭文件，只需填寫簡單的《User Story 提案卡》（包含角色、想要的功能、商業價值、原始輸入與目標成果）。
2. **階段二：啟動 AI 產品面試官（一問一答深挖規格）**
   - 將提案卡貼給 AI（Claude / ChatGPT / Gemini），啟動「一問一答」專業訪談模式。
   - AI 化身資深系統架構師，每次僅提問 1~2 個具體問題，循序漸進深挖：資料欄位型別、計算公式、勾稽平帳條件、邊界例外與驗收標準。
3. **階段三：收斂產出工業級 `PRD.md`（人類與 AI 雙向對齊）**
   - 訪談結束後，AI 自動將所有對話結晶收斂為標準的 `PRD.md`（產品需求規格書）。
   - 這份 PRD 不僅主管看得懂，其結構化的 I/O Schema 與邏輯規則更讓 AI 執行時達到「零幻覺、零誤差」。
4. **階段四：轉化為漸進式優化工作流（逐關驗收與一鍵換批）**
   - 依據 `PRD.md`，在課堂中展開四至五道實戰關卡（關卡 1 萃取 ➔ 關卡 2 勾稽 ➔ 關卡 3 目錄 ➔ 關卡 4 合併），逐步升級規格書，最終換上第二批資料一鍵通用驗證！

## 🎯 講師如何引導學生使用這套教材？

若您是授課講師，建議在課堂中依以下節奏引導學員：

### 步驟 1：課前或課堂前 15 分鐘（填寫 User Story）
- 請學生打開 [**01_User_Story_提案卡樣版.md**](./01_User_Story_提案卡樣版.md)，花 5~10 分鐘寫下自己手邊最繁瑣的「日常業務痛點」。
- 提醒學生備妥「平常拿到的原始檔案（Excel/CSV/PDF/照片）」與「期望做出的目標成果範本」。

### 步驟 2：課堂實作（啟動 AI 一問一答訪談）
- 請學生打開 Claude / ChatGPT 對話框，複製 [**02_AI產品顧問一問一答訪談提示詞.md**](./02_AI產品顧問一問一答訪談提示詞.md)，並附上剛寫好的《User Story 提案卡》。
- 學生化身「業務專家（Domain Expert）」，AI 擔任「產品顧問（AI-PM）」，雙方進行 4~6 輪的一問一答對話。
- 學生驚喜發現：**原本模糊的日常牢騷，在 AI 的追問下，自動變成了嚴謹的計算邏輯與邊界防呆條件！**

### 步驟 3：產出並審核 `PRD.md`
- AI 訪談完畢後自動輸出 [**03_標準PRD規格書範本.md**](./03_標準PRD規格書範本.md) 格式的完整 Markdown 檔案。
- 學生將檔案另存為 `PRD.md`，進行人工檢視確認。

### 步驟 4：雲端硬碟提報
- 學生依據 [**04_實戰專案雲端繳交與資料規範.md**](./04_實戰專案雲端繳交與資料規範.md)，在 Google 雲端硬碟建立 `【姓名】專案名稱` 資料夾，將 `01_來源檔案/`（包含原始 docx, xlsx, pptx, pdf）、`02_需要產出的檔案/` 與 `PRD.md` 上傳。學生在上傳前完全不需要自己清洗資料！

### 步驟 5：課堂現場示範資料清洗（提煉 md / csv / json 常駐知識庫）
- 上課時，講師將學生的 `PRD.md` 與學生提供的原始資料（`.docx`、`.xlsx`、`.pptx`、`.pdf`）直接輸入 AI。
- 現場示範如何將原始規章、對照表與參數，自動清洗提煉為輕量純文字的 **`.md`、`.csv` 或 `.json`**。
- 這些提煉成果將作為未來專案常駐在「專案知識庫（Project Knowledge Base）」的固定資產，達成 Token 節省 90% 且徹底消除模型解析幻覺！
