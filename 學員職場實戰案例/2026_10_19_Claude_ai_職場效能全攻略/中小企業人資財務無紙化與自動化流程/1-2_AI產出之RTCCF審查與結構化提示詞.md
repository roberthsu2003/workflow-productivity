# 1-2 AI 產出之 RTCCF 審查與結構化提示詞

> 💡 **RTCCF 框架定義**：Role（角色）／Task（任務）／Context（背景）／Constraints（限制）／Format（輸出格式）。

---

## 📋 RTCCF 結構化提示詞全文

```markdown
# Role（角色）
你是一位熟悉台灣中小企業行政、人資、財務會計流程的流程數位化顧問，擅長設計無紙化與自動化流程，並了解勞動法規、會計憑證保存與內控簽核要求。

# Task（任務）
請針對以下三項流程，設計無紙化及自動化的實施方案，包含每個節點的負責人、系統動作、輸入／輸出資料與留存的紀錄：
- **流程 1：員工打卡與薪資**
  員工以手機打卡 ➔ 主管簽核 ➔ 薪資計算 ➔ 拋轉財務系統建立傳票。
- **流程 2：費用報銷**
  憑證拍照上傳 ➔ 各主管簽核 ➔ 會計審核 ➔ 會計付款 ➔ 資料輸出 ➔ 會計軟體 ➔ 建立傳票 ➔ 列印。
  系統自動產生「會計傳票＋已簽核請款單＋簽核歷程＋發票／憑證附件」的完整 PDF，供列印或電子歸檔（合併列印）。
- **流程 3：合約／報價單／用印申請**
  各主管簽核 ➔ 行政用印後掃描（或電子章）➔ 產生最終文件 ➔ 列印申請單與附件 ➔ 產生目錄 ➔ 歸檔。

# Context（背景）
- 適用企業：台灣中小企業（含關係企業多組織型態）。
- 參與部門：行政、人資、財務、會計共同協作，目前仍有紙本簽核、列印與人工歸檔的情況。
- 核心目標：減少紙本與人工重複作業，同時保留完整簽核軌跡，方便稽核、查帳與歸檔。

# Constraints（限制與合規）
1. 每個流程都要保留簽核歷程（誰、何時、核准或退回）。
2. 憑證與合約須能對應原始附件，並符合會計憑證及文件保存年限的要求。
3. 薪資與打卡資料屬個人資料，需嚴格限制存取權限（防窺探與加密傳輸）。
4. 優先採用現有會計軟體與常用工具，避免大幅增加系統建置成本。
5. 方案須涵蓋例外情況（漏打卡、退件、金額修正、用印後內容變更）。
6. 用印申請需保留實體用印或電子章的使用紀錄。

# Format（輸出格式）
請依流程 1、2、3 分段輸出，每段包含：
1. 流程圖（文字版）：以「步驟 ➔ 步驟」呈現。
2. 節點明細表：欄位為「步驟／負責角色／系統動作／輸入資料／輸出資料／留存紀錄」。
3. 自動化重點與風險控管：條列說明。
4. 最終產出物範例：例如流程 2 的合併 PDF 目錄結構。
5. 最後附上一份三個流程的導入優先順序與時程建議。
```
