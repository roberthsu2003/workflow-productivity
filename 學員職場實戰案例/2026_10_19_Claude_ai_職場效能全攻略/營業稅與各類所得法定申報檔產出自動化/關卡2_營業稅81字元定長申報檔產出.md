## 🛠️ 實作步驟 2-A：自然語言執行任務（81 字元定長申報檔轉譯）

在同一個 AI Agent 對話視窗中，發送以下指令：

```text
進銷項憑證過濾已驗收通過！現在我們要產出能直接匯入財政部「營業稅電子申報繳稅系統（BLR）」的官方標準檔案。

請執行 81 字元定長文字檔轉譯任務：
1. 【財政部 81 字元定長規格嚴格套用】：
   - 每筆資料強制佔用 81 個 Bytes（字元），欄位不足必須精確補空白或補零，不可多也不可少。
   - 欄位配置：
     * 格式代號（2 碼）：進項三聯式填 21、進項公用事業填 22、進項三聯收銀機填 25；銷項發票填 31/35。
     * 申報所屬年月（5 碼）：民國年月（如 11510 代表民國 115 年 10 月）。
     * 營業人統一編號（8 碼）。
     * 發票流水號或收據字軌（10 碼）：如 AB12345678。
     * 買賣方統一編號（8 碼）。
     * 銷售金額（12 碼）：右靠齊，左補零。
     * 課稅別（1 碼）：1 為應稅、2 為零稅率、3 為免稅。
     * 營業稅額（10 碼）：右靠齊，左補零（銷售額 × 5% 四捨五入）。
     * 扣抵代號（1 碼）：進項得扣抵者填 1（進項之主要營業使用）或 2（固定資產）。
     * 空白保留欄（補齊至 81 字元）。
2. 【產出檔案命名】：命名為「本公司統一編號.TXT」（如 `12345678.TXT`）。
3. 【同行換行規範】：採 Windows CRLF (`\r\n`) 結尾，最後一列不可有多餘空白行。

請為我產出 81 字元文字檔內容，並輸出字元數校驗清單！
```

## 🔍 人工驗收（人機協作點 1）：核對 81 字元定長規格

- [ ] **每列字元數檢核**：每列長度（不含換行符）是否剛好 81 字元？（差一碼就會被財政部系統整批退件）
- [ ] **補零與補空白**：銷售金額與稅額是否向右靠齊、左側填滿 `0`（例如 `000000050000`）？
- [ ] **扣抵代號合規**：進項憑證之扣抵代號是否正確標記為 `1` 或 `2`？
