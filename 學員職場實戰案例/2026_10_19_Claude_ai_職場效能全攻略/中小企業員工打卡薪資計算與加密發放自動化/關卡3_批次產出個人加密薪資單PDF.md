# 關卡 3：批次產出個人身分證 AES-256 加密 PDF 薪資單

> 🎯 **本關目標**：落實台灣《勞動基準法》第 23 條（提供工資各項目計算明細）與企業個資保護，引導 AI Agent 撰寫批次自動化腳本，將每位同仁的薪資單個別轉為 PDF，並以各自的身分證字號設定為開啟密碼（AES-256 加密），同時 **動態更新【RTCCF 工作流規格書_v3】**。

---

## 🛡️ 業務痛點與資安防窺背景

* **傳統紙本發薪袋**：成本高、耗費紙張，且容易遺失或被同事在茶水間瞄到。
* **一般 Email 寄送明文 PDF**：公司的 IT 網管、郵件主機管理員只要調閱 Log 即可看光全公司主管與同仁薪資，存在極高的法律與內控風險。
* **💡 解法**：在產出 PDF 的當下，直接調用標準加密庫（AES-256），設定「該同仁身分證字號」為開啟密碼。即使檔案被他人轉寄或攔截，沒有本人密碼也絕對無法打開！

---

## 💬 本關白話自然語言發想指令（Prompt）

請在同一個 AI Agent 對話視窗中，繼續發送以下指令：

```text
我已經檢核過傳票分錄的「RTCCF_v2.md」了！現在我們要推進【第 3 個任務：個人薪資單安全加密發放之通用工作流程】擴充進去：

1. 規範防窺發放標準：依據勞基法第 23 條，雇主發薪時必須提供工資各項目明細。
2. 規範資安加密原則：為保護薪資機密、防止網管或他人窺探，系統必須具備為每位員工產出獨立 PDF 薪資單之流程規格。
3. 規範密碼鐵則：每份 PDF 必須啟用 AES-256 加密，並以每位員工各自的「身分證字號」作為唯一開啟密碼。
4. 規範腳本架構：定義自動化批次產出與加密之程式架構（如基於 Python pypdf / reportlab）。
5. 幫我「更新現有的 RTCCF 工作流規格書」，把上述資安防窺、身分證密碼保護與批次 PDF 產出的工作流規則擴充進去，並**務必儲存為獨立的 Markdown 檔案（RTCCF_v3.md）**交付給我！只有存成 .md 檔，我才能進行人機協同微調與代碼審查！
```

## 🔍 人工驗收合格標準（Checkpoints：檢驗工作流設計）

在 AI Agent 產出並儲存 `RTCCF_v3.md` 後，請檢核：

- [ ] **法規明細合規（Task）**：規格書中是否明確要求產出的 PDF 必須包含工資總額、加班費、各項扣除數與實發金額（符合勞基法第 23 條）？
- [ ] **高強度加密約束（Constraints）**：是否在 Constraints 中鎖定 AES-256 加密標準，並規範以身分證字號為密碼？
- [ ] **程式執行規範（Format）**：是否規範了 Python 批次處理腳本的核心結構？
- [ ] **成功儲存為實體檔案**：AI Agent 是否已將更新後的工作流儲存為獨立的 **`RTCCF_v3.md`** 檔案？
