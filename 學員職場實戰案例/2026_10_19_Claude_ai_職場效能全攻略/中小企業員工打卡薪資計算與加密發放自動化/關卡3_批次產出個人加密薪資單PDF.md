# 關卡 3：批次產出個人身分證 AES-256 加密 PDF 薪資單

> 🎯 **本關目標**：落實台灣《勞動基準法》第 23 條（提供工資各項目計算明細）與企業個資保護，引導 AI Agent 撰寫批次自動化腳本，將每位同仁的薪資單個別轉為 PDF，並以各自的身分證字號設定為開啟密碼（AES-256 加密），同時 **動態更新【RTCCF 工作流規格書_v3】**。

---

## 🛡️ 業務痛點與資安防窺背景

* **傳統紙本發薪袋**：成本高、耗費紙張，且容易遺失或被同事在茶水間瞄到。
* **一般 Email 寄送明文 PDF**：公司的 IT 網管、郵件主機管理員只要調閱 Log 即可看光全公司主管與同仁薪資，存在極高的法律與內控風險。
* **💡 解法**：在產出 PDF 的當下，直接調用標準加密庫（AES-256），設定「該同仁身分證字號」為開啟密碼。即使檔案被他人轉寄或攔截，沒有本人密碼也絕對無法打開！

---

## 💬 本關白話自然語言發想指令（Prompt）

請在同一個 AI Agent 對話視窗中，繼續發送以下指令：

```text
會計傳票分錄很清楚，借貸完全平衡！現在我們要推進【第 3 個任務：個人薪資單安全加密發放】。

1. 依據勞基法第 23 條規定，雇主發薪時必須提供工資各項目明細。
2. 為了保護薪資機密、防止被他人窺探或網管攔截，我需要為每位員工產生一份獨立的個人「薪資明細單 PDF」。
3. 每份 PDF 必須啟用高強度加密（AES-256），並以每位員工各自的「身分證字號（例如 A1XXXXXXXX）」設定為開啟密碼。
4. 請提供一套可批次處理的 Python 腳本邏輯（例如使用 pypdf / reportlab），自動讀取員工名冊並依序產出加密 PDF。
5. 幫我「更新現有的 RTCCF 工作流規格書」，把資安防窺、身分證密碼保護與批次 PDF 產出的規格擴充進去，並**務必儲存為獨立的 Markdown 檔案（例如 RTCCF_v3.md）**交付給我，只有存成 .md 檔我才能進行人機協同微調與代碼審查！
```

---

## 🔍 人工驗收合格標準（Checkpoints）

在 AI Agent 產出腳本邏輯與測試結果後，請檢核：

- [ ] **獨立單據隔離**：是否為每位員工生成「獨立的 PDF 檔案」（檔案命名包含員工編號與月份，如 `E001_202610.pdf`），而非將所有人擠在同一份檔案？
- [ ] **強制密碼防護**：使用 PDF 閱讀軟體打開檔案時，是否立即彈出「請輸入密碼」對話框？
- [ ] **身分證解密驗證**：輸入該同仁正確的身分證字號能否順利開啟？輸入隨機錯誤密碼是否被系統拒絕？
- [ ] **明細完整性**：解密開啟後，內容是否包含：應發明細、扣款明細、加班時數與實發總額（符合勞基法第 23 條法規底線）？
