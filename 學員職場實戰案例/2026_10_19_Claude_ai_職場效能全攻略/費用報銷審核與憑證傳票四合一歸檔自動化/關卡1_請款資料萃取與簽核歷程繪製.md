## 🛠️ 實作步驟 1-A：自然語言發想 ➔ 建立第 1 個工作流（RTCCF_v1.md）

請開啟您偏好的 **AI Agent 平台**（如 Claude / ChatGPT / Gemini 等）對話視窗，先上傳 `1_素材_無紙化流程_素材總表.xlsx`，發送以下指令：

```text
我們公司每個月都有大量員工申請差旅與採購費用報銷，目前會計需要將請款資料、主管簽核、會計傳票與發票附件手動裝訂成冊。

【任務：建立費用報銷與憑證封裝之工作流規格書】
請先不要執行任何檔案合併，也不要輸出任何特定的報銷單據。我現在要建立的是一套「可供未來各月份重複調用」的標準工作流程規格。
請依據所附素材表的結構，幫我產出【RTCCF 工作流規格書】：

1. Role（角色）：專精於企業財務會計內控流程、電子憑證保存法規（商業會計法）與 PDF 自動化封裝的架構顧問。
2. Task（任務）：定義輸入任意批次報銷資料時，標準的封裝作業鏈路（萃取請款資料 ➔ 簽核軌跡頁繪製 ➔ 傳票與單據勾稽 ➔ 動態目錄與書籤 ➔ 四合一 PDF 合併輸出）。
3. Context（背景）：定義適用的資料結構（費用報銷清單、簽核歷程 @trail、附件檔案清冊），適用於未來各月份。
4. Constraints（限制條件）：鎖定嚴格內控底線（簽核軌跡不可變更、退回紀錄完整保存、繁體中文正黑體排版防亂碼等）。
5. Format（輸出格式）：規範未來封裝後應產出的檢核總表與 PDF 結構頁次標準。

請將這套通用的工作流程規則，【務必儲存為獨立的 Markdown 檔案：RTCCF_v1.md】交付給我！
只要產出這份 .md 規格書即可，不需要輸出特定單據。後續關卡完成後，我們都會直接更新這份 RTCCF_v1.md，讓工作流愈變愈長！
```

## 🔍 人工檢核（人機協作點 1）：檢查 `RTCCF_v1.md`

AI 產出並儲存 `RTCCF_v1.md` 後，請開啟該檔案檢閱：
- [ ] **是否為純工作流程規格**？（未寫死特定單號或申請人名字，未來皆可通用）
- [ ] **簽核軌跡不可篡改約束是否清楚**？（包含簽核時間戳記、審批歷程鏈路）
- [ ] 檢核無誤後，保存這份 **`RTCCF_v1.md`** 作為我們指揮 AI 工作的基石。

## 🚀 實作步驟 1-B：叫 AI 開始依據這個工作流工作！

工作流規格確認後，請在同一個對話中發送執行指令，**真正叫 AI 依據工作流開始幹活**：

```text
這份 RTCCF_v1.md 工作流規格書我確認沒問題！

現在請你嚴格依據剛剛建立的【RTCCF_v1.md】工作流規格：
1. 讀取 Excel 中的費用報銷分頁與簽核歷程分頁。
2. 針對目標請款單號，自動萃取申請人、申請日期、費用科目、申請金額與事由。
3. 提取該單號之完整「主管簽核歷程（@trail）」，包含每位簽核主管的姓名、職稱、審核時間、簽核動作（核准/退回）與審查意見。
4. 輸出第一階段完整的【請款數據摘要與簽核歷程軌跡表】讓我驗收！
```

## 🔍 人工驗收（人機協作點 2）：核對請款與簽核軌跡

- [ ] **請款資訊正確無誤**：單號、金額、申請人是否與原始 Excel 記錄完全一致？
- [ ] **簽核歷程時序完整**：是否清楚呈現審批時間先後順序？若曾經退回修改，是否有忠實呈現退回紀錄？
