## 🛠️ 實作步驟 1-A：自然語言發想 ➔ 建立第 1 個工作流（RTCCF_v1.md）

請開啟您偏好的 **AI Agent 平台**（如 Claude / ChatGPT / Gemini 等）對話視窗，先上傳 `資料需求清單.docx` 與 `審核規格.docx`，發送以下指令：

```text
我們公司是一家參與政府各類公共工程與委託技術服務的工程顧問團隊，未來每週二與每週五，管理部都會從「政府電子採購網」查詢最新釋出的勞務類標案，並整理成清單交給技術部評估。

【任務：建立標案查詢需求與資料清洗之工作流規格書】
請先不要執行任何特定標案的搜尋，也不要輸出特定的案件資料。我現在要建立的是一套「可供未來每週定期重複調用」的標準工作流程規格。
請依據所附素材與審核規格，幫我產出【RTCCF 工作流規格書】：

1. Role（角色）：精通台灣《政府採購法》招標規定、政府電子採購網系統與標案情資清洗的專業顧問。
2. Task（任務）：定義輸入任意批次採購網搜尋結果或關鍵字需求時，標準的資料清洗作業鏈路（關鍵字匹配 ➔ 排除詞過濾 ➔ 等標期有效性檢查 ➔ 機關+案號+次別排重 ➔ 距截止日不足3天之急件標記 ➔ 產出標案篩選清單）。
3. Context（背景）：定義適用的資料結構（查詢需求包含關鍵字、同義詞、排除詞、地區、預算限制；標案資料包含機關、案號、案名、次別、公告日、預算、截止時間、連結）。
4. Constraints（限制條件）：鎖定嚴格審查標準（必須在法定等標期內、屬勞務類；同一機關+案號+次別不重複計列；距截止投標不足 3 個工作天者強制加註【🚨 急件】警示）。
5. Format（輸出格式）：規範未來產出之「標案每週篩選清單」欄位結構與技術部勾選欄位。

請將這套通用的工作流程規則，【務必儲存為獨立的 Markdown 檔案：RTCCF_v1.md】交付給我！
只要產出這份 .md 規格書即可，不需要輸出特定案件。後續關卡完成後，我們都會直接更新這份 RTCCF_v1.md，讓工作流愈變愈長！
```

## 🔍 人工檢核（人機協作點 1）：檢查 `RTCCF_v1.md`

AI 產出並儲存 `RTCCF_v1.md` 後，請開啟該檔案檢閱：
- [ ] **是否為純工作流程規格**？（未寫死特定標案名稱，未來每週二、五皆可調用）
- [ ] **排重與版本規則是否精確**？（以「機關＋案號＋招標次別」為唯一識別鍵）
- [ ] **急件臨界時間防呆是否存在**？（不足 3 個工作天自動標註警示）
- [ ] 檢核無誤後，保存這份 **`RTCCF_v1.md`** 作為我們指揮 AI 工作的基石。

```text

現在請你嚴格依據剛剛建立的【RTCCF_v1.md】工作流規格：
1. 讀取我提供的標案清單資料。
2. 檢查各標案之「招標類別（是否為勞務類）」與「截止投標時間（是否在等標期內）」。
3. 依照「機關＋案號＋次別」進行排重，過濾重複公告。
4. 計算截止投標距今之剩餘工作天數，若不足 3 天請標註【🚨 急件】。
5. 輸出第一階段完整的【標案每週篩選清單】（包含技術部評估勾選欄位）讓我驗收！

【測試數據輸入】：
- 案件 A：經濟部水利署／案號 WRA115001／115年度水資源智慧監控委託技術服務案／招標次別 01／預算 4,800,000 元／勞務類／公告日 2026-11-01／截止投標 2026-11-04 17:00
- 案件 B：臺北市政府工務局／案號 PWD-115-088／道路巡查影像AI辨識系統建置／招標次別 01／預算 9,500,000 元／勞務類／公告日 2026-10-25／截止投標 2026-11-15 17:00
- 案件 C：經濟部水利署／案號 WRA115001／115年度水資源智慧監控委託技術服務案／招標次別 01／預算 4,800,000 元／勞務類（重複查詢紀錄）
```
