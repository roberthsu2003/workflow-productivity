# 📑 02_工作流可行性評估與關卡規劃報告樣版（標準交付範本）

> 📌 **用途說明**：  
> 本樣版為 AI 在接收到學員上傳的零散檔案、需求說明，以及【期望產出之實體檔案範本（PDF/Word/Excel/PPT/圖片）】後，所應產出的標準 Markdown 報告規格。  
> 學員可將此樣版作為驗收基準，檢查 AI 產出的報告是否完整涵蓋了 7 大維度與防呆警示。

---

```markdown
# 📊 【專案名稱】工作流可行性評估與關卡規劃報告

- **評估日期**：YYYY-MM-DD
- **評審角色**：資深 AI 工作流總架構師
- **專案狀態**：🟢 綠燈（資料齊全可開工）／ 🟡 黃燈（部分規則或範本需補齊）／ 🔴 紅燈（素材嚴重不足需補齊）

---

* **建議專案名稱**：【例如：觀光飯店訂房月報指標統計與 16:9 實體 PPTX 簡報自動化生成】
* **核心業務痛點**：【簡要描述人工耗時、比對繁瑣、易出錯之處】
* **預期商業效益**：【量化節省工時、消除人為計算錯誤、提升稽核合規性】

## 二、最終實體交付成品規格審查（Delivery Artifacts）

* **期望交付之實體檔案格式**：【例如：實體 PowerPoint (`.pptx`) 簡報 / 實體 Word (`.docx`) 報表 / 實體 Excel (`.xlsx`) 總表 / 實體 PDF (`.pdf`) 文件 / 視覺圖片 (`.png`) / 法定申報檔 (`.txt`)】
* **目標排版樣版具備狀態**：
  - [x] **已具備目標範本**：學員已提供過去人工合格的樣版檔案（如 `官方空白查驗表.docx`、`16:9母片.pptx` 或 `四合一歸檔.pdf`），AI 可精準比對版型與佔位符。
  - [ ] **缺少目標範本（需補齊）**：尚未提供排版範本，AI 將在下方缺漏清單中提出警示。
* **實體檔案產出技術機制**：【例如：調用 Python openpyxl / python-docx / python-pptx / reportlab 程式碼腳本直接生成實體交付物】

## 三、資料齊全度盤點與缺漏補齊警示（Gap Analysis）

* 📘 `規章或對照表.docx`：【內容簡述與可用規則】
* 🎯 `目標成果範本.pdf/.pptx/.docx`：【目標實體成果格式對照】

### 2. 齊全度燈號與評估
* **當前燈號**：【🟢 綠燈 / 🟡 黃燈 / 🔴 紅燈】
* **總體評估**：【說明現有資料是否足以支撐全流程自動化】

### 3. 【🚨 缺漏待補齊清單】（若為黃燈或紅燈時必填）
若資料不齊全，請學員務必先補齊以下素材，方可啟動後續工作流：
- [ ] **缺漏項目 1**：【具體缺少的檔案、規則或實體範本，例如：缺少 16:9 PPT 母片檔案或缺少 ERP 4 碼會計科目對照表】
  - *影響環節*：AI 無法在最後關卡生成排版正確之實體檔案，會產生隨機編造（幻覺）。
  - *補齊方式*：請提供一份過去人工製作合格的目標樣版檔案放入對話框。

## 五、建議關卡數與階段拆解理由

依據業務複雜度評估，本專案建議規劃為 **【1 道關卡（單關閉環） / N 道關卡（漸進式推進）】**：

* **情境 A（單純業務，1 道關卡即可完成）**：
  - 本業務邏輯清晰、不涉及跨表複雜勾稽，**只需 1 個關卡**即可一次性高精度交付，無需刻意拆關，維持極致高效！
* **情境 B（複雜業務，拆為 2~5 道關卡）**：
  - 因涉及多表比對、長篇法規防呆、多模態影像辨識或實體 Word/PPT/PDF 產檔，建議遵循「一次一個任務、做一步驗一步」拆解為多個關卡推進。

## 六、各關卡具體執行藍圖（Prompt、輸入與實體交付物）

* **核心任務**：【本關具體要解決的核心目標】
* **📥 輸入素材**：知識庫【固定檔案.md】＋ 對話框上傳【動態檔案.xlsx】
* **💬 建議發送 Prompt**：
  ```text

## 七、工作流規格書（RTCCF）演進路徑

* **首版建立**：引導 AI 產出純規格書 `RTCCF_v1.md`（包含 Role, Task, Context, Constraints, Format）。
* **漸進式擴充**：每關驗收通過後，指令 AI 將新任務與實體產檔規則追加寫回 `RTCCF_v1.md`。
* **終極收斂與換批驗證**：收斂為生產級 SOP，並換上第二批全新資料，達成一鍵自動化產出實體成品！
