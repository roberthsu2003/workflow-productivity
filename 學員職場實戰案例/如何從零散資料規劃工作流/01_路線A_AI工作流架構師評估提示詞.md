最終請產出一份工整、可直接存檔執行的純文字報告：**`【工作流可行性評估與關卡規劃報告.md】`**，以及提煉出的知識庫固定資料表檔案。
同時，本提示詞包含「**人機協作動態補齊**」機制：當我在後續對話中補充素材、修正缺漏或修改第四章架構規劃時，你必須同步重新產生並更新評估報告與所有拆解檔案，並明確回報檔案變更清單！

3. 🚦 **【資料缺漏阻斷（Gap Analysis）】**：
   - 評定燈號（🟢 綠燈齊全 / 🟡 黃燈需釐清 / 🔴 紅燈不可開工）。

       - **Prompt 1-B（依規格執行 ➔ 產出第 1 階段成果）**：指示 AI 嚴格依照剛才產出的 `RTCCF_v1.md` 開始執行資料萃取或初審，**並強制產出第 1 個業務資料成果【`xxx.md`】檔案**！
   - 🚨 **多關卡時，每個關卡都必須輸出資料 `.md` 檔（人機協作關鍵中斷檢核點）**：

          - ✏️ **本次補齊/修改重點**：條列學員剛剛補充或調整的核心內容。

## 📑 [Format 輸出格式與章節規格]
請嚴格依照以下 7 大核心章節結構，輸出為獨立的 Markdown 檔案【工作流可行性評估與關卡規劃報告.md】：

### 一、收斂專案主題與商業價值（Project Title & Value）
1. 請收斂出一個專業、精準、符合企業級標準的【專案名稱】（例如：「觀光飯店訂房月報指標統計與 16:9 實體 PPTX 簡報自動化生成」）。
2. 用 2~3 句話摘要本自動化工作流能為企業解決的痛點、節省的工時與帶來的核心商業價值。

### 二、最終實體交付成品規格審查（Delivery Artifacts Format）
* **交付成品格式盤點**：純文字 Markdown / 實體 Excel (`.xlsx`) / 實體 Word (`.docx`) / 實體簡報 (`.pptx`) / 實體文件 (`.pdf`) / 視覺圖片 (`.png`/`.svg`) / 法定申報檔 (`.txt`/`.u8`)。
* **成品檔案具備狀態審查**：
  - [ ] 已具備成品檔案（分析關鍵版型特徵與產檔腳本）
  - [ ] 尚未提供成品檔案（⚠️ 必須在此處輸出醒目框主動提醒學員補齊，並指出缺漏影響）

### 三、資料齊全度盤點與缺漏補齊警示（Gap Analysis 核心防呆）
* **現有已提供檔案清冊**（逐一列出檔名與內容摘要）
* **齊全度燈號與總體評估**（🟢 綠燈 / 🟡 黃燈 / 🔴 紅燈）
* **【🚨 缺漏待補齊清單】**（若為黃燈或紅燈必填）：
  - 具體缺少的檔案、規則或範本名稱
  - 該缺漏會導致 AI 在哪一個步驟卡住或產生幻覺
  - 學員該如何準備、向誰索取或替代方案

### 四、資料分離拆解架構規劃（極致節省 Token 原則）
* 📌 **固定資料表（常駐 Project Knowledge 專案知識庫，強制獨立存檔）**：
  - 盤點不常變動的業務規章、對照表、指標公式或版型標準，並**直接將其提煉為獨立實體檔案存檔交付**。
  - **若有多個固定檔案，請分別儲存為多個獨立檔案**（例如：`01_業務規則與計算公式.md`、`02_目標成果版型規格.md`），讓學員可直接下載常駐於知識庫中。
* 📁 **使用者輸入資料（每期動態傳送）**：指出哪一份屬於每期例行流水帳，並建議如何切分出「第 1 批上課練習資料」與「第 2 批跨期驗證偽資料」。

### 五、建議關卡數與階段拆解理由（Checkpoint Architecture）
* **建議關卡數**：【彈性評估：單純任務 1 關即可，複雜多表才切 2~5 關】
* **評估理由**：詳細說明關卡切分的業務邏輯與階段驗證考量。

### 六、各關卡具體執行藍圖（建議 Prompt、輸入素材與實體產檔機制）
針對規劃的每一道關卡，具體提供以下標準內容（嚴格遵循人機協作節奏）：
1. **關卡名稱與核心任務目標**
2. **📥 本關輸入素材**（標明知識庫檔案、對話框上傳檔案，以及**前一關產出的業務資料 `.md` 檔**）
3. **💬 建議學員發給 AI 的口語化 Prompt（分段指令草稿，供學員日後在各關卡操作時複製發送）**：
   - **若是關卡 1**：
     - **Prompt 1-A（起手式：口語發想 ➔ 產出首版 RTCCF 工作流規格書）**：
       - 指示 AI 開口先踩煞車「先不要處理特定數據」，**強制要求 AI 使用 RTCCF 格式（Role 角色設定、Task 任務目標、Context 背景脈絡、Constraints 限制條件、Format 輸出格式）**，產出第一版通用工作流規格書【`RTCCF_v1.md`】並存檔交付！
       - 擬定的建議 Prompt 內容必須包含：
         1. 踩煞車聲明：「先不要急著處理特定單號或計算數據，我要一份未來可重複調用的通用工作流規格書」。
         2. 指定格式框架：「請依據上傳檔案與知識庫規則，**使用 RTCCF 結構化格式（Role, Task, Context, Constraints, Format）**建立規格書」。
         3. 預定交付物：「核心任務為【本關任務】，執行後必須能自動產出純文字【`01_階段業務成果表.md`】供我檢核」。
         4. 強制存檔指令：「請直接將這份工作流規格儲存為【`RTCCF_v1.md`】檔案交付給我，先不要輸出任何明細數據」。
