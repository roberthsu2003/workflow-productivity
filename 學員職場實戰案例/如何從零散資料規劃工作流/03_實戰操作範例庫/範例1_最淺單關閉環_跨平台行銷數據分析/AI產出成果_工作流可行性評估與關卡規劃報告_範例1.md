## 一、收斂專案主題與商業價值（Project Title & Value）

### 專案名稱
**「跨平台廣告投放週報：CTR／CPA／ROAS 指標計算、異常診斷與下週預算配置建議自動化」**

### 商業價值摘要
目前每週一需人工從多個廣告後台整理數據、手算指標，再憑經驗判斷要調整哪些預算，耗時且容易因公式或門檻標準不一致而產生誤判。本工作流把「指標公式」與「異常門檻」寫成固定規則常駐 AI 知識庫，每週只需上傳一份流水帳即可在單一對話中產出指標表、異常清單與預算建議，預估可將半天的人工作業壓縮到 15 分鐘內，且每週判斷標準一致、可追溯。

## 三、資料齊全度盤點與缺漏補齊警示（Gap Analysis 核心防呆）

### 現有已提供檔案清冊

| # | 檔名 | 內容摘要 |
|---|---|---|
| 1 | 學員提報背景說明（.txt） | 業務情境、4 項需求（整合數據、算 CTR／CPA／ROAS、異常診斷、預算建議）、1 條異常門檻範例 |
| 2 | `跨平台行銷投放原始數據_課堂練習.xlsx` | 僅 1 個工作表「課堂輸入」，共 3 列資料。欄位：期間、平台、曝光、點擊、轉換、費用。期間皆為 `2026-10`，平台為「甲平台／乙平台／丙平台」 |

### 🔍 說明書與實際檔案的落差（關鍵發現）

逐格檢查 Excel 後，發現實際檔案內容與說明書描述有多處不一致：

| 說明書寫的 | Excel 實際內容 | 影響 |
|---|---|---|
| 包含「轉換價值」 | **沒有轉換價值欄位** | ROAS（轉換價值 ÷ 花費）**完全無法計算** |
| 「當週」投放流水帳 | 期間欄是 `2026-10`（**月**） | 週報與月資料粒度不符 |
| 「各廣告活動」異常診斷 | 只有平台層級，**沒有活動名稱** | 無法指出「哪一個活動」異常，只能說到平台 |
| Google Ads、Meta、GA4 | 平台名稱是「甲／乙／丙」 | 無法對應實際通路，預算建議難以落地 |
| 「CPC 暴增」 | 只有單一期間，**沒有前期數據** | 「暴增」需要和上期比較，目前無從判斷 |
| 花費超過 2 萬元才算異常 | 最高單筆花費僅 4,000 元 | 門檻永遠不會觸發，課堂上看不到異常判斷效果 |
| — | 丙平台轉換數為 0 | CPA 會出現「除以 0」，需事先定義怎麼呈現 |

### 齊全度燈號與總體評估

## 🟡 黃燈：需釐清後才能完整開工

- **可以先開工的部分**：CTR、CPC、CPA 計算（欄位齊全）。
- **🔴 卡住的部分**：ROAS 計算、「花費 > 2 萬且 ROAS < 2.0」異常規則、「CPC 暴增」判斷、具體的預算增減金額。這幾項正是主管最在意的「預算調整」依據，資料不補齊就開工，AI 只能自己編轉換價值或自訂門檻，等於產生幻覺。

### 🚨 缺漏待補齊清單

- [ ] **1. 轉換價值欄位**
  - 卡在：指標計算（ROAS）、異常診斷、預算建議
  - 不補的後果：AI 可能自行假設「每筆轉換值多少錢」，算出看似合理但完全虛構的 ROAS
  - 如何補齊：Google Ads 匯出時勾選「轉換價值（Conv. value）」；Meta 廣告管理員匯出「購買轉換值」；或向電商／業務部門索取各通路訂單金額
- [ ] **2. 廣告活動名稱欄位與週別日期**
  - 卡在：異常診斷（要指出是哪個活動）、週報期間標示
  - 如何補齊：從各後台改用「活動層級、本週一至週日」匯出；或在 Excel 新增「活動名稱」與「週起日」欄位
- [ ] **3. 上一週（前期）數據**
  - 卡在：「CPC 暴增」判斷
  - 如何補齊：每週保留上一期檔案一併上傳；或在同一份檔案中放兩週資料，以「期間」欄區分
- [ ] **4. 「CPC 暴增」的量化定義**
  - 卡在：異常診斷
  - 不補的後果：AI 會自己決定「漲多少算暴增」，每週標準不一
  - 如何補齊：請主管確認，例如「CPC 比上週增加 30% 以上」
- [ ] **5. 下週預算總額與調整規則**
  - 卡在：預算建議
  - 不補的後果：AI 只能給方向（加碼／減碼），給不出可執行的金額
  - 如何補齊：向主管確認「下週總預算」、「單一平台每週最多可增減幾 %」、「是否有平台最低保底預算」
- [ ] **6. 平台代號對照表（甲／乙／丙 → 實際通路）**
  - 如何補齊：課堂練習可保留代號；實際上線時改用真實平台名稱
  - ⚠️ **特別提醒**：GA4 是「網站分析工具」，不是廣告投放平台，本身沒有「廣告花費」。若把 GA4 的轉換數與 Google Ads／Meta 的轉換數直接加總，同一筆訂單可能被重複計算。請確認 GA4 在本報告中的角色（建議作為「轉換數據的交叉驗證來源」，而非並列的投放通路）
- [ ] **7. 成品樣式範本**（見第二章警示框）
- [ ] **8. 轉換數為 0 時的處理方式**
  - 建議規則：CPA 顯示「無轉換」而非錯誤值，並自動列入「花費無效」觀察名單

## 四、資料解耦架構規劃（極致節省 Token 原則）

### 📌 固定資料表（常駐 Project Knowledge 專案知識庫，已儲存為獨立實體檔案）

以下內容每週都一樣，整理成純文字 `.md` 檔案儲存並常駐於專案知識庫，不必每週重複貼給 AI：

* 📄 **已儲存之固定檔案**：👉 [`廣告指標與預算規則.md`](./廣告指標與預算規則.md)

```markdown
# 廣告指標與預算規則

## 1. 指標公式（固定）
- CTR = 點擊 ÷ 曝光
- CPC = 費用 ÷ 點擊
- CPA = 費用 ÷ 轉換（轉換 = 0 時顯示「無轉換」）
- ROAS = 轉換價值 ÷ 費用

## 2. 異常門檻（待主管確認後填入）
- 規則 A：費用 > 20,000 元 且 ROAS < 2.0 → 🔴 高風險
- 規則 B：CPC 較上期增加 ___% 以上 → 🟠 CPC 暴增
- 規則 C：費用 > 0 且轉換 = 0 → 🟠 花費無效

## 3. 預算調整原則（待主管確認後填入）
- 下週總預算：___ 元（或與本週相同）
- 單一平台單週調整上限：±___%
- 各平台保底預算：___ 元
- 調整方向：ROAS 高者加碼、觸發規則 A 者減碼

## 4. 平台對照表
| 代號 | 實際平台 | 角色 |
|---|---|---|
| 甲平台 | （待填） | 投放通路 |
| 乙平台 | （待填） | 投放通路 |
| 丙平台 | （待填） | 投放通路 |
```

### 📁 使用者輸入資料（每期動態傳送）

- **每週上傳**：當週廣告投放流水帳 `.xlsx`（建議含上週資料，以便判斷 CPC 變化）。
- **建議標準欄位**：週起日、平台、活動名稱、曝光、點擊、轉換、轉換價值、費用。

### 兩批測試資料切分建議

| 批次 | 用途 | 建議內容 |
|---|---|---|
| **第 1 批：上課練習資料** | 課堂示範、走通流程 | 沿用現有 3 列檔案，但**補上「轉換價值」欄**，讓 ROAS 可以算 |
| **第 2 批：跨期驗證偽資料** | 驗證規則與 Prompt 是否穩定 | 建議 2 週 × 3 平台 × 2~3 個活動，並**刻意埋入**以下情境：<br>① 某活動花費 > 2 萬且 ROAS < 2.0（驗證規則 A）<br>② 某活動 CPC 比上週翻倍（驗證規則 B）<br>③ 某活動轉換 = 0（驗證除以 0 處理）<br>④ 一切正常的活動（驗證不會誤報） |

第 2 批的關鍵在「有答案的題目」：學員事先用 Excel 手算好哪幾筆應被標為異常，再拿來比對 AI 的判斷，才能證明工作流可靠。

## 五、建議關卡數與階段拆解理由（Checkpoint Architecture）

### 建議關卡數：**1 道關卡**

### 評估理由

1. **資料來源單一**：每週只有 1 份已整合的流水帳，不需要跨檔案比對或合併。
2. **計算邏輯固定且簡單**：4 個指標都是單純除法，異常規則是明確的 if 條件，沒有需要分段確認的複雜推論。
3. **資料量小**：一週數十筆以內，一次對話就能處理完畢，不會超出 AI 單次處理能力。
4. **驗收可以一次完成**：指標表、異常清單、預算建議三者環環相扣，拆開反而要多次搬運中間檔案，增加出錯機會。
5. **符合拒絕過度設計原則**：這是例行週報，硬拆成 3~4 關只會讓學員每週多花時間在關卡切換上。

### 何時才需要升級為 2 道關卡？

若未來改為**直接上傳 Google Ads、Meta、GA4 三份「原始匯出檔」**（各平台欄位名稱、日期格式、幣別、歸因方式都不同），建議追加一道前置關卡：

- **關卡 0：多平台原始檔清洗與欄位統一** → 產出標準化流水帳，人工確認合併筆數與總花費無誤後，再進入本報告的分析關卡。

目前課堂檔案已是整合好的格式，**不需要**這一關。

## 六、各關卡具體執行藍圖

### 關卡 1：週報指標計算、異常診斷與預算建議

#### 1. 核心任務目標
讀取當週流水帳，依知識庫規則計算 CTR／CPC／CPA／ROAS，標示異常項目，並依預算原則提出下週配置建議，產出 Excel 明細與 Markdown 摘要各一份。

#### 2. 📥 本關輸入素材

| 來源 | 檔案 |
|---|---|
| 📌 專案知識庫（常駐） | `廣告指標與預算規則.md` |
| 📁 對話框上傳（每週） | 當週流水帳 `.xlsx`（含轉換價值，建議含上週資料） |

#### 3. 💬 建議發給 AI 的口語化 Prompt

```text
這是本週的廣告投放流水帳，請依照知識庫裡的《廣告指標與預算規則.md》幫我做週報。

請先不要直接算！先做這三件事，回報給我確認：
1. 告訴我檔案有幾筆資料、包含哪些平台和活動、期間是哪一週。
2. 檢查必要欄位（曝光、點擊、轉換、轉換價值、費用）有沒有缺，有沒有空白或負數。
3. 如果有任何欄位缺漏、或規則裡還有「待填」的門檻，直接告訴我，不要自己假設數字。

我回覆「確認」之後，再請你：
- 用 Python 計算每一列的 CTR、CPC、CPA、ROAS，轉換為 0 的 CPA 顯示「無轉換」。
- 依規則 A、B、C 標示異常，並寫出觸發哪一條規則。
- 依預算調整原則提出下週各平台的建議預算（金額與增減 %），並說明理由。
- 產出兩個檔案：
  ①「廣告週報_指標與異常_YYYYMMDD.xlsx」：第一頁是指標明細表，異常列用紅底標示；第二頁是各平台彙總。
  ②「廣告週報_預算建議摘要_YYYYMMDD.md」：給主管看的一頁摘要，包含本週重點、異常清單、下週預算建議表。
- 最後列出你算出的「總花費」與「總轉換數」，讓我和原始檔核對。
```

#### 4. 🎯 預期交付成果檔名與實體產檔方式

| 檔名 | 產檔方式 |
|---|---|
| `廣告週報_指標與異常_YYYYMMDD.xlsx` | Python `pandas` 計算 + `openpyxl` 寫入；異常列以條件格式（紅底）標示；建議保留 Excel 公式欄（如 `=D2/C2`）讓主管可自行驗算 |
| `廣告週報_預算建議摘要_YYYYMMDD.md` | AI 直接產出 Markdown，需要時可再轉為 Word |

#### 5. 🔍 人工驗收重點清單（Checklist）

- [ ] **總數核對**：AI 回報的總花費、總點擊、總轉換，與原始 Excel 用 `SUM` 加總的結果一致。
- [ ] **公式抽驗**：隨機挑 1 列，用計算機手算 CTR 與 ROAS，與 AI 結果一致（注意百分比與小數位數）。
- [ ] **異常規則驗證**：用第 2 批偽資料埋入的異常項目，AI 全部有標出，且正常項目沒有被誤標。
- [ ] **預算總額守恆**：下週各平台建議預算加總 = 知識庫設定的總預算，且單一平台調整幅度沒有超過上限。

## 七、規格書演進機制（RTCCF 漸進式升級藍圖）

由於本案只有 1 道關卡，規格書的演進重點不在「逐關追加」，而在「**逐週驗證、逐步定版**」：

| 版本 | 時機 | 內容 |
|---|---|---|
| `RTCCF_v1.md` | 第 1 批課堂資料跑完、驗收通過後 | 請 AI 把本次對話整理成 RTCCF 規格書：角色（行銷成效分析師）、任務、輸入欄位規格、指標公式、輸出檔名與版面 |
| `RTCCF_v1.1.md` | 第 2 批偽資料驗證後 | 追加：異常規則的實際門檻值、轉換為 0 等邊界情況的處理方式、驗收時發現並修正的問題 |
| `RTCCF_v2.md`（企業級生產版） | 連續 2~3 週真實資料驗收通過、主管確認版面後 | 定版：固定主管認可的成品樣式、預算規則、平台對照表；此後每週只需上傳流水帳 + 一句「依 RTCCF_v2 產出本週週報」 |

**升級時可對 AI 說的話**：

```text
這次的週報我驗收通過了。請把我們這次確認過的所有規則、公式、
邊界處理方式和輸出格式，整理成 RTCCF 規格書 v1.1，
並標註跟 v1 相比新增或修改了哪些地方。
```

最終定版的 `RTCCF_v2.md` 可與 `廣告指標與預算規則.md` 一起放進專案知識庫，形成「規則 + 規格書」的固定雙檔架構，每週的 Token 消耗只剩當週流水帳本身。
