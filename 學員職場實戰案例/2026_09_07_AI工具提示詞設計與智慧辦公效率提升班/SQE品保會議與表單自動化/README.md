# 🏭 SQE 品保會議記錄與表單自動化

> 📖 **這個業務在做什麼？（非本科新手先看這段）**

> 🧱 **建議關卡規劃**：**2 道關卡**（產出 `RTCCF_step1~2.md` ＋ 最後組裝 `RTCCF_main.md`）

## 🚀 獨立專案實作流程（不限 AI 平台，掌握注意事項即可）

1. **Step 1｜啟動架構師體檢或互動建置**
   * 將「原料 1～4」上傳至您使用的 AI（Claude / ChatGPT / Gemini），依需求套用 [**路線 A：體檢評估提示詞**](../../00_AI工作流架構師實戰指南/01_路線A_AI工作流架構師評估提示詞.md) 或 [**路線 B：一問一答提示詞**](../../00_AI工作流架構師實戰指南/02_路線B_互動式漸進生成RTCCF提示詞.md)。
2. **Step 2｜關卡 1｜逐字稿清洗與決議整理（`RTCCF_step1.md`）**
   * 先產出 `RTCCF_step1.md`，提取批次、公差數據、決議／建議／待確認清單與追蹤事項，輸出純文字會議草稿 `.md` 人工核對後封存 `step1`。
3. **Step 3｜關卡 2｜官方 Word 表單產出與總控組裝（`RTCCF_step2.md` ＋ `RTCCF_main.md`）**
   * 讀取已核對的草稿 `.md`，透過 Python `python-docx` 套入 FR-MR09 正式 Word 表格（含會簽欄），封存 `step2` 並組裝 `RTCCF_main.md`。
4. **Step 4｜用第 2 批測試資料進行換批驗證**
   * 開新對話呼叫 `RTCCF_main.md`，上傳 [`02_換批驗證_偽資料.md`](02_AI清洗後教材_課堂實作專用/使用者提供/02_換批驗證_偽資料.md)，驗證工作流是否能全自動跨期通用產出第 2 批成果！

## ⚠️ 關鍵注意事項（每個 AI 產出不同，請抓準這 4 點）

1. **忠實呈現原文數據**：批次、數量、量測值、公差與單位必須 100% 來自逐字稿，且需註明發言來源段落。
2. **三態嚴格區分**：明確拆開「已同意的決議」、「個人建議」、「尚待確認」，不可將建議寫成決議。
3. **不腦補負責人與日期**：未明確決定的負責人或完成日期強制填「`待確認`」，僅明確相對日期可由會議日期換算。
4. **先確認 `.md` 再產 Word**：必須先人工核對會議草稿 `.md` 的追蹤事項與公差數據，確認無誤才生成 `.docx`。
