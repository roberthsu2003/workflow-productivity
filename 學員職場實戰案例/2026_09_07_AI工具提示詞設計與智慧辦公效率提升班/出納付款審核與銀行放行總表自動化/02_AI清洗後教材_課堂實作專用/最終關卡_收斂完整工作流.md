# 出納付款審核與銀行放行總表自動化｜最終關卡：產生可重複使用的完整工作流

## 這一關要做什麼？

完成前面所有關卡並核對成果後，請 AI 將每一關確認過的規則整合到同一份 `RTCCF_v1.md`。這份檔案是未來換資料時要重複使用的工作流；請下載或自行儲存到自己的電腦。

## 請準備

- 目前的 `RTCCF_v1.md`：關卡 0 建立、每一關驗收後持續更新的版本。
- 每一關已核對的成果；如果對話已經中斷，請重新上傳這些檔案及固定資料表。
- 前面關卡的規則：歸戶與風險卡、放行表樣板與套表。

## 複製給 AI

```text
我已完成並核對前面各關。請閱讀目前的 RTCCF_v1.md、固定資料表與各關已驗收的成果，整合成一份可重複使用的完整工作流，並儲存為 RTCCF_v1.md。

請保留 Role、Task、Context、Constraints、Format 五個部分，並在規格中明確列出：
1. 哪些資料固定、每次使用者需要提供哪些資料與欄位。
2. 依序執行的所有任務、每關的輸入及產出檔名。
3. 清洗、計算或判斷規則，以及缺值、衝突和無法計算時如何處理。
4. 每關需要由人員確認的項目、未確認時如何暫停；成果必須能追溯來源。
5. 換一批資料後如何使用同一份規格重跑及驗收。

不要把本次虛構資料的姓名、日期、數量或結果寫死在規格中；如前面規則有衝突，列出待確認處，不要自行決定。請交付可下載的檔案；若無法建立檔案，請輸出完整 Markdown，讓我另存。
```

## 驗收及保存

- [ ] `RTCCF_v1.md` 包含每一關，並標明輸入、輸出與人員驗收點。
- [ ] 規則有處理缺值與例外，不會把本次資料當作固定值。
- [ ] 下載或另存工作流及固定資料表，確認能重新開啟。
- [ ] 前往[課堂導覽的換批驗證](./README.md#最後驗證換批重跑)，使用第二批偽資料重新測試；如發現錯誤，先修正並保存規格，再重新測試。
