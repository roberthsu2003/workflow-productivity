## 🧩 二、四大業界進階互補方法（含實戰 Prompt 雛型）

當學員遇到「連文字說明都寫不出來」、「擔心寫好的 `RTCCF_v1.md` 遇到髒資料會出包」、或是「AI 算數老是出錯」時，可以導入以下 4 種方法作為補充武器：

---

### 方法 1：黃金成品逆向工程法（Reverse-Engineering from "Gold Standard" Output）

* **🎯 專治痛點**：  
  許多非資訊背景的職場學員（例如行政、人資、行銷），腦中其實說不出清楚的「業務規則」或「流程步驟」，但他們手上有**1~2 份過去人工做出來、老闆非常滿意的「黃金標準成品」**（如一封成交率極高的開發信、一份精美週報 Word/PPT、一張標準核銷表）。
* **⚙️ 核心運作原理（由果推因）**：  
  1. **投入黃金成品**：把成功成品丟給 AI。
  2. **解剖結構特徵**：讓 AI 自動分析這份成品的「受眾語氣、段落骨架、欄位順序、計算邏輯、視覺風格與禁忌用詞」。
  3. **反推必要輸入**：讓 AI 逆向列出「如果要自動生成這份成品，未來使用者必須提供哪些最低限度的輸入欄位？」。
  4. **自動生成 `RTCCF_v1.md`**：直接將解剖結果轉換為可重複調用的通用工作流規格書。

#### 💡 未來可擴充為「路線 C」的提示詞雛型（RTCCF）
```markdown
## 🎭 [Role]
你是一位精通「逆向工程與工作流萃取」的資深 AI工作流架構師。

## 🎯 [Task]
我手邊暫時沒有完整的工作流程說明文件，但我有一份過去人工製作且獲得主管認可的【黃金標準成品】（見附件）。
請你幫我進行「由果推因」的逆向解剖，反推出要穩定產出這份成品所需要的輸入資料規格與處理規則，並直接建立為一份通用工作流規格書【RTCCF_v1.md】。

## 🌐 [Context]
* **黃金標準成品**：（附檔，或貼於下方）
* **使用者未來大概能提供的原始素材**：（若不確定請填「請依成品反推建議」）

## ⚠️ [Constraints]
1. 請先對黃金成品進行「結構解剖」，條列出：① 核心語氣與角色定位、② 固定版面/章節架構、③ 隱含的計算公式或篩選邏輯、④ 禁區與防呆重點。
2. 明確列出「未來每次執行時，使用者最少必須提供哪幾個輸入欄位或檔案」，缺一不可。
3. 請勿直接複製範例裡的特定人名、日期或特定金額，必須將其抽象化為通用規則與變數佔位符。

## 📑 [Format]
1. 先在對話中輸出【黃金成品解剖報告】（讓使用者核對是否符合心中期待）。
2. 若使用者無異議，即儲存交付通用規格書【RTCCF_v1.md】供後續套用新資料實測。
```

### 方法 2：口述錄音轉 SOP 法（Voice-to-SOP / 語音訪談提煉法）

* **🎯 專治痛點**：  
  職場上最資深的老員工（如資深會計、採購、生管）業務能力最強，但最常卡在「**我會做，但叫我打成 Word 操作說明要花兩小時**」。這會導致他們在路線 A／B 的第 1 格「工作流程說明」卡住。
* **⚙️ 核心運作原理（說話代替打字）**：  
  1. **口述 3 分鐘**：請作業人員打開手機語音備忘錄或 ChatGPT 語音，想像在帶一位新同事，口頭唸出：「*我每週一早上會先開 A 系統下載報表，把金額小於 0 的刪掉，如果廠商名稱有 XXX 就歸到專案部...*」。
  2. **AI 清洗與結構化**：將雜亂、帶有口語贅字與跳躍邏輯的逐字稿丟給 AI。
  3. **產出標準四大原料**：由 AI 自動整理出結構化的「業務流程說明（含 `If-Then` 決策樹）」與「缺漏確認清單」，**無縫銜接投入老師的路線 A 或路線 B**！

#### 💡 可給學員使用的「語音轉工作流程說明」前置 Prompt
```markdown
以下是我用手機口述錄音轉成的逐字稿，內容是我平常在公司執行【某項例行業務】的真實作業方式（裡面有很多語助詞與跳躍敘述）。

請你幫我：
1. 去除贅字與重複片段，整理成一份邏輯清晰、條列式的【標準業務流程說明.md】。
2. 將我口述中的判斷條件，全部改寫成明確的「如果...就...（If-Then）」規則。
3. 幫我順便整理出這份流程對應的四大原料清單：① 工作流程說明、② 提到的參考規章/對照表、③ 需要的輸入檔案、④ 預期產出的成果格式，並標註我口述中漏講的關鍵細節。
```

### 方法 3：評估者－優化者雙迴圈（Evaluator-Optimizer / 紅隊壓力測試法）

* **📖 理論出處**：Anthropic 官方技術指南《Building Effective Agents》核心推薦模式之一。
* **🎯 專治痛點**：  
  學員透過路線 A 或路線 B 好不容易產出 `RTCCF_v1.md`，用第 1 批正常資料測試看似完美，但實際在職場運作一兩個月後，突然因為一筆「金額為 0」、「跨年度日期」、「空白儲存格」或「奇怪的全形符號」而整份報表算錯或崩潰。
* **⚙️ 核心運作原理（AI 自我紅隊攻防）**：  
  在 `RTCCF_v1.md` 定版準備上線前，加掛一道**「魔鬼稽核員（Evaluator）」**步驟：
  1. 叫 AI 切換成「專找系統漏洞的挑剔稽核員」。
  2. 針對目前的 `RTCCF_v1.md`，強制要求 AI 腦力激盪出 **5 種職場最常發生的極端邊界測資（Edge Cases）**。
  3. 逐一推演：「如果真的餵進這 5 種極端資料，`RTCCF_v1.md` 哪裡會出現幻覺、除以 0 或格式錯亂？」
  4. 直接生成修補條款，並追加寫回 `RTCCF_v1.md`！

#### 💡 可直接加掛在路線 A/B 之後的「壓力測試 Prompt」
```markdown
這是我剛建立好的工作流規格書【RTCCF_v1.md】（以及相關知識庫規則檔）。
現在請你切換角色，扮演一位「極度挑剔、專門抓系統漏洞的資深品保與內控稽核員」，對這份規格書進行紅隊壓力測試：

1. 請列出 5 種真實職場中最容易讓工作流爆掉的【極端髒資料／邊界情境】（例如：除以 0、欄位缺失、重複單號、跨年度日期、文字夾雜換行或負數）。
2. 逐一檢查：按照目前這份 RTCCF_v1.md 執行上述 5 種情境時，AI 會不會出錯、卡住或產生幻覺？
3. 請針對找出的每一個漏洞，幫我擬定具體的「防呆補充條款」，經我確認後，直接追加更新寫回【RTCCF_v1.md】！
```

### 方法 4：確定性程式碼 vs. 生成式認知分工法（Deterministic vs. Generative Split）

* **🎯 專治痛點**：  
  大型語言模型（LLM）天生擅長「語言理解與模糊推理」，但天生不擅長「精確四則運算、長字串精準對齊、重複數百列的資料處理」。若學員在規劃工作流時沒有劃清界線，就很容易出現「AI 心算把發票總額加錯 10 元」或「81 字元申報檔少 1 個空白」的致命錯誤。
* **⚙️ 核心架構原則（「AI 負責想、程式負責算」）**：

| 工作性質 | 應該交給誰？ | 實務職場範例（對應本課程案例） |
| :--- | :--- | :--- |
| **模糊語意理解與推理** | 🧠 **生成式 AI（LLM）** | • 讀取口語會議逐字稿提煉決議<br>• 看懂施工現場手寫白板照片（OCR）<br>• 判斷廣告成效異常的可能原因並撰寫主管摘要<br>• 牌面意象提取與心理投射文字撰寫 |
| **精確運算與結構化產檔** | ⚙️ **確定性程式（Python / Excel 公式）** | • 薪資加減乘除、勞健保級距對照與借貸平帳驗算<br>• 營業稅 81 字元定長空白補齊與檢核碼計算<br>• `openpyxl` / `python-docx` / `python-pptx` / `pypdf` 實體套表、目錄跳轉與 AES-256 加密 PDF 生成 |

* **💡 教學金句**：  
  > **「只要涉及數學加減乘除、日期天數計算、超過 20 筆的勾稽比對，以及正式交給主管的 Excel/Word/PPT/PDF 產出——在寫 `RTCCF_v1.md` 時，一定要加上一句『強制使用 Python 程式碼執行運算與產檔，嚴禁 AI 直接心算』！」**

## 🏗️ 三、高階擴展視野：Anthropic 五大工作流設計模式光譜

若未來老師想開設「進階企業自動化班」或將部分工作流轉入 API / n8n / Make / Dify / Claude Skills 平台，Anthropic 官方將所有穩健的 AI 系統歸納為以下 **5 種可組合建築積木（由簡至繁）**：

1. **Prompt Chaining（提示鏈／關卡串接）**  
   ➔ **正是本課程的核心基石！** 將大任務切成關卡 1 ➔ `.md` 人工檢核（Gate）➔ 關卡 2 ➔ 最終實體產檔。
2. **Routing（路由分流）**  
   ➔ 當入口進來多種不同類型的單據（例如：差旅費 vs 交際費 vs 採購請款），先由第 1 步 AI 判斷分類，再分流送給對應的專用子工作流與規則檔（避免單一 Prompt 塞滿所有規則）。
3. **Parallelization（平行處理／多重審查）**  
   ➔ 適合長文件（如 50 頁合約）切塊同步審查，或是同一份報表同時從「法規合規」、「財務風險」、「語氣潤飾」三個視角平行批閱再彙整。
4. **Evaluator-Optimizer（評估－優化閉環）**  
   ➔ 即上方「方法 3」：生成器產出後，由評估器依清單打分數並打回重寫，直到 100% 通過驗收標準。
5. **Orchestrator-Workers（總控調度員－專才工人）**  
   ➔ 最高階動態架構，由主 AI 依當次任務複雜度動態決定要拆出幾個子任務並派工給不同工具執行（但穩定度要求高的日常財務行政作業，仍建議優先採用前 1~4 種可控工作流）。
