# 討論方式的內容生成（人機協作實戰：跨介面通用指南）

> 🟢 **適用介面**：**Chats（一般對話）**、**Artifacts（成品畫布）**、**Projects（專案空間）** 全介面通用！  
> 💡 **核心破除迷思**：**不需要進入 Artifacts 也可以使用！** 只要掌握核心工作流，在 Claude 的任何介面都能展開高效的人機協作。

---

## 🎯 核心實作心法：為什麼「先產生 Markdown」是一切人機協作的前提？

在日常使用 AI 時，很多人常犯一個直覺錯誤：**一開始就要求 AI 產出 Word、PDF 或 PowerPoint 簡報**。
結果往往是：
- 格式雖然出來了，但內容細節不滿意。
- 想請 AI 改動某個論點或數字時，AI 不是整份重新生成耗費大量時間，就是改了前面壞了後面。
- 二進位檔案（.docx / .pptx / .pdf）無法在畫面上直接進行逐字檢視與局部修改。

**最佳實踐的「人機協作三階段工作流」是：**

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 第一階段：先產生結構化 Markdown                                          │
│ 指令：「請先以 Markdown 格式輸出這份企劃案的完整架構與內文」             │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 第二階段：人機協作、反覆討論與局部精修                                   │
│ （在 Chats / Artifacts / Projects 任何介面皆可無縫進行局部調整與深掘）   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 第三階段：確認定稿，一鍵轉出正式成品                                     │
│ 指令：「內文已定稿，請將上述內容直接製作為正式 Word (.docx) 與 PPT 供下載」│
└─────────────────────────────────────────────────────────────────────────┘
```

## 🛠️ 在三大不同介面中，如何運用 Markdown 進行人機協作？

不管你當前身處 Claude 的哪一個工作介面，只要手握 Markdown，人機協作的威力就能完全釋放：

### 1. 在 Chats（一般對話視窗）中使用 ── 免開畫布也能精準協作
> **情境**：純對話模式，不需要跳出側欄或開啟額外工具。
- **作法**：要求 Claude：「請用 Markdown 表格／條列產出」。
- **局部討論技巧**：
  - *「第二個小節的論點不夠充分，請維持其他段落不變，專門針對『營運風險評估』補充 3 個應對方案。」*
  - *「請把表格中的第 3 欄『預估時程』全部往後順延一週，並重新計算總工時。」*
- **優勢**：不需要任何外加介面，利用 Markdown 的階層標題（`#`、`##`、`###`）與編號清單作為「溝通座標」，精準指哪改哪。

### 2. 在 Artifacts（成品畫布）中使用 ── 視覺化雙欄協同打磨
> **情境**：長篇報告、合約審查、或需要視覺化比對歷史版本。
- **作法**：要求 Claude：「請將企劃草案以 Markdown 格式產出在 Artifacts 中」。
- **協同優勢**：
  - **右側獨立呈現**：左側對話提出意見，右側畫布就地更新，討論過程不會洗掉最終成果。
  - **版本回溯（Version History）**：點擊右上角歷史版本，隨時可復原到前一版的文字狀態。
  - **手動微調**：你可以直接在畫布上複製段落或微調標點符號。

### 3. 在 Projects（專案空間）中使用 ── 跨對話知識沉澱與持續迭代
> **情境**：長期大型企劃（如：年度新品發表會、長達數月的標案準備）。
- **作法**：將討論出的 Markdown 成果儲存為 Project 專屬知識檔案（Project Knowledge）。
- **協同優勢**：
  - **跨對話繼承**：今天在「對話 A」打磨好的 Markdown 產品規格大綱，明天開「對話 B」時可以直接要求：*「請根據 Project 裡的規格 Markdown，為我撰寫經銷商招商信」*。
  - **全域一致性**：團隊所有協作成員都能以同一份定稿 Markdown 作為對齊基準。

## 💬 實戰示範：四輪「討論式人機協作」對話過程

以下展示一般知識工作者如何透過 Markdown 與 AI 反覆打磨出高品質成果：

### 第 1 輪：奠定架構（出 Markdown）
- **你**：
  ```text
  我們正在規劃一場針對中小企業主的「AI 自動化辦公實戰研討會」。
  請先以 Markdown 格式為我擬定一份 1 頁紙企劃大綱，包含活動目標、目標受眾痛點、3 個核心議程主題與預期成效。
  ```
- **Claude**：（輸出結構分明的 Markdown 條列與大綱）

### 第 2 輪：深入痛點（局部反思修訂）
- **你**：
  ```text
  目前的議程太偏技術名詞。
  請針對【核心議程主題】這個區塊重寫：改用老闆最在意的「省下多少人力成本」、「常見行政流程防呆」與「公文自動草擬」等實務角度來命名，並列出每個主題包含的 20 分鐘實作亮點。其餘部分保持不變。
  ```
- **Claude**：（精準更新議程 Markdown 區塊）

### 第 3 輪：風險審查與對策（增加維度）
- **你**：
  ```text
  如果現場學員完全沒有技術背景，操作卡住怎麼辦？
  請在文末新增一個 Markdown 表格：【現場突發狀況與助教應變 SOP】，列出可能遇到的 3 大問題與解法。
  ```
- **Claude**：（補上應變 SOP 表格）

### 第 4 輪：定稿轉出（一鍵出成品）
- **你**：
  ```text
  內容完全對齊了！
  請根據剛才定稿的 Markdown 內容，幫我生成一份正式的 Word 檔案（.docx）與一份可直接匯入簡報的 Markdown 投影片大綱，提供下載連結。
  ```
- **Claude**：（執行程式碼，產出正式可交付的 .docx 與檔案）

## 📋 總結檢核表（Cheatsheet）

- [ ] **拒絕一步到位**：永遠不一開始就索取複雜格式的成品檔案。
- [ ] **以 Markdown 為基底**：不管是聊天、畫布還是專案空間，先拿到乾淨、結構化的 Markdown。
- [ ] **精準定位討論**：利用 Markdown 標題、項目清單或表格行號作為「座標」引導 AI 局部修改。
- [ ] **先重內容，後整排版**：確認觀點與邏輯無誤後，最後一哩路才讓 AI 生成 Word、Excel、PPT 或 PDF。
