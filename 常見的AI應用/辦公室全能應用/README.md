# 辦公室全能應用：五大商務交付格式生成手冊
## 🚀 AI Agent 人機協作實戰

> **本模組簡介**：本專題專為現代職場與辦公室非技術人員量身設計，徹底擺脫對單一工具的依賴。核心工作流通用於各類主流 AI Agent。
> 
> 針對初學者「不會寫 Prompt、擔心 AI 產出不可控、格式無法直接交付」的三大痛點，同時避免單一任務流程過於繁瑣，本教學全面導入 **6 個口語條列重點 ＋ `RTCCF.md` 一問一答閉環機制（Human-in-the-Loop）**，並依檔案性質設計差異化交付路徑：
> 1. **依 6 個重點口語條列（不用複製貼上）**：學員不用死背提示詞，只要掌握 6 個重點並用自己平時講話的方式簡短條列需求（或附上 PDF、Word、Excel、CSV、白板照片等素材），要求 AI 先存為 **`RTCCF.md`**。
> 2. **AI 儲存 `RTCCF.md` ＋ 一問一答（約 5~6 題）**：AI 自動用專業經驗填好小細節並產出 **`RTCCF.md`**，只針對章節大綱、欄位設計或簡報每頁大綱等大方向問 5~6 題（一次 1 題並附建議選項），每確認一題就同步更新儲存 `RTCCF.md`。
> 3. **依文件類型進行 Human-in-the-Loop 交付**：
>    - **Word (`.docx`) / PDF (`.pdf`)**：確認 `RTCCF.md` 後，AI **必須先交付完整內文的 Markdown 檔案（`.md`）**，讓使用者審核 AI 寫得對不對（不對就繼續 Human-in-the-Loop 修改），確認無誤才轉換為 `.docx` 或 `.pdf`。
>    - **Excel (`.xlsx`)**：不需要多一層 `.md` 資料檔，只要 `RTCCF.md` 的任務與規格（欄位、公式、防呆）對了，就**直接交付 `.xlsx`**。
>    - **PowerPoint (`.pptx`)**：**`RTCCF.md` 內就已包含每頁大綱**，只要透過一問一答通過審核，就**直接交付 `.pptx`**。

## 🧭 AI Agent 辦公室人機協作全景架構（Human-in-the-Loop）

![辦公室人機協作全景圖](./images/辦公室人機協作全景圖.svg)

本手冊全面導入 **6 大口語重點 ＋ `RTCCF.md` 一問一答閉環機制**，讓學生不需複製或背誦提示詞，就能用口語確保 AI 產出受控、符合企業實務標準：
1. **口語條列輸入 (Input Layer)**：依「主題對象、基本條件、先存 `RTCCF.md`、細節先填、5~6 題問答、邊問邊存檔」6 大重點簡短條列，支援 PDF、Word、Excel、CSV、白板照片（OCR）等 7 大多模態實體素材。
2. **AI 儲存 `RTCCF.md` ＋ 一問一答 (Spec & Q&A)**：AI 自動填妥格式與專業細節並存為 **`RTCCF.md`**（簡報類同步納入每頁大綱），只針對大方向提出 5~6 題附選項的確認問題，學員用口語回覆即可，每答一題同步更新 `RTCCF.md`。
3. **人類確認與分流交付 (Review Gate & Deliverables Hub)**：
   - **Word / PDF**：`RTCCF.md` 通過後 ➔ **先交付完整內文 `.md` 審核修改（Human-in-the-Loop）** ➔ 定稿後轉換為 `.docx` / `.pdf`。
   - **Excel**：`RTCCF.md` 任務與規格通過後 ➔ **直接交付 `.xlsx`**。
   - **PowerPoint**：`RTCCF.md`（已含每頁大綱）通過後 ➔ **直接交付 `.pptx`**。

## 📌 關鍵核心原則：為什麼人機協作的任務規格書必須儲存為 `RTCCF.md`？

在與 AI Agent 進行深度人機協作時，**「將 AI 整理的任務條件與架構規格儲存為單一 Markdown 檔案 (`RTCCF.md`)」是兼顧效率與品管的最佳實踐**：

| 評估面向 | 儲存為 Markdown (`.md`) | 存為一般記事本 (`.txt`) | 存為 Word (`.docx`) |
| :--- | :--- | :--- | :--- |
| **語意結構保真度** | 🟢 **100% 原生解析**：保留 `#` 標題、`\| 表格 \|`、代碼區塊與縮排層級，AI Agent 精準理解任務角色、欄位邊界與約束條件。 | 🟡 **結構模糊**：僅有平鋪文字，複雜的交辦步驟、參數對齊容易錯位，AI Agent 容易漏看約束。 | 🔴 **格式污染**：夾帶大量二進位與 XML 富文本標籤，複製到對話介面時引發格式錯亂與雜訊。 |
| **AI Agent 相容性** | 🟢 **完美通用**：主流 AI Agent 原生皆以 Markdown 渲染與解析，直接讀取 `.md` 規格書能做到**零幻覺精準執行**。 | 🟡 段落切分較生硬，跨段落檢索容易斷層。 | 🟡 檔案體積大，上傳與解析耗時較久，部分平台解析表格易變形。 |
| **人機協作與版本控管** | 🟢 **最佳數位資產**：支援 Git、VS Code、Obsidian，一份檔案同時保存 RTCCF 提示詞與預檢標準，團隊可多人修訂並作為下次一鍵套用的 SOP 資產庫。 | 🔴 缺乏結構化，難以建立可追蹤、可擴充的規格資產庫。 | 🔴 難以進行純文字 diff 版本比較與自動化管道調用。 |

> 💡 **口語條列與一問一答操作原則（Human-in-the-Loop 核心前提）**：
> 1. **在步驟 1 必須要求 AI「直接儲存為 `RTCCF.md`」**：唯有產出並儲存成實體 `.md` 檔（而不只是對話框裡的文字），人類才能打開檢視、透過問答修改並真正落實 Human-in-the-Loop。
> 2. **不用死背複製，掌握 6 大口語重點與 5~6 題問答**：只要對照各範例的「6 個重點」（主題對象、基本條件、先存 `RTCCF.md`、小細節 AI 先填、一次 1 題附選項最多問 5~6 題、邊問邊更新存檔），用自己平時講話的方式簡短條列並口語回答問題即可！

## 🔤 跨平台（Mac / Windows）四大格式統一字型防跑版機制

在轉換 `.xlsx`、`.pptx`、`.docx`、`.pdf` 時之所以常出現「英文換字型了，中文卻退回新細明體」，甚至「雖然變成黑體，但『申、請、補、準』的筆畫卻像簡體字」，主要有三大原因：
1. **Mac（蘋方體 `PingFang TC`）與 Windows（微軟正黑體 `Microsoft JhengHei`）預設字庫互斥**。
2. **AI 產檔時常漏設 Office 底層的「東亞中文字型標籤（`eastAsia` / `a:ea`）」與繁體中文語系（`zh-TW`）**。
3. **雲端 Linux 轉 PDF 容易誤映射到簡體／日文字庫**：未宣告 `lang="zh-TW"` 時，雲端轉檔伺服器預設會將 `Noto Sans TC` 映射到簡體 `Noto Sans CJK SC` 或日文 `Noto Sans CJK JP`，導致繁體筆畫走樣。

為了讓所有檔案在 Mac、Windows 與雲端檢視時呈現**正統台灣繁體字形（`zh-TW`）**並維持一致視覺，請依交付路徑在不同階段鎖定字型（全格式首選開源台灣版思源黑體 **`Noto Sans CJK TC` / `Noto Sans TC`**；若免安裝字體且雙平台皆有 Microsoft Office，可統一使用 **`Microsoft JhengHei`（微軟正黑體）＋ 英數 `Arial`**）：

| 交付路徑與格式 | 字型鎖定寫入時機 | 跨 Mac / Windows 底層鎖定標準（台灣繁體 `zh-TW`） |
| :--- | :--- | :--- |
| **直出型：Excel (`.xlsx`)** | **寫入 `RTCCF.md` 格式規範** | 在 `RTCCF.md` 明確要求全活頁簿（標題、表頭、資料列、總計列與圖表）所有儲存格皆顯式指定 `Microsoft JhengHei`（或台灣版 `Noto Sans TC` / `Noto Sans CJK TC`，語系 `zh-TW`），禁止留空退回預設字型。 |
| **直出型：PowerPoint (`.pptx`)** | **寫入 `RTCCF.md` 格式規範** | 在 `RTCCF.md` 明確指定全簡報中文為 `Microsoft JhengHei`（或台灣版 `Noto Sans TC` / `Noto Sans CJK TC`）、英數為 `Arial`，且強制要求底層 XML 同時寫入**東亞中文字型 `<a:ea>`**、**拉丁字型 `<a:latin>`** 與繁體中文語系 `lang="zh-TW"`。 |
| **先審內文型：Word (`.docx`)** | **`.md` 定稿後的「最終轉檔 Prompt」** | 在內文 `.md` 審核通過後下達轉換指令時，要求所有樣式（標題、內文、表格儲存格）同時綁定**西文字型（`w:ascii`/`w:hAnsi` 為 `Arial` 或 `Calibri`）**、**東亞中文字型（`w:eastAsia` 為 `Microsoft JhengHei` 或台灣版 `Noto Sans TC`）**，並將語系鎖定為繁體中文（`zh-TW`）。 |
| **先審內文型：PDF (`.pdf`)** | **`.md` 定稿後的「最終轉檔 Prompt」** | 在內文 `.md` 審核通過後下達轉換指令時，要求 HTML 底層必須宣告 **`lang="zh-TW"`**，並優先呼叫 **`"Noto Sans CJK TC"`** 與 **`"Noto Sans TC"`** 內嵌字型（堆疊：`"Noto Sans CJK TC", "Noto Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif`），嚴禁映射到簡體 `SC` 或日文 `JP` 字庫；內文 `11pt`、行高 `1.6` 倍。 |

> 💡 **100% 純正台灣繁體字形（防簡體筆畫）一勞永逸解方**：若雲端轉檔環境未安裝繁體中文字庫、轉出 PDF 的筆畫仍偏簡體字形（如「申、請、補、準」），最穩定的做法是**先輸出已鎖定字型的 `.docx` 檔（或匯出至 Google Docs），下載回本機電腦後，直接用本機 Word 或 Google Docs「另存為 PDF」**，即可調用最純正的台灣繁體字型庫！  
> 💡 **詳細轉換說明 Prompt 範本**：請見 [**Word 與 PDF 匯出轉換說明指南**](./Word與PDF文件的生成/README.md#-ai-agent-匯出-word-docx-與-pdf-pdf-指南)。
