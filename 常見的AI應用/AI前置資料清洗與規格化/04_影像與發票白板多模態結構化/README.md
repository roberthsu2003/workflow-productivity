# 實戰 04：手機照片與單據影像多模態提煉為「RTCCF 規格檔」

> 💡 **核心教學工作流（極簡白話 ➔ AI產出規格 ➔ 人工審核 ➔ 正式執行）**：  
> **1. 學生只講一句大白話 ➔ 2. AI 自動幫學生寫出 RTCCF.md ➔ 3. 🔍 學生當審查官檢查修改 ➔ 4. 以確認後的 RTCCF.md 當作 Prompt 正式上工**

---

## 📂 實作素材清單
1. [**`範例_手撕發票與報銷憑證數據.md`**](./範例_手撕發票與報銷憑證數據.md)：多張不同格式單據（高鐵票、加油發票、餐飲收據）之手機照片文字資訊。
2. [**`參考成果_費用報銷憑證結構清單.md`**](./參考成果_費用報銷憑證結構清單.md)：標準規格檔完成範本，供學員對照觀摩。

---

## 🛠️ 第一階段：學生發送大白話 Prompt（不要自己寫 RTCCF！）

一般的學生不會自己寫繁雜的 RTCCF 結構。學生只要上傳發票單據照片，發送以下這句大白話即可：

```text
我提供了這些手機拍攝的發票與單據照片，我要將它們轉換為結構化的 Markdown 憑證規格檔。
請先不要直接做，請先幫我產生一個符合 RTCCF（Role, Task, Context, Constraints, Format）架構的 prompt，並儲存為獨立的【RTCCF.md】檔案交付給我。
```

> 🤖 **AI 收到後會自動幫學生做什麼？**  
> AI 會自動去辨識照片上的字軌、統編與欄位，替學生撰寫出一份包含「OCR 辨識、5% 稅額檢算、統編勾稽、不得扣抵標註」的完整 `RTCCF.md` 提示詞規格書！

---

## 🔍 第二階段：人機協作檢核點（檢查 AI 寫出來的 `RTCCF.md`）

> ⚠️ **學員必讀提醒**：  
> 多模態影像最容易受到拍照角度、反光或摺痕影響！請學生開啟 AI 寫好的 `RTCCF.md`，化身「財務審計員」，逐一核對以下 3 大注意事項：

### ✅ 人機協作檢查清單（Checklist）

1. [ ] **【統編與發票號碼是否有 OCR 錯字防呆？】（最常見致命傷！）**  
   * **檢查重點**：看 AI 在 Constraints 是否有要求「防範英數字混淆（如數字 0 與英文 O、數字 8 與英文 B）」？
   * ❌ **常見錯誤**：中油統編 `03799401` 被誤判為 `O37994O1`，學生必須用肉眼核對抓出！

2. [ ] **【未稅 ＋ 5% 稅額 是否有要求自動驗算？】**  
   * **檢查重點**：AI 的任務中是否有規定「未稅金額 ＋ 營業稅(5%) 必須等於 總金額」？
   * 確認是否有要求四捨五入計算，避免 1 元差額。

3. [ ] **【沒打統編的憑證是否有要求標註「不得扣抵」？】**  
   * **檢查重點**：例如星巴克發票買受人空白，AI 的規則中是否有強制規定「未打公司統編者，必須在備註欄加註 ❌ 不得扣抵營業稅進項」？

---

## 🚀 第三階段：以確認後的 `RTCCF.md` 當作 Prompt 正式上工！

人機協作檢查無誤後，在同一個對話中，學生只要對 AI 說一句話：

```text
這份 RTCCF.md 我確認無誤！
現在請你嚴格依據這份【RTCCF.md】的規範，正式辨識剛才上傳的這批發票照片，並輸出標準結構報銷清單！
```
