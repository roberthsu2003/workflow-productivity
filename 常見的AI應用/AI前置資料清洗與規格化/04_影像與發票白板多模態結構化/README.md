# 實戰 04：手機照片與單據影像多模態提煉為「RTCCF 規格檔」

> 💡 **核心教學工作流**：  
> **學生發送白話自然語言 ➔ AI 產出 RTCCF 影像規格檔 ➔ 🔍 人機協作審查修改 ➔ 以 RTCCF 規格檔作為 Prompt 正式執行**

---

## 📂 實作素材清單
1. [**`範例_手撕發票與報銷憑證數據.md`**](./範例_手撕發票與報銷憑證數據.md)：多張不同格式單據（高鐵票、加油發票、餐飲收據）之手機照片文字資訊。
2. [**`參考成果_費用報銷憑證結構清單.md`**](./參考成果_費用報銷憑證結構清單.md)：標準規格檔完成範本，供學員對照觀摩。

---

## 🛠️ 第一階段：複製白話自然語言 Prompt ➔ 叫 AI 產出規格檔

請學生開啟支援多模態圖像上傳的 AI 對話視窗，上傳發票單據照片，**直接複製並發送以下自然語言指令**：

```text
我們公司同仁每月出差採購後，都會用手機隨手拍發票上傳申請報銷，格式雜亂且常有沒打統編的情況。

【任務：將手機發票照片多模態提煉為 RTCCF 憑證審核規格檔】
請先不要執行任何特定款項的報銷沖銷。請依據發票影像結構，幫我產出【RTCCF 工作流規格書】：

1. Role（角色）：資深財務審計與稅務合規分析師。
2. Task（任務）：定義標準多模態解析鏈路（OCR 辨識關鍵欄位 ➔ 5% 營業稅額驗算 ➔ 買受人統編核對 ➔ 標註可扣抵/不得扣抵 ➔ 映射會計科目）。
3. Context（背景）：定義費用報銷標準清單結構（序號、日期、廠商、發票號、統編、未稅、稅額、總額、扣抵狀態、科目）。
4. Constraints（限制條件）：
   - 自動驗算平衡：未稅金額 ＋ 營業稅(5%) 必須等於 總金額（四捨五入）。
   - 稅法防呆鐵則：未打本公司統一編號者，必須強制標註「❌ 不得扣抵」。
5. Format（輸出格式）：輸出為標準 Markdown 結構表格規格書。

請將這套通用的憑證審核規格，【務必儲存為獨立的 Markdown 檔案：RTCCF_憑證審核規格檔.md】交付給我！
只要產出這份 .md 規格書即可，不需要輸出其他內容。
```

---

## 🔍 第二階段：人機協作檢核點（檢查 `RTCCF_憑證審核規格檔.md` 的注意事項）

> ⚠️ **學員必讀提醒**：  
> 多模態影像最容易受到拍照角度、反光或摺痕影響！請學員開啟 AI 產出的規格檔，核對以下 3 大注意事項：

### ✅ 人機協作檢查清單（Checklist）

1. [ ] **【統編與發票號碼是否有 OCR 錯字？】（最常見致命傷！）**  
   * **檢查重點**：手機拍的英文字母與數字容易混淆（例如：數字 `0` 與英文 `O`、數字 `8` 與英文 `B`、數字 `1` 與英文 `I`）。
   * ❌ **常見錯誤**：中油統編 `03799401` 被誤判為 `O37994O1`，人工必須肉眼核對！

2. [ ] **【未稅 ＋ 5% 稅額 是否等於 總金額？】**  
   * **檢查重點**：高鐵票 $1,490（內含稅）：
     * 未稅金額：$1,419
     * 稅額：$71
     * 合計：$1,419 + $71 = $1,490（完全吻合）
   * 確認 AI 有沒有依公式自動驗算，若有 1 元差額應檢查是否四捨五入。

3. [ ] **【沒打統編的憑證是否有標註「不得扣抵」？】**  
   * **檢查重點**：例如星巴克發票買受人空白，AI 的規格檔中是否有正確標註「不得扣抵營業稅進項」，避免國稅局查稅受罰。

---

## 🚀 第三階段：以這份規格檔作為 Prompt 正式執行

審查確認後，未來每個月同仁只要上傳一整疊發票照片，直接指示：
```text
這份 RTCCF_憑證審核規格檔.md 我確認無誤！
現在請嚴格依據規格檔，辨識剛才上傳的這批發票照片，並輸出標準結構報銷清單！
```
