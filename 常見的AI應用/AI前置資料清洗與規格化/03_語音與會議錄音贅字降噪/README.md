# 實戰 03：語音與會議錄音逐字稿贅字降噪為「RTCCF 規格檔」

> 💡 **核心教學工作流**：  
> **學生發送白話自然語言 ➔ AI 產出 RTCCF 會議規格檔 ➔ 🔍 人機協作審查修改 ➔ 以 RTCCF 規格檔作為 Prompt 正式執行**

---

## 📂 實作素材清單
1. [**`範例_產品例會語音逐字稿_未清洗.txt`**](./範例_產品例會語音逐字稿_未清洗.txt)：真實口語錄音生稿，包含大量口頭禪、支離破碎的語意與時間軸跳躍。
2. [**`參考成果_產品例會決議與行動清單.md`**](./參考成果_產品例會決議與行動清單.md)：標準規格檔完成範本，供學員對照觀摩。

---

## 🛠️ 第一階段：複製白話自然語言 Prompt ➔ 叫 AI 產出規格檔

請學生開啟 AI 對話視窗，貼上 [`範例_產品例會語音逐字稿_未清洗.txt`](./範例_產品例會語音逐字稿_未清洗.txt)，**直接複製並發送以下自然語言指令**：

```text
我提供了這份會議語音辨識逐字稿，我要將它轉換為去除贅字口頭禪的 Markdown 會議決議規格檔。
請先不要直接做，請先幫我產生一個符合 RTCCF（Role, Task, Context, Constraints, Format）架構的 prompt，並儲存為獨立的【RTCCF.md】檔案交付給我。
```

---

## 🔍 第二階段：人機協作檢核點（檢查 `RTCCF_會議決議規格檔.md` 的注意事項）

> ⚠️ **學員必讀提醒**：  
> 口語錄音是資訊失真最嚴重的素材！請學員開啟 AI 產出的規格檔，核對以下 3 大注意事項：

### ✅ 人機協作檢查清單（Checklist）

1. [ ] **【每項行動都有明確負責人（Who）嗎？】**  
   * **檢查重點**：確認清單上的任務是否有明確指派到個人（如：Alex、Sarah、Kevin）。
   * ❌ **常見錯誤**：AI 常會偷懶寫成「工程團隊負責...」或「行銷部應於...」，請手動改為具體負責人姓名！

2. [ ] **【死線時間（When）有沒有被模糊化？】**  
   * **檢查重點**：核對會議中提到的確切時間點：
     * Alex 的金流測試 ➔ **11/05 (四) 下班前**
     * Sarah 的文案與海報 ➔ **11/06 (五) 12:00 前**
   * ❌ **常見錯誤**：AI 常會誤寫成「本週內完成」或「下週前完成」，喪失追蹤價值。

3. [ ] **【關鍵商業決策有沒有漏掉？】**  
   * **檢查重點**：會議中拍板的關鍵條件（例如：年繳方案確認加贈 30 天試用），AI 有沒有準確提煉在「決議事項」中。

---

## 🚀 第三階段：以這份規格檔作為 Prompt 正式執行

確認修正後，直接指示 AI：
```text
這份 RTCCF_會議決議規格檔.md 我確認無誤！
現在請正式依此規格，輸出最終正式的【產品例會決議與行動追蹤紀錄】！
```
