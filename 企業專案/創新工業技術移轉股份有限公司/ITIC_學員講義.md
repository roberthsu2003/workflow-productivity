# 第一章　Claude 核心操作、Projects 知識庫與關注清單 Skill

## 1-1　🧭 先建立一個關鍵觀念：模型 ≠ 應用程式

很多人問：「為什麼 AI 的功能愈來愈多？」答案是——**底層能力其實沒變，變的是外面那層應用程式**。

| 階段 | 本質 | 能做的事 |
|---|---|---|
| 最初 | **語言模型** | 輸入文字 → 輸出文字 |
| 現在 | **應用程式** | 文字、圖片、搜尋、檔案處理、外部系統串接…… |

大型語言模型（LLM）的核心能力始終是「根據輸入產生合理的文字輸出」。這就像引擎——引擎只負責運轉，不決定車子能做什麼。

**用職場比喻理解：**

> 語言模型 ＝ 聰明的新進員工（有能力、有基礎知識）
> 應用程式 ＝ 公司的工作流程與系統（決定這個員工能發揮多大效益）

一個優秀的新員工，進到流程完善的公司，能做的事會遠超出他原本的能力範圍。**本課程要教的，就是怎麼幫這位員工把「流程」搭起來。**

### ✏️ 課堂練習 A：分類練習（3 分鐘）

判斷以下功能屬於「模型核心」還是「應用程式擴充」：

| 功能 | 你的判斷 |
|---|---|
| 根據提示寫一封 Email | |
| 上傳 PDF 合約並摘要重點 | |
| 翻譯一段英文為中文 | |
| 搜尋今天的股市新聞 | |
| 連結公司內部的 CRM 系統 | |

> **判斷關鍵**：問自己「這件事只需要文字理解與生成嗎？」若需要存取外部資料、檔案或其他系統，就屬於應用程式擴充層。

## 1-2　🧭 三種擴充功能：Skills、Connectors、Plugins

這三個名詞很容易混淆，但分工其實很清楚：

| 類型 | 解決什麼問題 | 比喻 | 本課程用途 |
|---|---|---|---|
| **Skills（技能）** | 教 Claude 怎麼把特定任務做好，**不連外部服務** | 食譜／SOP | 新聞蒐集、重點摘要、簡報產出 |
| **Connectors（連接器）** | 讓 Claude **存取外部資料**或操作其他系統 | 對外的插座、橋樑 | 讀取 Gmail、Google Drive、Sheets |
| **Plugins（外掛）** | 把多種能力打包成一個可安裝單位 | 整套工具箱 | 本課程不深入 |

**一句話區分**：Skills 是「怎麼做」，Connectors 是「拿得到資料」。兩者常常搭配使用——例如「用 Connectors 讀取 Gmail，再用 Skill 決定怎麼摘要」。

## 1-3　🛠️ RTCCF：本課程通用的 Prompt 框架

本課程所有 Prompt 都採用 **RTCCF** 五段式結構。養成習慣後，你寫出來的指令品質會穩定很多。

| 代號 | 英文 | 建議寫什麼 |
|---|---|---|
| **R** | Role | 你希望 AI 扮演的專業角色 |
| **T** | Task | 要做什麼、產出物是什麼 |
| **C** | Context | 背景、對象、已查到的資料（可整段貼上） |
| **C** | Constraint | 語氣、長度、不可捏造、隱私與法遵 |
| **F** | Format | 檔案類型、版面、是否用 Artifact／Skill 產檔 |

### 📋 RTCCF 空白範本

```markdown
## Role
你是一位（填入專業角色）。

## Task
請（填入具體任務），產出物為（填入交付形式）。

## Context
- 背景：
- 對象：
- 已知資料：

## Constraint
- 語言：繁體中文
- 不可捏造數據；無法確認者請標註「待查證」
- （其他限制）

## Format
- （Markdown 表格／Word 檔／簡報大綱……）
```

> ⚠️ **踩雷提醒**：五段都要填。學員最常省略的是 **Constraint**，結果 AI 自行「腦補」數據——這在投資研究情境是致命問題。**「不可捏造，無法確認請標註」這句話務必每次都寫。**

## 1-4　🛠️ Projects：建立 ITIC 專屬雲端知識沙盒

**Projects** 是 Claude 的持久化工作空間。如果一般對話像路邊攤快餐，Project 就是你專屬的實驗室。

### Projects 的三層本質

1. **雲端知識沙盒**：專案空間彼此隔離，上傳的檔案僅限該專案內存取。
2. **行為約束器**：透過 Custom Instructions 定義這個沙盒裡的角色與規則。
3. **運算沙盒**：內建分析工具可執行 Python 運算。

### 本章實作：建立「ITIC 投資標的關注清單」專案

**步驟：**

1. 建立新 Project，命名為「ITIC 每日情報」
2. 在 **Instructions** 欄位填入角色設定（見下方範本）
3. 上傳 ITIC 投資組合公司清單、重點關注產業領域資料
4. 為此專案**獨立勾選**需要的 Connectors

### 📋 專案 Instructions 範本

```markdown
## Role
你是 ITIC 投資研究團隊的資深產業分析助理。

## Context
- 本專案知識庫中包含 ITIC 的投資標的清單與重點關注領域。
- 重點產業：半導體先進封裝（CoWoS／FOPLP）、矽光子（CPO）、AI 伺服器供應鏈。

## Constraint
- 一律使用繁體中文。
- 所有數據與新聞須註明來源與發布時間。
- 不可捏造財務數字或未經證實的消息；無法確認者標註「待查證」。
- 涉及投資判斷時，僅陳述事實與影響評估，不提供買賣建議。

## Format
- 預設以 Markdown 表格呈現結構化資訊。
```

### 💡 進階技巧：專案隔離

建議針對不同任務建立**獨立專案**，並僅為其啟用必要的 Connectors。

**為什麼？** 過多的工具定義會擠壓系統的可用空間，讓背景資訊變得臃腫，反而降低 AI 的推理精確度與反應速度。**工具不是開越多越好。**

## 1-5　🛠️ Connectors：免複製貼上的資料存取

| 傳統做法 ❌ | 使用 Connectors ✅ |
|---|---|
| 打開信箱 → 複製內文 → 貼回 Claude | 直接說：「摘要我上週的郵件」 |
| 下載 Excel → 上傳至對話框 | 讓 Claude 直接讀取 Google Sheets |
| 手動整理行事曆衝突 | 讓 Claude 掃描日曆並找出空檔 |

### 設定步驟

1. 登入 Claude，點擊左下角頭像 → **Settings** → **Connectors**
2. 找到要連線的服務（如 Google Drive、Gmail）
3. 點擊 **Connect**，在跳出視窗中登入並授權
4. 回到對話，直接用自然語言下指令

### 安全性：我的權限鑰匙放在哪？

| 類型 | 儲存位置 | 說明 |
|---|---|---|
| **遠端連線**（Gmail、Drive） | Anthropic 雲端加密保險箱 | 與帳號綁定，僅在授權的專案中有效 |
| **本地連線**（Local MCP） | 你的電腦（macOS 鑰匙圈／Windows 認證管理員） | 資料在本地處理，雲端不持有長期鑰匙 |

背後兩個關鍵技術：**OAuth 2.0**（一張限時、限權的通行證，Claude 不會看到你的密碼）與 **MCP**（兩端溝通的共同語言）。

> **常見問題：連線後，Claude 會偷看我所有資料嗎？**
> 不會。Claude 只有在收到你的指令、且該指令需要用到相關資料時，才會透過 Connectors 索取。你也可以隨時在設定中切斷連線。

> ⚠️ **課前提醒**：請先與 ITIC 的 IT 單位確認 Google Workspace 的第三方應用授權政策是否允許。

# 第二章　自動化新聞情報蒐集、Excel 數據分析與重點摘要 Skill

> **本章分兩段**：前半段（約 2 小時）文字情報蒐集與摘要；後半段（約 2 小時）Excel 數據判讀。

## 2-1　🧭 核心差異：泛用搜尋 vs 定點爬蟲

每日產業情報蒐集有兩種技術路線，各有明確的適用場合：

| 面向 | 泛用搜尋（Web Search） | 定點爬蟲（Targeted Scraping） |
|---|---|---|
| **運作方式** | 透過搜尋引擎索引比對關鍵字，回傳「相關」網頁 | 直接開啟指定網站，解析頁面結構取得資料 |
| **時效性** | 索引更新有延遲，會混入舊文、分析文、業配文 | 可精準鎖定近 24 小時頭條，時效性最佳 |
| **涵蓋範圍** | 廣，可跨無數網站 | 窄，只涵蓋你指定的少數網站 |
| **對日期的掌控** | **弱**：相關度不等於時間新舊 | **強**：可直接讀取網頁上的發布時間戳記 |
| **穩定性** | **高**：不受單一網站改版影響 | **低**：網站改版或加防爬機制會失效 |
| **適合情境** | 主題探索、找背景資料 | 已知固定來源、每日例行監控 |

> 💡 **一句話理解**：泛用搜尋像是問「這個主題有什麼相關的東西」；定點爬蟲像是每天固定去某幾份報紙、翻到某一版，只看你要的那則新聞。

### ⚠️ 實務最常見的痛點

用泛用搜尋做每日情報蒐集時，經常會發生「搜尋引擎回傳一堆幾個月前的科普介紹文」。原因是搜尋引擎預設以**關鍵字命中率**排序——**相關性高，不代表時間最新**。

**因應方式**：拿到結果後一律做日期驗證，或改採定點爬蟲。

---

## 2-2　🛠️ 混合策略：實務上最穩健的做法

不要二選一，而是**分工**：

1. **定點爬蟲**負責每日固定監控 3–5 個權威來源（經濟日報、工商時報、TechNews、DIGITIMES），確保時間與內容精準。
2. **泛用搜尋**負責「補漏」——當固定來源沒有相關報導時，再以關鍵字廣泛比對，並於取得結果後執行日期驗證。

### 三種蒐集工具的差異

| 工具 | 瀏覽器來源 | 登入狀態 | 適合情境 |
|---|---|---|---|
| **Web Search** | 不需瀏覽器 | 無 | 主題探索、廣度補漏 |
| **Claude in Chrome** | 你現有、已登入的 Chrome | **有**，沿用現有登入 | 需要登入的網站、公司內部系統、Gmail |
| **Playwright** | 自己啟動全新、乾淨的瀏覽器 | 無 | 公開資料、可重複執行的自動化 |

> **記住這條規則**：**不需要登入 → 用 Playwright；需要登入狀態 → 用 Claude in Chrome。**

---

## 2-3　⚠️ 關鍵限制：哪一種做法可以「排程自動執行」？

**這一節請務必弄懂，否則第三章的排程會做不出來。**

| 執行方式 | 能否用 Claude 原生排程 | 原因 |
|---|---|---|
| **Web Search** | ✅ 可以 | 完全在雲端執行，不依賴本機環境 |
| **Claude in Chrome** | ⚠️ 需本機 Chrome 開著 | 依賴本機瀏覽器與登入狀態 |
| **Playwright 本地爬蟲** | ❌ **不行** | 排程在雲端遠端執行，**無法呼叫你電腦上的程式與資料夾** |

**課程設計上的分工：**

- **要每天自動跑、無人值守** → 用 **Web Search 為主**的版本掛 Claude 原生排程（第三章實作）。
- **要精準鎖定時間、深挖特定來源** → 用 **Playwright 定點爬蟲**，由你手動觸發。

另外要注意，就算用 Claude in Chrome，排程重跑時的「允許」設定目前**可能無法穩定保存**，導致任務卡住等待人工核准。因此：

> **若只是要抓公開、免登入的資料，優先考慮該網站是否有開放 API 或可直接下載的檔案連結——完全不需要瀏覽器互動，最適合排程無人值守執行。**

## 2-4　📋 ITIC 每日情報蒐集 Prompt（可直接使用）

```text
請幫我執行『ITIC 每日焦點產業與投資標的新聞情報蒐集』任務：

1. 搜尋策略與依據設定：
   - 搜尋依據：讀取本專案知識庫的關注清單（重點關注『半導體先進封裝
     (CoWoS/FOPLP)』、『矽光子 (CPO)』、『AI 伺服器供應鏈』）。
   - 關鍵字組合策略：
     ("先進封裝" OR "矽光子" OR "CPO") AND ("擴產" OR "融資" OR "技術突破" OR "營收")
   - 時間範圍控制：僅保留過去 24 小時內發布的新聞。
   - 時間驗證要求：搜尋引擎的相關性排序不等於時間排序，請「逐則標示實際發布
     時間」供人工覆核；若某則新聞無法確認發布時間，請標註「時間未確認」，
     不要逕行捨棄，也不要視為今日。

2. 網頁爬取與資料結構化：
   - 檢視權威財經與科技媒體（經濟日報、工商時報、科技新報、電子時報）。
   - 擷取欄位：發布時間、新聞標題、關鍵品牌／公司名稱、核心議題分類、原始連結。

3. 結構化結果輸出：
   - 整理成 Markdown 表格輸出。
   - 表格下方提供 2-3 點對 ITIC 投資標的與產業發展影響的簡要評估摘要。
```

### 學習重點：關鍵字組合的布林邏輯

- `OR`：擴大範圍，列出同一概念的各種說法（先進封裝／矽光子／CPO）
- `AND`：收斂範圍，加上「事件性」條件（擴產／融資／技術突破／營收）

**兩者搭配的意義**：先用 OR 涵蓋所有你關心的技術領域，再用 AND 濾掉純科普、純介紹的文章，只留下真正有「事件發生」的新聞。

## 2-5　🛠️ 新聞與情報重點摘要 Skill

蒐集完只是第一步，主管要看的是**判斷**，不是原文。

### 摘要 Skill 的設計要點

1. **濃縮到 2-3 句**：一則新聞的重點若超過三句，通常是沒抓到核心。
2. **分類標記**：依「利多／利空／中性」標示。
3. **產業影響度分級**：高／中／低，讓主管知道該先看哪幾則。

### 📋 摘要 Prompt 範本

```markdown
## Role
你是 ITIC 的產業研究分析師。

## Task
請將上述蒐集到的新聞逐則摘要，並進行分類與影響度評估。

## Constraint
- 每則摘要濃縮為 2-3 句，只寫「發生什麼事」與「為什麼重要」。
- 立場分類：利多／利空／中性（須說明判斷依據）。
- 產業影響度：高／中／低。
- 不可捏造未在原文出現的數據；原文未提及者標註「原文未載明」。

## Format
| 影響度 | 立場 | 標的／公司 | 2-3 句摘要 | 發布時間 |
```

> ⚠️ **踩雷提醒**：AI 判斷「利多／利空」時容易過度自信。**請務必要求它說明判斷依據**，你才有辦法覆核。這就是人負責的 20%。

## 2-6　🛠️ Excel 業績與營運資料分析

### 人機分工原則：80 / 20

| 🤖 AI 負責的 80% | 👤 你負責的 20% |
|---|---|
| 自動計算統計數據（平均值、成長率、趨勢） | 提供原始數據或數據來源 |
| 生成資料視覺化建議 | 定義分析目標和關鍵指標 |
| 識別異常數據點 | **驗證 AI 發現的問題是否合理** |
| 撰寫分析段落 | 決定建議方案的優先順序 |
| 生成報告結構 | 最終報告的決策和簽核 |

> **這張表是本課程最重要的觀念之一。** AI 做的是「勞力密集」的部分，你做的是「責任密集」的部分。簽名蓋章的永遠是人。

### 實作步驟

1. **數據準備**：確認 Excel 的表頭清楚、無合併儲存格、無多層標題
2. **上傳解析**：將檔案上傳至專案，請 Claude 先「描述這份資料的結構」
3. **趨勢判讀**：要求分析成長率、季節性、異常波動
4. **異常提醒**：請 AI 列出「需要進一步調查」的項目清單
5. **驗證**：**逐項核對 AI 指出的異常是否真的存在**
6. **報表整理**：確認無誤後，請 AI 撰寫摘要報表

> ⚠️ **踩雷提醒**：上傳前先整理表格。合併儲存格、跨行標題、隱藏欄位是 AI 誤讀的三大主因。**先花五分鐘整理，勝過後面花一小時抓錯。**

# 第三章　每日彙整簡報產出、排程自動化與交付實作

## 3-1　🛠️ 用 Artifacts 反覆討論、產出正式文件

**Artifacts** 是對話中產生的**獨立預覽區塊**。當你要求 Claude 產生長篇文字、報告或圖表時，內容不會混雜在對話紀錄中，而是在右側開啟一個獨立畫布。

### 核心特性

- **即時預覽**：內容直接渲染，所見即所得
- **版本控制**：記錄每一次修改，方便比對與還原
- **介面隔離**：主對話視窗保持乾淨，專注於討論邏輯

### 適合 / 不適合使用 Artifacts

| 適合 | 不適合 |
|---|---|
| 長篇文章、報告、結構化文件 | 簡短的問答或說明 |
| 可視覺化的圖表與表格 | 僅需一兩句回覆的對話 |
| 需要反覆迭代優化的內容 | 需要私密或保密的草稿 |

### 討論式優化的四種方向

拿到第一版後，用**自然語言**繼續修改即可，不需要重寫 Prompt：

1. **調整詳細度**：「第三段太長，濃縮成兩句」
2. **調整語氣**：「改成給主管看的正式口吻」
3. **調整結構**：「把風險提示移到最前面」
4. **補充內容**：「加上上一季的對照數據」

## 3-2　🛠️ 簡報大綱設計

產出簡報前，**先確定大綱**。直接叫 AI「做一份簡報」，得到的通常是空泛的內容。

### 大綱設計的五個要素

| 要素 | 說明 |
|---|---|
| **角色設定** | AI 扮演什麼專業角色 |
| **任務目標** | 這份簡報要達成什麼溝通目的 |
| **執行步驟** | 希望它依什麼順序組織內容 |
| **輸出格式** | 每頁要有哪些欄位（標題、要點、備註） |
| **範圍與風格** | 頁數上限、配色調性、專業程度 |

### 📋 ITIC 每日彙整簡報 Prompt 範本

```markdown
## Role
你是 ITIC 投資研究團隊的簡報顧問。

## Task
請將本專案中今日的新聞摘要與 Excel 營運數據分析，整合為一份給投資主管
的每日彙整簡報大綱。

## Context
- 閱讀對象：投資決策主管，時間有限，先看結論。
- 資料來源：本專案知識庫中今日產出的情報摘要與數據分析結果。

## Constraint
- 總頁數 6-8 頁。
- 每頁最多 5 個要點，每點不超過兩行。
- 所有數據須標註來源與時間；無法確認者標註「待查證」。
- 不提供投資買賣建議，僅陳述事實與影響評估。

## Format
- 每頁包含：頁碼、標題、要點清單、口頭補充備註。
- 第一頁為「今日三大重點」摘要頁。
```

## 3-3　🛠️ 排程自動化

**Scheduled（排程任務）**讓你把重複性工作「說一次、之後自動跑」。

> 🔵 **方案需求**：需 **Pro / Max / Team / Enterprise** 付費方案。此功能仍在分階段開放中，**優先開放 Max 方案**。請課前先登入確認左側欄是否已出現「Scheduled」項目。

### 運作方式

- 建立時，Claude 會把你的指令存成任務的「執行說明」，依設定頻率自動執行
- 每次執行都是獨立的工作階段，完成後可像一般任務一樣檢視結果
- **在雲端遠端執行**，即使電腦休眠或未開啟 Claude 也會準時執行

### ⚠️ 最重要的限制

> 排程任務只能使用內建的排程選項，搭配你的 Connectors 與存放在 Claude 帳號中的檔案；**無法綁定你電腦上的本機資料夾**。若任務需要本機檔案或應用程式，該任務只能在本機執行。

**這代表**：第二章的 Playwright 本地爬蟲**無法**由雲端排程觸發。可排程的版本必須以 **Web Search ＋ Connectors** 為主。若真的需要自動執行本機爬蟲，得改由作業系統的排程器（macOS 的 launchd／Windows 工作排程器）來觸發。

### 建立步驟

1. 點選左側欄「Scheduled」→ 右上角「New task」
2. 選擇「Create with Claude」（對話式建立）或「Set up manually」（手動設定）
3. 手動設定需填寫：任務名稱、任務指令、核准模式、執行頻率（每小時／每日／每週／工作日／手動）、工作資料夾
4. 儲存完成

### 管理功能

在「Scheduled」頁面可以：檢視過去與未來的執行紀錄、編輯指令或頻率、暫停／恢復任務、刪除任務、手動立即執行一次。

## 3-4　🛠️ 例外處理與交付對接

自動化流程最怕的不是出錯，而是**出錯了沒人知道**。

### 必須規劃的四種例外情境

| 情境 | 建議處理方式 |
|---|---|
| 來源網站當日無相關報導 | 明確輸出「今日無符合條件之新聞」，而非空白或捏造 |
| 網站改版導致擷取失敗 | 輸出錯誤訊息並通知，不要靜默失敗 |
| 排程執行失敗 | 定期檢查執行紀錄，設定失敗通知 |
| 資料時間無法確認 | 標註「時間未確認」，保留給人工判斷 |

> ⚠️ **在 Prompt 中就要寫明**：「若查無資料，請明確說明查無資料，不得以推測內容填補。」這句話能擋掉大部分的幻覺問題。

### 交付管道對接

透過 Connectors 將成品送達：

- **Email**：串接 Gmail，將每日彙整寄送至指定信箱
- **共用雲端資料夾**：串接 Google Drive，將報告存入團隊共用資料夾

> **課前請確認**：ITIC 現有的資料交付管道為何？內部信箱還是共用雲端硬碟？先確認才能在課堂上直接對接實際情境。
