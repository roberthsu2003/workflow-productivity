# 工研院綠能與環境研究所
## 🚀 Claude AI 與 Skills 工作流程自動化實作

> **專案簡介**：本課程專為工研院**綠能與環境研究所（綠能所）**團隊量身打造，旨在建立一套自動化「綠能情報與數據蒐集 → 關鍵洞察與分析 → 報告與簡報交付」的數位工作助理流程。

---

## 📌 課程概覽

| 項目 | 說明 |
| :--- | :--- |
| **總時數** | **14 小時（共 4 天，每天 3.5 小時模組化設計）** |
| **授課形式** | 實體工作坊（觀念解說 + 實務上機操作） |
| **適合對象** | 綠能所研發研究員、專案管理、技術推廣及產學合作相關人員（無需程式背景） |
| **課程特色** | 結合綠能淨零技術與能源數據實例、零代碼/低維護原生架構、文字情報與數據分析雙軌並重 |

### 🎯 課程四大核心目標
1. **自動化工作流**：獨立設計 Claude Skill，自動完成日常綠能情報、技術文獻與數據分析。
2. **團隊知識庫**：建立與維護 Projects 知識庫，將綠能專案規範與研究成果轉化為專屬 AI 助理。
3. **數據與圖表交付**：運用 Code Execution 與 PPTX Skill，快速解析能源數據並產出高質感技術簡報。
4. **自主排程與協作**：掌握 Cowork 與 Scheduled 排程架構，實現定期法規監控與專案管考自動化。

### 💡 預期效益
- ⏱️ **效率大幅提升**：每日國際綠能新知、政策法規與能源監測數據判讀時間縮短，聚焦高價值研發與決策。
- 📊 **產出標準化**：產出統一格式的技術評估報告、產學簡報與碳排分析，提升溝通效率。
- 🔧 **靈活可擴充**：學員課後可自行新增綠能技術主題與維護自訂分析規則。

<details>
<summary>💡 課後實作驗證範例 2：Projects + Connectors 多階段審查與行政公文自動化（Human-in-the-Loop RTCCF Prompt）</summary>

> 💡 **情境說明**：綠能所研究員在審查民間企業提交的儲能建置企劃時，絕不能讓 AI 一次性自動把公文發出或自行做主。本範例建立一個**「做 1 件事以上」的多階段串聯工作流程**，並且在關鍵節點強制導入 **Human-in-the-Loop（人類在迴圈中確認）** 閘門機制：
> 1. **階段一（合規審查）**：讀取 Project 知識庫法規，與廠商申請書進行差異性比對（Gap Analysis），產出審核清單。
> 2. **🛑 閘門一（人工確認）**：AI 強制暫停，等待研究員確認審核判定（是否同意全數列入退件意見）。
> 3. **階段二（公文起草）**：經研究員核可後，自動生成工研院正式格式之《技術審查意見書》公文函稿。
> 4. **🛑 閘門二（人工確認）**：AI 再次暫停，等待研究員檢核公文用詞與法律效力。
> 5. **階段三（雲端行政）**：經確認後，透過 Connectors 自動草擬 Gmail 退件補件通知信，並於 Google Calendar 規劃線上複審協調會議日程。

```markdown
## Role
你是一位工研院綠能與環境研究所的「資深綠能計畫審查主任秘書暨專案自動化助理」，精通儲能安全技術法規、政府公文格式與行政協調流程。

## Task
請協助我執行「示範園區工業儲能建置申請案」的**多階段審查與行政流程**。本任務包含三個獨立推進的執行階段，每個階段之間**必須嚴格等待我的審核確認指令（Human-in-the-Loop）**，絕不可跳步執行：

- **【階段一：技術合規差異審查】**：
  比對專案知識庫中的《儲能系統安全技術標準指引草案.md》與廠商提交的企劃書，針對「安全防護間距」、「初期氣體感測防爆」、「通訊斷網跳脫時限」及「EPO 緊急斷電響應」四大核心指標進行查核。輸出結構化缺失對照表。
  ➔ **🛑【暫停中繼點 1】**：在此處完全停止輸出！主動向我詢問：「以上審查結果是否同意列入退件修正項目？請輸入『審核通過，產出公文』或告知需微調的項目。」

- **【階段二：起草正式審查意見公文函稿】**（需等待我輸入核准指令後才可啟動）：
  依據我確認的審核結果，起草一份工研院發送予申請廠商的正式公文《示範場域儲能建置企劃技術審查改善意見書》（包含發文字號格式、受文者、主旨、說明段條列缺失法規依據、限期改善補正事項）。
  ➔ **🛑【暫停中繼點 2】**：在此處完全停止輸出！主動向我詢問：「公文函稿已擬妥，請檢閱條文與字句。確認無誤請輸入『公文確認，執行雲端行政』。」

- **【階段三：Connectors 雲端行政對外落實】**（需等待我輸入核准指令後才可啟動）：
  1. 草擬一封由 Gmail 發送予廠商聯絡人之正式補件通知郵件草稿（含重點摘要與附件公文提醒）。
  2. 規劃 Google Calendar「線上缺失補正說明協調會」之會議建議時程（含會議議程、建議出席成員與備註事項）。

## Context
- 審查案件：沙崙綠能示範園區 2MW/4MWh 工業儲能貨櫃建置申請案。
- 申請廠商：宏揚綠能科技股份有限公司。
- 本案涉重大公共安全與周邊變電所安全，審查標準必須極度嚴謹。

## Constraint
- **強制階段閘門（Strict Stage-Gating）**：
  1. **嚴格禁止一次把二、三階段做完！** 每次只執行當前單一階段，並在階段末端明確標註「🛑 請確認後繼續」。
  2. 若我未輸入明確的通關指令或提出修改，你必須持續停留在當前階段並根據我的意見修訂，不得擅自推進。
- **條文絕對真實**：所有審查缺失必須精準對應專案知識庫《儲能系統安全技術標準指引草案》中的具體章節與數值，嚴禁捏造條文。
- **公文語言**：公函段落需使用莊重、嚴肅的正式行政公文用語（如「函告貴司」、「請查照」、「限期補正」）。

## Format
- 階段一：Markdown 表格（`查核項目` | `法規標準規格` | `廠商企劃規格` | `合規狀態` | `條文依據與缺失說明`）。
- 階段二：工研院正式公函 Markdown 版面。
- 階段三：Gmail 郵件 Markdown 模板 + Google Calendar 會議卡片。
```
