> **使用章節**：第二章 — 自動化新聞情報蒐集與爬蟲策略

---

## 🎯 核心差異：泛用搜尋 vs 定點爬蟲

在進行每日產業情報蒐集時，通常有「泛用搜尋（Web Search）」與「定點爬蟲（Targeted Scraping）」兩種主要技術模式：

| 面向 | 泛用搜尋（Web Search） | 定點爬蟲（Targeted Scraping） |
|---|---|---|
| **運作方式** | 透過搜尋引擎索引比對關鍵字，回傳「相關」網頁 | 直接開啟指定網站頁面，解析 HTML 結構取得資料 |
| **時效性** | 索引更新有延遲，且會混入舊文、分析文、業配文 | 可精準鎖定「今日/近 24 小時」頭條，時效性最佳 |
| **涵蓋範圍** | 廣，可跨無數網站 | 窄，只涵蓋您指定的少數網站 |
| **對「日期」的掌控** | 弱：搜尋引擎判斷的「相關度」不等於「時間新舊」 | 強：可直接讀取網頁上的發布時間戳記做精確篩選 |
| **穩定性** | 高：不受單一網站改版影響 | 低：網站改版、加防爬機制會導致失效，需要維護 |
| **適合情境** | 主題探索、找背景資料、找沒有特定來源的資訊 | 已知固定資訊來源、需要每日/定時執行的例行監控 |

> 💡 **一句話理解**：**泛用搜尋像是問「這個主題有什麼相關的東西」；定點爬蟲像是每天固定去某幾份報紙翻到某一版，只看你要的那則新聞。**

### 實務常見痛點
使用泛用搜尋執行每日情報蒐集時，經常會遇到「搜尋引擎回傳了許多數個月前發布的科普介紹文」這類問題，這是因為搜尋引擎預設以關鍵字命中率排序，**相關性高不代表時間最新**。因此在做定時監控時，需特別強化日期驗證或採用定點爬蟲。

## 💡 範例一：泛用搜尋（適合課堂示範「廣度優先」）

### 搜尋策略設計
```text
web_search("先進封裝 CoWoS 擴產 2026年7月")
```

- **優點**：一行關鍵字即可觸及經濟日報、工商時報、TechNews、財經部落格等多樣化來源。
- **缺點**：無法 100% 保證回傳皆為「今天」的新聞，需要人工或程式二次過濾發布日期。

**教學重點**：
- 適合教學員如何設計「關鍵字組合」與「布林邏輯」（`AND` / `OR`）。
- 必須提醒學員：搜尋引擎的「相關性排序 ≠ 時間排序」，拿到結果後務必進行日期驗證。

## 🕷️ 範例二：定點爬蟲（適合課堂示範「精準鎖定」）

使用 Playwright 直接開啟指定科技媒體（如 TechNews 半導體專區），精準解析文章標題與 HTML `<time>` 發布時間：

> ⚠️ **給無程式背景學員的說明**：以下程式碼**不需要自己手寫**。課堂上的做法是「用自然語言描述需求 → 請 Claude 產生程式碼 → 執行 → 把錯誤訊息貼回給 Claude 修正」。這段程式碼的用途是讓你**看懂它在做什麼**，以便驗證 Claude 產出的結果是否合理。

```python
from playwright.sync_api import sync_playwright
from datetime import datetime, timedelta

TARGET_KEYWORDS = ["先進封裝", "CoWoS", "矽光子", "CPO"]
# 使用 astimezone() 取得「帶時區」的現在時間，才能與網頁上帶時區的時間戳記比較
CUTOFF = datetime.now().astimezone() - timedelta(hours=24)

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://technews.tw/category/semiconductors/")
    page.wait_for_selector("article")

    articles = page.query_selector_all("article")
    results = []
    for art in articles:
        # 頁面上的廣告、推薦區塊也可能是 <article>，但缺少標題或時間標籤，
        # 直接取用會出現 AttributeError，因此逐一檢查後才使用
        title_el = art.query_selector("h2")
        link_el = art.query_selector("a")
        time_el = art.query_selector("time")
        if not (title_el and link_el and time_el):
            continue

        title = title_el.inner_text()
        link = link_el.get_attribute("href")
        time_str = time_el.get_attribute("datetime")
        if not time_str:
            continue

        published = datetime.fromisoformat(time_str)
        # 若該網站的時間戳記沒有帶時區，補上本地時區再比較
        if published.tzinfo is None:
            published = published.astimezone()

        # 時間篩選：只留過去 24 小時
        if published < CUTOFF:
            continue
        # 關鍵字篩選：標題需命中至少一個焦點詞
        if not any(kw in title for kw in TARGET_KEYWORDS):
            continue

        results.append({
            "發布時間": published.strftime("%Y-%m-%d %H:%M"),
            "標題": title,
            "連結": link
        })

    browser.close()
```

**教學重點**：
1. 使用 HTML 中的 `<time datetime="...">` 結構化標記做「真正的 24 小時篩選」，而非依賴搜尋引擎猜測。
2. **時區是最常見的踩雷點**：網頁時間戳記多半帶時區（如 `+08:00`），若直接與 `datetime.now()` 比較會出現 `TypeError: can't compare offset-naive and offset-aware datetimes`。統一用 `astimezone()` 處理即可。
3. **防呆比功能重要**：實際頁面混雜廣告與推薦區塊，取不到標題或時間時要先跳過，否則程式在課堂上一跑就中斷。
4. 關鍵字比對在爬蟲取得資料後執行，避免搜尋引擎回傳語意相關但缺乏關鍵字的舊文章。
5. **缺點與維護注意事項**：若目標網站改版、移除標籤或加入反爬驗證，程式將會失效，需提醒學員維護成本。

## 🔄 建議教學搭配方式（混合策略）

實務上最穩健的做法是**兩者混合**：

1. **定點爬蟲**：負責每日固定監控 3-5 個權威來源（經濟日報、工商時報、TechNews、DIGITIMES），確保時間與內容精準。
2. **泛用搜尋**：負責「補漏」— 當固定來源無相關報導時，再以關鍵字廣泛比對，並於取得結果後執行日期驗證。

## ⏰ 重要限制：哪一種做法可以「排程自動執行」？

第三章會把本章的工作流掛上排程，但**兩種做法的可排程性完全不同**，這點必須在第二章就先講清楚：

| 執行方式 | 能否用 Claude 原生排程（Scheduled） | 原因 |
|---|---|---|
| **Web Search 泛用搜尋** | ✅ 可以 | 完全在雲端執行，不依賴本機環境 |
| **Claude in Chrome** | ⚠️ 需本機 Chrome 開著 | 依賴本機瀏覽器與登入狀態 |
| **Playwright 本地爬蟲** | ❌ 不行 | 排程任務在雲端遠端執行，**無法呼叫你電腦上的程式與資料夾** |

> 📌 **課程設計上的分工**：
> - **要每天自動跑、無人值守** → 用 **Web Search 為主**的版本掛 Claude 原生排程（第三章實作）。
> - **要精準鎖定時間、深挖特定來源** → 用 **Playwright 定點爬蟲**，由學員手動觸發，或在本機另行搭配作業系統排程器（macOS `launchd` / Windows 工作排程器）呼叫 Claude Code 執行。
>
> 若沒有事先區分，學員很容易在第三章把 Playwright 流程直接丟進雲端排程，結果每次執行都失敗。

參考：[Claude Scheduled 排程任務說明](../../Claude_ai/Scheduled/README.md)

```text
請幫我執行『ITIC 每日焦點產業與投資標的新聞情報蒐集』任務：

1. 搜尋策略與依據設定（關鍵字組合與時間控制）：
   - 搜尋依據：讀取關注清單（重點關注『半導體先進封裝 (CoWoS/FOPLP)』、『矽光子 (CPO)』、『AI 伺服器供應鏈』）。

   - ⚠️ 時間驗證要求：搜尋引擎的相關性排序不等於時間排序，請**逐則標示實際發布時間**供人工覆核；
     若某則新聞無法確認發布時間，請標註「時間未確認」而非逕行捨棄或視為今日。

   - 使用 Playwright / claude in chrome 開啟並檢視權威財經與科技媒體（如：經濟日報、工商時報、科技新報 TechNews、電子時報 DIGITIMES）。
   - 擷取新聞必備欄位：『發布時間』、『新聞標題』、『關鍵品牌/公司名稱』、『核心議題分類』與『原始連結』。

3. 結構化結果輸出：
   - 將搜集到的情報整理成 Markdown 表格輸出。
   - 於表格下方提供 2-3 點對 ITIC 投資標的與產業發展影響的簡要評估摘要。
```
