# 進階指南 03：發佈與分享 SOP

> 對應 `Claude_ai/Artifacts/Guide/04_Publish_and_Remix_SOP.md`。
>
> **Codex 的發佈比 Claude 嚴肅得多**——Sites 是真的網站，有網址、有資料庫、可能被搜尋引擎索引。

---

## ⚠️ 最容易犯的一個錯

> [!WARNING]
> ### 分享範圍選成「公開網際網路」
>
> Sites **新建立時預設只有擁有者可見**，但部署時要**手動選擇**分享範圍。
>
> 選錯的後果：你們的內部數據上網了，**而且可能已被搜尋引擎索引**——事後刪除也來不及。
>
> **這是不可逆的。** 沒有 `git restore`。

---

## 🔐 分享範圍決策

| 範圍 | 誰看得到 | 什麼時候用 |
| :--- | :--- | :--- |
| **僅自己**（預設） | 只有你 | 開發中、還在調整 |
| **工作區成員** | 同 workspace 的人 | **內部工具的預設選擇** |
| **受邀的外部訪客** | 逐一邀請的人 | 給特定客戶或合作夥伴 |
| **整個工作區** | 組織全員 | 全公司都該看的東西 |
| **公開網際網路** | 任何人 | **對外行銷頁面，且內容已審查** |

### 決策流程

```text
這個 Site 的內容包含……

├─ 內部營運數據、客戶資料、財務數字
│   → 工作區成員（絕不公開）
│
├─ 給特定客戶的專屬內容
│   → 受邀的外部訪客
│
├─ 全公司都該知道的資訊
│   → 整個工作區
│
└─ 已通過法務／品牌審查的對外內容
    → 公開網際網路
```

## 📋 發佈前檢查清單

Sites 採**兩階段發佈**：先建立可審查版本 → 確認後才部署。**不要跳過審查階段。**

### 內容檢查

- [ ] 數字與來源資料一致（**抽查至少 3 筆**）
- [ ] 缺漏資料有正確標示，沒有補 0 或內插
- [ ] 沒有「測試用」「TODO」「Lorem ipsum」殘留
- [ ] 日期、幣別、單位標示正確
- [ ] 錯誤狀態有處理（查無資料時顯示什麼？）

### 隱私檢查

> [!WARNING]
> **這一段是最重要的。**

- [ ] **沒有個人資料**（姓名以外的聯絡方式、身分證號、地址）
- [ ] 沒有客戶名單或可識別的客戶資訊
- [ ] 沒有內部成本結構、毛利率（除非確定要揭露）
- [ ] 沒有員工個人績效資料
- [ ] 沒有 API key、token、連線字串
- [ ] 頁面原始碼中沒有註解洩漏的內部資訊
- [ ] **不儲存查詢紀錄**（除非有明確需求且已告知使用者）

### 權限檢查

- [ ] **分享範圍是你要的那一個**（再確認一次）
- [ ] 需要身分驗證的話，已加上 Sign in with ChatGPT
- [ ] 企業環境已確認管理員政策允許

### 無障礙檢查

- [ ] 對比度符合 WCAG 2.1 AA
- [ ] 不只用顏色區分資訊
- [ ] 可鍵盤操作
- [ ] 手機可正常使用
- [ ] 字級不小於 16px

---

## 🚫 Sites 明確禁止的用途

> [!WARNING]
> - 受保護的健康資訊（PHI）
> - 支付卡處理
> - 13 歲以下兒童相關服務
> - 金融交易
> - 惡意程式散布
>
> 另外：**資料落地（data residency）目前不支援**。有落地要求的資料不要放 Sites。

## 🔄 更新與版本

| 動作 | Sites 的行為 |
| :--- | :--- |
| 修改內容 | 先建立可審查版本，確認後部署 |
| 更改網址 | 在支援的情況下**可更改而不需重新部署**，舊網址轉址到新的 |
| 接自訂網域 | 透過 DNS 記錄 |
| 分析 | 自動提供訪客數與頁面瀏覽數 |

### 建議的更新流程

```text
1. 在對話中修改 → 產生新的可審查版本
2. 用上方檢查清單重跑一次（**特別是隱私檢查**）
3. 確認分享範圍沒有被改動
4. 部署
5. 開實際網址確認一次
```

> **第 3 步常被忽略。** 更新內容時很容易連帶動到權限設定。

## 📤 Visualizations 沒有網址，怎麼分享？

| 需求 | 做法 |
| :--- | :--- |
| 會議上展示 | 直接投影，你操作 |
| 給別人看一眼 | 截圖 |
| **別人要自己操作** | **升級成 Sites** |
| 要放進報告 | 截圖 + 產出對應的 `.xlsx` 附原始數據 |

> **不要為了分享而硬把 Visualization 截成一堆圖。**
> 需要別人自己操作，就是 Sites 的使用時機。

## 🗂️ Workspace 檔案的「發佈」

檔案沒有分享範圍設定，但有它自己的風險：

> [!WARNING]
> **產出的檔案會直接寫進你的 workspace，而 workspace 可能是一個 Git repo。**
>
> - `git add .` 一按，含客戶資料的報表就進了版本歷史
> - **即使事後刪除，Git 歷史仍保留**

### 建議做法

```gitignore
# .gitignore
reports/          # 產出的報表不進版控
output/
*.xlsx
!templates/*.xlsx # 但範本要進
```

並在 `AGENTS.md` 寫明：

```markdown
## Output boundaries
- 產出檔一律寫入 `reports/` 或 `output/`，這兩個目錄已被 .gitignore。
- 產出檔中不得包含客戶完整個資（姓名以外的聯絡方式一律遮罩）。
- **絕不提交 .env、憑證、客戶名單。**
```

## ✅ 一頁式速查

| 情境 | 分享範圍 | 特別注意 |
| :--- | :--- | :--- |
| 內部營運儀表板 | 工作區成員 | 隱私檢查、不存查詢紀錄 |
| 給客戶的專屬頁面 | 受邀外部訪客 | 不可洩漏其他客戶資訊 |
| 公司公開頁面 | 公開網際網路 | **需法務／品牌審查** |
| 開發中 | 僅自己 | — |
| 產出的報表檔 | 不適用 | **`.gitignore` + 不含個資** |
