# 進階指南 02：資料的誠實呈現

> 這一篇沒有 Claude 的直接對應章節，但它是**整份講義最重要的一篇**。

視覺化最大的風險不是「做得醜」，是**「看起來很專業但在誤導人」**。

---

## ⚠️ 四種常見的視覺化謊言

### 一、把缺漏值畫成 0

> [!WARNING]
> **這是最常見、也最嚴重的一種。**

中區 2026-06 沒有資料（WMS 系統移轉未落帳）。三種畫法：

| 畫法 | 讀者看到什麼 | 判定 |
| :--- | :--- | :---: |
| 畫成 0 | 「六月中區崩了」——一個急降到底再彈回的 V 型 | ❌ **嚴重誤導** |
| 用前後月內插 | 「六月中區正常」——假裝有資料 | ❌ 誤導 |
| **線段斷開 + 標註「資料缺漏」** | 「六月沒資料」 | ✅ **正確** |
| 整條線不畫 | 「中區沒資料」——過度，其他 11 個月是有的 | ⚠️ |

**數字上的影響有多大**：中區 Q2 準時率，排除缺漏是 **96.3%**；把空值當 0 會變成 **64.2%**。

### 二、把「不存在」畫成「零」

**這和缺漏值不一樣，處理方式也不同。**

| 情況 | 意思 | 正確處理 |
| :--- | :--- | :--- |
| **資料缺漏** | 該有卻沒有 | 斷線 + 標「資料缺漏」 |
| **尚未存在** | 本來就沒有（新品未上市） | **從存在的時間點才開始畫** |

麥禾的秋栗蒙布朗只有 2026Q3 有銷售——因為它 10 月才上市。
把 Q1/Q2 畫成「銷售 0」，會讓人以為這個商品賣不動。

**正確做法**：從 Q3 開始畫，並標註「10 月上市」。

### 三、離群值壓縮座標軸

南區 2026-11 單量 33,489（雙 11 檔期），其他月份在 6,000～18,000 之間。

直接畫，其他 11 個月會全部擠在圖表底部，看不出差異。

| 解法 | 讓什麼變清楚 | **犧牲了什麼** |
| :--- | :--- | :--- |
| 對數座標軸 | 所有月份都看得清 | 一般讀者容易誤讀比例 |
| 斷軸（break axis） | 保留線性直覺 | 視覺上會**低估**落差幅度 |
| 分成兩張圖 | 兩者都清楚 | 失去「一眼看完整年」 |
| 什麼都不做 | 誠實呈現落差 | 其他月份看不清 |

> [!IMPORTANT]
> **沒有標準答案。** 但有一個原則：**每一種選擇都在強調某些東西、隱藏某些東西。**
>
> 「照著資料畫」不是中立的——**選擇座標軸範圍本身就是一種詮釋。**
> 好的做法是：選一種，然後**在圖上說明你的選擇**。

### 四、座標軸不從 0 開始

準時率 94% 到 97% 的差異，如果 Y 軸從 93% 開始，看起來會像天差地遠。

| 情況 | 可以不從 0 嗎 |
| :--- | :---: |
| 比較量級差異（營收、單量） | ❌ 必須從 0 |
| 觀察小幅波動（準時率、溫度） | ✅ 可以，**但要明確標註** |
| 對外簡報 | ⚠️ 極謹慎，容易被質疑 |

## ✅ 誠實視覺化的檢查清單

把這份清單寫進你的 prompt 的 `Verification`：

```markdown
## Verification
- [ ] 每個數字都能追溯回原始資料（指出來源檔案與欄位）
- [ ] **缺漏值的處理方式有明說**（斷線？標註？絕不可補 0 或內插）
- [ ] **「尚未存在」與「資料缺漏」有區分處理**
- [ ] 離群值的處理方式有說明，並指出犧牲了什麼
- [ ] 座標軸不從 0 開始時有明確標註
- [ ] 單位與幣別標示清楚
- [ ] 計算平均值時，計算基礎（幾筆）有標明
- [ ] 對比度足夠，且**不只用顏色**區分類別（色盲友善）
- [ ] 可鍵盤操作、尊重「減少動態效果」偏好
- [ ] 公開分享前已移除敏感資料
```

## 🎨 無障礙：不只是善意，是正確性

> [!WARNING]
> **四條顏色不同的折線，紅綠色盲的讀者可能看到兩條一樣的線。**
>
> 這不是「體貼」問題，是**資訊傳達失敗**。

### 雙重編碼

| 區分方式 | 單獨使用夠嗎 |
| :--- | :---: |
| 只用顏色 | ❌ |
| 顏色 + **線型**（實線／虛線／點線） | ✅ |
| 顏色 + **標記形狀**（圓／方／三角） | ✅ |
| 顏色 + **直接標籤**（線末端標名稱） | ✅ **最好** |

### 對比度

WCAG 2.1 AA：一般文字 **4.5:1**、大字（≥18pt 或 ≥14pt 粗體）**3.0:1**。

> **不要憑印象判斷，跑一次計算。**
> 見 [Skills / Design 章節](../../Skills/Design/README.md#-為什麼要求寫腳本實際計算)的對比度計算腳本。

## 📝 把誠實原則寫進 `AGENTS.md`

```markdown
## Data visualization
- 資料缺漏一律以斷線或明確標註呈現，**絕不補 0、絕不內插**。
- 區分「資料缺漏」（該有沒有）與「尚未存在」（本來就沒有），處理方式不同。
- 計算任何平均值時，須註明計算基礎筆數；排除缺漏筆時須明說。
- 座標軸不從 0 開始時，必須在圖上標註。
- 離群值不得刪除或截斷；如需特殊處理，須在圖上說明做法與影響。
- 類別區分不得只依賴顏色，須搭配線型、形狀或直接標籤。
- 所有文字對比度須符合 WCAG 2.1 AA。
```

寫進去之後，這些檢查會在**每一次**視覺化中自動生效。

## 🧪 課堂演練

用 [配送績效互動儀表板](../Examples/01_Delivery_Dashboard/README.md)的資料：

1. **先不加任何限制**，請它「畫出 2026 年各區準時率趨勢」
2. 觀察它怎麼處理中區 6 月
3. **加上誠實原則**（或寫進 `AGENTS.md`），重跑
4. 對照兩次的差異

> **如果第一次它就正確斷線了**：很好，但不要因此放鬆。
> 模型行為會隨版本改變，**防護要靠明確的指示，不是靠運氣**。
