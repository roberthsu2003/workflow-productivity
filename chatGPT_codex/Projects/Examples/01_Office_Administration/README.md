# 範例 01：行政營運

> 🟢 **方案需求**：Free（本範例全部練習 Free 可完成）

**情境**：你是潮汐物流營運處的行政承辦。每週要把週會逐字稿整理成會議紀錄，並追蹤待辦事項。逐字稿裡有大量內部縮寫、離題討論，以及**看起來像決議但其實還沒定案**的內容。

> **這個範例練的是 Project Sources 的正確用法**——如何讓背景知識在每次對話中自動生效。

---

| :--- | :--- |

| [`sample_files/內部術語對照表.md`](./sample_files/內部術語對照表.md) | 上傳到 Sources |
| [`sample_files/會議逐字稿_營運週會.md`](./sample_files/會議逐字稿_營運週會.md) | 待處理的逐字稿 |

## 🏗️ 課前設定

1. 建立一個 ChatGPT project，命名「潮汐物流 行政營運」
2. 把 `內部術語對照表.md` 上傳到 **Sources**
3. 把 [`Instructions.md`](./Instructions.md) 的內容貼進 **Instructions**
4. 逐字稿**不要**放 Sources——它是每週更換的處理對象，不是長期參考資料

> [!IMPORTANT]
> ### 什麼該放 Sources、什麼不該
> | 該放 | 不該放 |
> | :--- | :--- |
> | 術語對照表（長期不變） | 這週的逐字稿（每週換） |
> | SOP、規範、範本 | 大量原始資料 |
> | 部門與人員對照 | 含個資的檔案 |
>
> **判準：這份資料下個月還會用到嗎？** 會 → Sources；不會 → 放在 task 裡。

## 🥇 練習一：驗證 Sources 有生效

在做正事之前，先確認設定真的有作用。

```markdown
請解釋以下這段話的意思，用非工程背景同仁看得懂的方式：

「東區八月有 99 件客訴，主要是黑洞件跟爆倉造成的末端延遲，
OTR 掉到 81.3%，ADH 拉高到 62.7 小時。」

若有任何術語不在術語表中，請明確指出，不要猜測。
```

**驗收**：它應該正確解讀 OTR、ADH、黑洞件、爆倉、末端，且**不需要你額外貼術語表**。

> 如果它猜錯或說不知道，代表 Sources 沒設定成功——先解決這個再往下。

## 🥈 練習二：整理會議紀錄（核心練習）

```markdown
## Goal
把 2026-09-07 營週會的逐字稿整理成正式會議紀錄。

## Context
- 逐字稿：`會議逐字稿_營運週會.md`
- 讀者：未與會的同仁與相關承辦

## Scope
- **嚴格區分「已決議」與「討論中但未拍板」。**
- 不捏造逐字稿中沒有的人名、日期、數字。
- 需要他人決定的事項標示為「待確認」，不要代為決定。

## Verification
輸出結構：
1. 會議資訊（時間、地點、主持、出席）
2. **決議事項**（條列，每項註明拍板者）
3. **行動項目**（表格：項目 / 負責人 / 期限）
4. **討論中但未定案**（這一段不可省略）
5. **待確認問題**（需要其他單位回覆的事項）
```

### 📝 解答對照（講師用）

逐字稿中刻意設計了**四類難以區分的內容**：

| 內容 | 正確分類 | 為什麼容易搞錯 |
| :--- | :--- | :--- |
| 東區 SOP 修改 → 鄭以樂本週給草稿 | ✅ **已決議 + 行動項目** | 明確 |
| 報表要同時呈現「含颱風」與「排除颱風」兩個數字 | ✅ **已決議** | 陳柏宇明確拍板「兩個數字都要寫」 |
| 六月中區資料標「資料缺漏」 | ✅ **已決議** | 吳課長說明 + 陳柏宇指派雅琪加註記 |
| 南區彈性人力 10/15 前定案 | ✅ **行動項目** | 有明確期限 |
| **麥禾冷藏案是加購還是另簽合約** | ⚠️ **待確認** | 陳柏宇說「我禮拜三問業務處」——**還沒決定** |
| **冷鏈車輛是否夠用** | ⚠️ **討論中未定案** | 吳建志提議「先確認車輛再談合約」，陳柏宇回「你講得有道理，但我不能替業務處決定」——**沒有結論** |

> [!WARNING]
> ### 最容易出錯的是冷鏈車輛那段
> 陳柏宇說「你講得有道理」。這聽起來像同意，但下一句是「但我不能替業務處決定」。
>
> **把它寫成「決議：先確認車輛再談合約」是錯的。** 正確的寫法是放進「討論中但未定案」，並註明需業務處回覆。
>
> 這是會議紀錄最常見的失真——**把「附和」寫成「決議」**。

## 🥉 練習三：對外用語轉換

```markdown
## Goal
從會議紀錄中，抽出需要對外（客戶）說明的部分，改寫成客戶溝通稿。

## Context
- 對象：受八月東區延遲影響的客戶
- 目的：說明原因與後續改善措施

## Scope
- **必須使用對外用語**（見術語表第六節）。
- 不可出現內部縮寫。
- 不可透露內部檢討中的責任歸屬與人名。
- 不承諾未經拍板的事項。

## Verification
1. 完整的客戶溝通稿
2. 對照表：| 內部用語 | 改成什麼 |
3. **列出你刻意省略的內容與理由**
```

**預期的用語轉換**：異常件 → 延遲件、黑洞件 → 查詢中的包裹、末端延遲 → 最後一哩配送延遲、OTR → 準時送達率。

**預期刻意省略**：SOP 沒寫主動通知（內部檢討）、各站長姓名、冷鏈車輛不足。

## 🏁 練習四：待辦追蹤

```markdown
## Goal
從會議紀錄產出待辦追蹤表，供下次週會檢視。

## Scope
- 寫入 `reports/2026-W37_營週會待辦追蹤.md`
- 不要包含個人聯絡方式

## Verification
表格欄位：項目 / 負責人 / 期限 / 狀態 / 相依於誰

**「相依於誰」欄位很重要**：例如「麥禾冷藏合約條件」相依於業務處回覆，
在對方回覆前，這項無法由營運處推進。
```
