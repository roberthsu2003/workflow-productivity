## 一、營運術語

| 縮寫／術語 | 全稱 | 說明 |
| :--- | :--- | :--- |
| **OTR** | On-Time Rate | 準時率。準時送達件數 ÷ 總配送件數 |
| **ADH** | Average Delivery Hours | 平均配送時數。從收件到簽收的平均時間 |
| **末端** | 末端配送 | 從最後一個轉運中心到收件人的路段 |
| **中繼站** | — | 區域轉運節點，非倉庫，不做長期儲存 |
| **爆倉** | — | 單日進貨量超過倉容 85% 的狀態 |
| **回頭車** | — | 送完貨後回程順路載貨的車輛，成本較低 |
| **黑洞件** | — | 系統顯示已出庫但超過 48 小時無掃描紀錄的包裹 |
| **檔期** | — | 電商大促期間（雙 11、雙 12、年中慶） |
| **彈性人力** | — | 檔期臨時調用的派遣人力 |

## 六、⚠️ 容易混淆的詞

> [!WARNING]
> 以下詞彙在公司內外意思不同，撰寫對外文件時請特別注意。

| 詞 | 公司內部意思 | 一般／對外意思 | 對外請改用 |
| :--- | :--- | :--- | :--- |
| **異常件** | 未準時送達的件（含輕微延遲） | 容易被理解為「出事的包裹」 | 「延遲件」 |
| **黑洞件** | 超過 48 小時無掃描紀錄 | 無此說法 | 「查詢中的包裹」 |
| **爆倉** | 倉容超過 85% | 容易被理解為「倉庫爆炸」 | 「倉儲量能吃緊」 |
| **回頭車** | 回程順路載貨 | 可能被理解為「退貨」 | 「回程車輛」 |
| **末端** | 最後一段配送 | 可能被理解為「結束」 | 「最後一哩配送」 |

## 七、數字慣例

| 項目 | 慣例 |
| :--- | :--- |
| 金額 | 一律標註 **TWD**，內部系統以「分」為單位儲存 |
| 日期 | `YYYY-MM-DD`，對外文件用「2026 年 9 月 8 日」 |
| 時間 | 24 小時制，時區一律 `Asia/Taipei` |
| 準時率 | 保留小數點後一位（97.8%） |
| 單量 | 千分位分隔（18,500 件） |

## 八、資料處理原則

> [!IMPORTANT]
> **資料缺漏時應明確標示為「資料缺漏」，不得以 0 或推估值填補。缺漏原因須於備註欄說明。**
>
> 此原則源自 2026 年 Q2 WMS 系統移轉期間的經驗——中區 6 月資料未落帳，若以 0 計入平均，會嚴重扭曲全年統計。
