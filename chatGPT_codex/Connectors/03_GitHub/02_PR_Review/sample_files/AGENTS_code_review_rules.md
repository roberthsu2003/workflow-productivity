# 潮汐物流 `tideflow-portal` — Code Review 規則

> ⚠️ 教學用虛構資料。
>
> **使用方式**：把本檔內容併入你測試 repo 的 `AGENTS.md`，作為 `## Code review rules` 章節。

---

## Code review rules

Codex 在審查 PR 時，必須逐條檢查以下規則。**每一條發現都要指出檔案與行號。**

### 🔴 阻擋級（Blocking）— 必須修正才能合併

| 編號 | 規則 | 為什麼 |
| :--- | :--- | :--- |
| B-1 | **金額一律用整數（分）計算。** 發現浮點數金額請標記。 | 浮點數累加會產生誤差，帳務對不上 |
| B-2 | **禁止直接字串拼接 SQL。** 一律使用參數化查詢。 | SQL injection |
| B-3 | **未處理的 Promise rejection。** 每個 async 呼叫都要有錯誤處理。 | 靜默失敗，問題無法追蹤 |
| B-4 | **不可提交 `.env`、`*.pem`、`secrets/` 底下任何檔案。** | 憑證外洩 |
| B-5 | **不可修改既有的 migration 檔。** 只能新增。 | 已套用的 migration 被改會導致環境不一致 |
| B-6 | **不可修改公開 API 的輸入／輸出型別**，除非 PR 說明明確指出。 | 破壞下游整合 |
| B-7 | **日誌中不可包含完整卡號、CVV、持卡人姓名、身分證號。** | 個資與 PCI 法遵 |
| B-8 | **修 bug 的 PR 必須包含對應的回歸測試。** | 沒有測試就會再壞一次 |

### 🟡 警告級（Warning）— 應該處理，但不阻擋

| 編號 | 規則 |
| :--- | :--- |
| W-1 | 新增執行期依賴需在 PR 說明中說明理由 |
| W-2 | `src/api/` 不可直接 import `src/ui/`；跨層呼叫走 `src/lib/` |
| W-3 | 單一函式超過 80 行建議拆分 |
| W-4 | 缺少 TypeScript 型別標註（避免 `any`） |
| W-5 | 硬編碼的設定值（URL、逾時秒數、魔術數字）應移到設定檔 |
| W-6 | 時區處理未明確指定（應使用 `Asia/Taipei` 或 UTC，不依賴系統預設） |

### 🟢 建議級（Suggestion）

| 編號 | 規則 |
| :--- | :--- |
| S-1 | commit message 使用繁體中文，程式碼註解使用英文 |
| S-2 | 測試檔命名為 `*.test.ts`，放在 `tests/` |
| S-3 | 變數命名避免縮寫（`cnt` → `count`） |

## 特別區域規則

### `src/legacy/`

> **只修正 bug，不要重構、不要改風格、不要加型別。**
>
> 這個目錄的程式碼沒有測試覆蓋，任何「順手改善」都是高風險行為。
> 審查時若發現 PR 在此目錄做了非 bug 修正的變更，標記為 🔴 阻擋級。

### `services/payments/`

> 除上述規則外，額外要求：
> - 任何變更必須同時更新 `CHANGELOG.md`
> - 對外 API 的錯誤碼**不可變更語意**，只能新增
> - 測試覆蓋率不得低於 90%

### `migrations/`

> 只能新增檔案。既有 migration 一律不可修改或刪除（B-5）。

## 審查行為規範

> [!WARNING]
> ### Codex 在審查時**不可以**做的事
> - ❌ **不可 approve PR**
> - ❌ **不可 merge PR**
> - ❌ **不可直接修改 PR 的程式碼**
> - ❌ **不可關閉 PR**
>
> Codex 的角色是**留下審查意見**。所有決定由人做。

### 審查意見的格式要求

每一條意見必須包含：

1. **規則編號**（B-1 / W-3 / S-2…）
2. **檔案與行號**
3. **問題描述**（一句話）
4. **建議的修法**（具體，不是「請改善」）
5. **嚴重度**

**範例**：

> 🔴 **B-1** `src/checkout/calcTotal.ts:47`
> 小計使用 `parseFloat` 計算金額，累加多筆時會產生誤差。
> 建議：改用整數（分）計算，顯示時再除以 100。
> 例：`const subtotalCents = items.reduce((s, i) => s + i.priceCents * i.qty, 0)`

### 沒有問題時

**不要為了留意見而留意見。** 若整個 PR 沒有違反任何規則，回覆：

> 已依 code review rules 逐條檢查，未發現需要處理的問題。
> 已檢查的規則：B-1 ~ B-8、W-1 ~ W-6、S-1 ~ S-3。

## 安全替代方案（Safe alternatives）

當標記問題時，一併提供安全的替代寫法：

| 問題 | 安全替代 |
| :--- | :--- |
| 字串拼接 SQL | 參數化查詢：`db.query('SELECT * FROM t WHERE id = $1', [id])` |
| 浮點數金額 | 整數分：`priceCents: number` |
| 未處理的 Promise | `try/catch` 或 `.catch()`，並記錄錯誤 |
| `any` 型別 | 明確型別或 `unknown` + 型別守衛 |
| 硬編碼設定 | 讀取環境變數並提供預設值 |
| 依賴系統時區 | 明確指定 `Asia/Taipei` 或全程使用 UTC |
