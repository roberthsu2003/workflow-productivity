# 02-2. IG 貼文與品牌合規審查

> 🔵 **方案需求**：Plus 起。合規審查部分僅需讀檔，🟢 Free 也可練。

**情境**：實習小編交了一批秋季新品的社群文案草稿。上市前你要做最後的合規審查——**這批草稿裡有 18 處問題，其中 9 處涉及法規風險。**

## 🥇 練習一：合規審查（本章核心）

```markdown
## Goal
審查社群文案草稿，找出所有違反品牌規範、法規或與事實不符的內容。

## Context
審查依據（三份文件都必須讀）：
1. `秋季新品社群文案庫草稿.md`（待審查對象）
2. `麥禾烘焙_品牌視覺規範與色彩配置表.json`（tone of voice 與禁用語）
3. `麥禾烘焙_2026秋季新品行銷企劃與視覺規格書.md`（**產品事實的唯一正確來源**）

## Scope
- **只審查，不要改寫。** 改寫是下一個練習。
- 不要修改任何來源文件。
- **每一項發現都必須指出違反的是哪份文件的哪一條規定。**

## Verification
輸出一張表：
| 編號 | 位置 | 原文 | 問題 | 違反的規定 | 嚴重度 |

嚴重度分三級：
- 🔴 **法規／不實**（可能違法或陳述不實，絕對不能上）
- 🟡 **品牌規範**（違反內部規定）
- 🟢 **風格建議**（可改可不改）

最後統計：共幾處？其中幾處是 🔴？
```

### 📝 驗收標準（講師用）

**應找出 18 處，其中 9 處為 🔴。**

三個難度層級：

| 難度 | 例子 | 說明 |
| :---: | :--- | :--- |
| 🟢 容易 | 「全台最好吃」「養生」「純天然」 | 直接比對禁用語清單就能抓到 |
| 🟡 中等 | 標籤 12 個超過上限 8 個；缺少必要標籤 `#當日現烤`；未標過敏原 | 需要細讀 JSON 規範 |
| 🔴 **困難** | **草稿 C 第 2 張「栗子來自日本頂級產區」** | 單看社群規範**不違規**，必須**交叉比對企劃書**才知道實際產地是**嘉義中埔** |

> [!IMPORTANT]
> ### 第 13 項（日本產地）是整個 Connectors 章節的教學高潮
> 這句話讀起來正面、專業、沒有觸犯任何禁用語。**只有把三份文件對起來看，才會發現它是不實陳述。**
>
> **如果 Codex 沒抓到它**：不要當成失敗，當成教材。問學員：「為什麼會漏掉？」答案是 prompt 沒有明確要求「與企劃書交叉比對事實」。
>
> 加上這一句再跑一次：
> ```text
> 額外檢查：文案中所有關於產品的**事實性陳述**（產地、成分、價格、數量、
> 日期），是否與企劃書一致？不一致的一律標記為 🔴 不實。
> ```
>
> **兩次結果的差異，就是這堂課最值得記住的東西。**

## 🥈 練習二：改寫

```markdown
## Goal
將草稿 A（IG 貼文主圖文案）改寫成完全合規的版本。

## Context
- 承續練習一的審查結果。
- 產品事實一律以企劃書為準。
- IG 規範：建議字數 300 字內，標籤 3–8 個，必含 `#麥禾烘焙` `#當日現烤`。

## Scope
- **不可使用任何禁用語。**
- 必須包含：食材產地（嘉義中埔）、每日限量（75 個）、販售期間（10/05–11/30）、**過敏原**。
- 語氣依規範：用「我們」、描述具體口感與香氣、誠實說明售完狀況。
- 不要修改原始草稿檔，改寫版另存新檔。

## Verification
輸出：
1. 改寫後的完整文案
2. 對照表：| 原文問題 | 我怎麼處理 |
3. 字數與標籤數統計（證明符合規範）
```

### 參考答案的方向

> 🌰 秋栗蒙布朗，10/5 開賣
>
> 我們用嘉義中埔的栗子，蒸熟後手工壓成細泥，一圈一圈擠在當天現烤的塔皮上。上頭是北海道鮮奶油，甜度壓得比一般蒙布朗低一些，讓栗子的香氣出得來。
>
> 每間店每天做 75 個，通常中午前就會結束。供應到 11/30。
>
> NT$145
> 過敏原：含蛋、乳、小麥、堅果（栗子）
>
> #麥禾烘焙 #當日現烤 #秋栗蒙布朗 #嘉義中埔栗子

**注意**：沒有驚嘆號轟炸、沒有最高級形容、沒有製造焦慮，但**具體的細節本身就有說服力**。

## 🥉 練習三：把審查流程做成 Skill

這個合規審查每一季都要做一次。**這正是該做成 Skill 的訊號。**

```markdown
## Goal
把剛才的合規審查流程封裝成一個可重複使用的 skill。

## Scope
- 建立 `.agents/skills/brand-compliance-review/SKILL.md`
- 不要修改任何示範資料檔。

## Verification
SKILL.md 必須包含：
1. `description` 明確寫出何時該用、何時不該用
2. 編號的審查步驟，**含「與事實來源交叉比對」這一步**
3. 三級嚴重度的判定標準
4. 輸出格式
5. 明確的限制（不可自行改寫、不可放行 🔴 項目）
```

> 完成後，用**另一份**文案草稿測試它。做得好的 skill 應該在新資料上也抓得到問題。
> 詳見 [Skills 章節](../../../Skills/README.md)。

## 🏁 練習四：對比度實測

品牌規範說 `wheat_gold #C8912F` 在 cream `#F7F1E6` 上對比度不足。**別只是相信它——實際算一次。**

```markdown
## Goal
驗證品牌規範中的無障礙宣稱，並找出所有安全的色彩組合。

## Context
- 色票來源：`麥禾烘焙_品牌視覺規範與色彩配置表.json`
- 標準：WCAG 2.1 AA（一般文字 4.5:1，大字 3.0:1）

## Scope
- 寫一個小腳本實際計算，**不要憑印象判斷**。
- 腳本放在 `scripts/contrast_check.py`，不要修改 JSON 規範檔。

## Verification
輸出一張矩陣表：所有「文字色 × 背景色」組合的對比度數值，並標示：
- ✅ 通過一般文字（≥ 4.5）
- ⚠️ 僅通過大字（3.0–4.5）
- ❌ 不通過（< 3.0）

最後回答：規範中「wheat_gold 不可作為內文色」的說法，**計算結果支持嗎？**
```

> **這是 Codex 相對於 Claude 的具體優勢**：品牌規範是結構化的 JSON，Codex 可以寫程式實際驗證，而不是憑感覺。
