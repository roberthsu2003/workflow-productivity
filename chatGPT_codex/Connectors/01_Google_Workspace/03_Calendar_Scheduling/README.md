# 01-3. Calendar 排程調配

> 🔵 **方案需求**：Plus 起。授權範圍建議 **`calendar.readonly`**。
>
> [!WARNING]
> **本章所有練習都不直接修改行事曆。** Codex 負責偵測衝突與提出方案，異動由人執行。行事曆改錯會影響其他與會者，而且沒有 `git restore` 可以救。

**情境**：你是潮汐物流營運處副理陳柏宇的助理。他下週的行事曆已經被塞滿，你要在他上班前找出所有排程問題。

---

## 📂 示範資料

[`模擬行事曆日程資料集.md`](./sample_files/模擬行事曆日程資料集.md) — 2026-09-07 至 09-11 的完整日程，**內含三組刻意設計的衝突**。

---

## 🥇 練習一：衝突偵測（含移動時間）

> [!IMPORTANT]
> **這個練習的關鍵在「地理不可能」。** 大多數人（和模型）只會比對時間區間有沒有重疊，因此會漏掉週二那組——時間沒重疊，但台北到花蓮的移動時間讓它根本做不到。

```markdown
## Goal
找出 2026-09-07 至 09-11 這週行事曆中所有的排程問題。

## Context
- 當事人：營運處副理陳柏宇，主要辦公地點為台北總部。
- 這週有一場需要跨縣市移動的現勘行程。

## Scope
- **只讀取行事曆，絕對不要新增、修改或刪除任何事件。**
- 不要發送任何會議邀請或變更通知。

## Verification
衝突偵測必須涵蓋**三種類型**，缺一不可：
1. **時間直接重疊**：兩個事件的時段有交集
2. **地理不可能**：時間沒重疊，但**扣掉地點之間的移動時間後做不到**
   （台北 ↔ 花蓮請以單程 2.5 小時計算，含站到現場的交通）
3. **緩衝不足**：連續會議之間沒有任何空檔（含跨樓層移動與線上會議切換）

輸出格式：
| 編號 | 日期 | 衝突類型 | 涉及事件 | 具體說明 |

最後回答：這三組衝突中，哪一組**最不容易被發現**？為什麼？
```

### 📝 解答對照（講師用）

| 編號 | 日期 | 類型 | 涉及事件 |
| :---: | :--- | :--- | :--- |
| 1 | 09-08（二） | **地理不可能** | 11:00–12:00 台北會議室 B ／ 14:00–16:00 花蓮現勘 |
| 2 | 09-09（三） | 時間重疊 | 10:00–11:00 供應商議價 ／ 10:30–11:30 麥禾會議（重疊 30 分） |
| 3 | 09-10（四） | 時間重疊 + 價值衝突 | 13:00–14:00 星鏈提案 ／ 13:30–14:30 和欣客訴（重疊 30 分） |

**答案**：最不容易被發現的是**第 1 組**。時間欄位上完全沒有重疊，只有把「地點」與「移動時間」納入考慮才看得出來。

> **教學重點**：如果 Codex 只找到 2 和 3，不要當成它「表現不好」——**當成教材**。讓學員自己發現第 1 組，然後回頭改 prompt（加上「請檢查地點之間的移動可行性」），重跑一次比較差異。這比直接給正確 prompt 有效得多。

## 🥈 練習二：提出調整方案（不執行）

```markdown
## Goal
針對偵測到的三組衝突，各提出 2 個可行的調整方案供陳副理選擇。

## Context
不可異動的事項：
- 年度預算編列（週四 09:00–12:00）
- 月度營運檢討會（週二 09:30–11:00）
- 每日晨會（08:30–09:00）

偏好與限制：
- 外部客戶會議偏好排在下午
- 週五 14:00–17:00 已刻意保留，可用於安插延期會議
- 花蓮現勘需搭配東區站長行程，改期需重新協調
- 週三 16:00–17:00 個人週報時段可讓步，但需另找時段補回

## Scope
- **只提方案，不要執行任何行事曆異動。**
- 不要發送會議邀請或變更通知。
- **不要替我決定**——每組都要給兩個方案並說明取捨。

## Verification
每組衝突輸出：
| 方案 | 具體調整 | 需通知誰 | 代價 | 風險 |

最後標註：哪些方案**需要對方同意**才能成立（例如需重新協調東區站長行程）。
```

### 品質檢查

| 檢查項目 | 為什麼 |
| :--- | :--- |
| 有沒有動到「不可異動」的事項？ | 這是明確的紅線測試 |
| 週四那組有沒有替你做決定？ | 它應該呈現取捨，不是選一個 |
| 有沒有指出哪些方案需要對方同意？ | 你能單方面決定的和不能決定的，成本天差地遠 |
| 有沒有處理「週報時段要補回」？ | 讓步不等於取消 |

## 🥉 練習三：價值判斷題（課堂討論）

週四的衝突沒有標準答案：

| | 星鏈物流合作提案 | 和欣零售客訴案 |
| :--- | :--- | :--- |
| 性質 | 策略機會 | 客訴處理 |
| 時效 | 可延期 | **已逾 9/4 期限** |
| 延期成本 | 低（對方也在找合作） | 高（客戶情緒高張，有解約風險） |
| 缺席影響 | 策略處可代表 | 客戶指名要營運端說明 |

```markdown
## Goal
針對週四 13:00–14:30 的衝突，分析兩個會議各自的延期成本，供我做決定。

## Scope
- 只做分析，**不要替我選**。
- 不要修改行事曆。

## Verification
輸出：
1. 兩個會議各自的「延期會發生什麼事」
2. 兩個會議各自的「缺席但派代表會發生什麼事」
3. **你認為哪些資訊是我有、但你沒有的**——這些資訊會影響決定嗎？
```

> **第 3 點是這個練習的靈魂。** 好的分析會誠實說：「我不知道星鏈這個合作對貴公司的策略優先度，也不知道和欣的合約金額量級——這兩項會改變結論。」
>
> **會替你下定論而不承認資訊缺口的模型，是最危險的。**

## 🏁 練習四：產出交辦清單

```markdown
## Goal
把調整方案整理成一份可執行的交辦清單。

## Scope
- **不要修改行事曆、不要發通知。**
- 產出寫入 `reports/2026-W37_行事曆調整建議.md`。
- 清單中不要包含外部與會者的完整信箱（用「姓名（公司）」代稱）。

## Verification
清單包含：
- 需陳副理親自決定的項目（含選項）
- 可由助理直接處理的項目
- 需要對外協調的項目（含建議的協調順序）
- **建議的執行時間**（例如「請於週一 09:00 前完成，以免週二來不及」）
```
