# 01-1. Drive 跨檔分析

> 🔵 **方案需求**：Plus 起，需授權 Google Drive app（建議 `drive.file` 唯讀範圍）。

**情境**：你是潮汐物流的營運分析師。主管在會議前 30 分鐘丟給你一句話：「東區到底出了什麼事？」你手上有一份全年配送績效 CSV 和一份策略備忘錄，都在 Drive 上。

---

## 📂 示範資料

| 檔案 | 說明 |
| :--- | :--- |
| [`潮汐物流_2026全年配送績效與客訴分析表.csv`](./sample_files/潮汐物流_2026全年配送績效與客訴分析表.csv) | 4 區 ×12 月，48 列量化資料 |
| [`潮汐物流_2026年度跨境物流擴張策略備忘錄.md`](./sample_files/潮汐物流_2026年度跨境物流擴張策略備忘錄.md) | 質化策略文件，含年度目標與已知風險 |

**課前準備**：把這兩個檔案上傳到 Drive 的同一個資料夾（例如「潮汐物流／2026 營運分析」）。

---

## 🥇 練習一：唯讀偵察（先不要下結論）

```markdown
## Goal
盤點 Drive「潮汐物流／2026 營運分析」資料夾內的資料，說明它能回答什麼問題、不能回答什麼問題。

## Context
- 資料夾內有一份 CSV（配送績效）與一份 MD（策略備忘錄）。
- 我還不知道資料的完整性如何。

## Scope
- **只讀取這個資料夾內的檔案，不要讀取其他 Drive 內容。**
- 不要修改、移動或分享任何檔案。
- **這一輪不要做分析，也不要下結論。**

## Verification
輸出四段：
1. 每個檔案的欄位／章節結構
2. 資料涵蓋的時間範圍與粒度
3. **資料品質問題清單**（缺漏、格式不一致、可疑數值）
4. 這批資料**無法**回答的問題
```

> **教學重點**：第 3、4 段是關鍵。學員通常會直接問「幫我分析」，然後拿到一份看似完整、實則建立在缺漏資料上的報告。

**預期它應該發現**：中區 2026-06 整列為空。如果它沒發現，這就是很好的教材——**證明「先偵察」不是多餘步驟**。

---

## 🥈 練習二：區分「真異常」與「離群但正常」

```markdown
## Goal
找出 2026 年配送績效中**真正需要管理層介入**的異常，並排除只是「數字看起來奇怪但其實正常」的情況。

## Context
- 資料來源：Drive 中的 `潮汐物流_2026全年配送績效與客訴分析表.csv`
- 交叉參考：同資料夾的 `..._擴張策略備忘錄.md`（內含年度目標與已知風險）
- 公司的準時率目標是 95%。

## Scope
- 只讀取，不修改任何 Drive 檔案。
- **對每一個你標記為異常的項目，必須指出支持證據**（備註欄、客訴數、或備忘錄中的對應段落）。
- **不可對缺漏值做內插或補 0。**

## Verification
輸出一張表格，每列包含：
| 月份 | 區域 | 觀察到的現象 | 分類 | 證據 | 建議動作 |

「分類」欄只能是三種之一：
- **真異常**（需要管理層處理）
- **可解釋的波動**（有明確原因，不需處理）
- **資料問題**（不是營運問題，是資料本身有問題）

最後用三句話總結：如果只能處理一件事，該處理哪一件？為什麼？
```

### 📝 解答對照（講師用）

| 月份 | 區域 | 現象 | 正確分類 | 證據 |
| :--- | :--- | :--- | :--- | :--- |
| 2026-08 | 東區 | 準時率 81.3%，配送時數 62.7 小時 | **真異常** | 備註「颱風封路」+ 異常件數 765 + 客訴 99 件 |
| 2026-11 | 南區 | 單量 33,489（平時 2.3 倍） | **可解釋的波動** | 備註「雙 11 檔期」；準時率僅降 3.8pp，屬合理 |
| 2026-06 | 中區 | 所有數值欄為空 | **資料問題** | 備註「WMS 系統移轉期間未落帳」 |

> [!WARNING]
> **常見的錯誤答案**：把南區 11 月當成「異常暴增需調查」，或把中區 6 月當成「單量歸零的重大營運危機」。
>
> 如果模型犯了這兩個錯，正好用來教學員：**每個結論都要求附證據，是防止這類錯誤最有效的手段。**

## 🥉 練習三：跨檔交叉比對

質化文件 + 量化資料的組合，是 Drive 分析最有價值的用法。

```markdown
## Goal
檢驗策略備忘錄中的年度目標，有哪些在實際數據上已經達成、哪些明顯落後。

## Context
- 質化來源：`潮汐物流_2026年度跨境物流擴張策略備忘錄.md` 的「年度目標」章節
- 量化來源：`潮汐物流_2026全年配送績效與客訴分析表.csv`

## Scope
- 只讀取，不修改。
- **只評估備忘錄中有明確數字的目標**；純敘述性的目標請列在「無法量化評估」區。
- 中區 6 月資料缺漏，計算年度平均時**須排除該筆並註明**，不可視為 0。

## Verification
輸出：
1. 目標達成對照表（目標 / 實際 / 差距 / 判定）
2. 「無法量化評估」的目標清單
3. **你在計算中做過的每一個假設**（例如缺漏值怎麼處理）
```

> **教學重點**：第 3 點「列出你做過的假設」應該變成學員的預設習慣。分析報告的可信度，取決於假設是否被說清楚。

## 🏁 練習四：產出可交付成果

```markdown
## Goal
把前三個練習的結論，整理成一份主管會議用的簡報大綱與一張試算表。

## Scope
- **不要修改 Drive 上的任何檔案。**
- 產出檔寫在本機 `reports/` 目錄：
  - `reports/2026_配送績效檢討.md`（簡報大綱）
  - `reports/2026_配送績效檢討.xlsx`（數據附件）
- 數字必須與來源 CSV 完全一致。

## Verification
- 簡報大綱結構：現況 → 真異常（1 項）→ 資料品質問題（1 項）→ 建議行動
- 試算表含三個工作表：明細（首列凍結）／各區年度彙總／異常月份
- **缺漏資料在兩份產出中都要明確標示為「資料缺漏」，不可留白也不可填 0。**
```
