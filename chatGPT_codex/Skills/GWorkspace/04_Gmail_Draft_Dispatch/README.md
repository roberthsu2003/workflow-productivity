# GW-04. 採購通知草稿

> 🔵 **方案需求**：Plus 起（Gmail plugin + Spreadsheets plugin）。
>
> [!WARNING]
> **本章一律不授權 `gmail.send`。** 所有產出都是草稿。

**情境**：採購核准單三級簽核完成，你要通知供應商下單、通知內部相關單位、並產出一份追蹤表。三件事、三種對象、三種語氣。

## 🥇 練習一：先核對，再發信

> [!IMPORTANT]
> **發信前先核對兩份文件是否一致。** 這是實務上最常出事的地方——核准單寫的金額與明細表合計對不上，信發出去才發現。

```markdown
## Goal
核對採購核准單與料件明細表是否一致。

## Scope
- **只讀取，不要建立任何郵件或草稿。**
- 不要修改任何檔案。

## Verification
逐項核對：
| 項目 | 核准單 | 明細表 | 一致？ |

特別確認：
1. **金額**：核准單的預估金額 vs. 明細表的合計
2. 簽核是否完整（三級都簽了嗎？）
3. 需求日期與「急件」標記是否一致
4. **有沒有任何不一致的地方？如果有，發信前必須先處理。**
```

### 📝 解答（講師用）

核准單預估 **486,300 元**；明細表合計 = 250,000 + 68,000 + 58,000 + 94,800 + 15,300 = **486,100 元**。

**差 200 元。**

> 這個差異很小，容易被忽略——但採購單上的金額與實際下單金額不符，會在請款時卡住。
>
> **正確行為**：指出差異、暫緩發信、請承辦確認是哪一邊要修正。
>
> 若模型直接無視差異開始寫信，就是很好的教學時刻：**「差 200 元而已」不是理由，帳就是帳。**

## 🥈 練習二：三種對象的草稿

```markdown
## Goal
核對無誤（或差異已確認處理）後，產出三封郵件草稿。

## Context
| 對象 | 目的 | 語氣 |
| 供應商（冷研設備） | 正式下單 | 商務正式，含完整規格 |
| 內部倉管 | 預告到貨、準備收料空間 | 簡潔，重點是日期與數量 |
| 財務處 | 預告付款需求 | 含單號、金額、預計請款時間 |

## Scope
- **一律建立草稿，絕對不要寄出。**
- **不可承諾核准單上沒有的事項**（折扣、付款條件、額外交期）。
- 供應商信件不可透露內部成本結構或其他供應商資訊。
- 內部信件不需要附完整明細，附單號即可。

## Verification
三封草稿 + 對照表：
| 收件對象 | 附上了什麼 | 刻意沒附什麼 | 為什麼 |

最後列出：**需要我確認後才能寄出的事項**。
```

### 品質檢查

| 檢查 | 常見錯誤 |
| :--- | :--- |
| 供應商信有承諾付款天期嗎？ | ⚠️ 核准單沒寫，不可自行承諾 |
| 內部信附了完整價格明細嗎？ | 倉管不需要知道單價 |
| 「急件」有傳達給倉管嗎？ | 明細表第 1 項標了急件 |
| 有寄出嗎？ | **紅線** |

## 🥉 練習三：產出追蹤表

```markdown
## Goal
產出這張採購單的到貨追蹤表。

## Scope
- 輸出 `output/PO-2026-0915_到貨追蹤.xlsx`
- 不要修改原始檔案。

## Verification
欄位：項次 / 料號 / 品名 / 訂購量 / 已到貨 / 待到貨 / 預計到貨日 / 狀態 / 備註
- 「已到貨」初始為 0
- **「乾冰」註明分批交貨**（明細表備註有寫）
- 首列凍結，可篩選
```

## 🏁 練習四：串成完整流程

前三個練習是分開的。真實工作是一條龍。

```markdown
## Goal
把「核對 → 草稿 → 追蹤表」做成一個 skill。

## Scope
- 建立 `.agents/skills/purchase-dispatch/SKILL.md`

## Verification
SKILL.md 必須包含：
1. `description`：何時用、何時不用
2. **核對步驟必須在草稿步驟之前**，且核對不通過時**中止流程**
3. 三種對象的資訊揭露原則
4. 紅線：不可寄出、不可承諾核准單外的事項
5. 輸出清單

**特別檢查**：你的 skill 在「金額對不上」時會怎麼做？
應該是**停下來報告**，不是繼續往下走。
```

> **這題的教學重點**：好的自動化流程要有**中止條件**。一路往下跑的流程，會把錯誤放大成三封發出去的信。
