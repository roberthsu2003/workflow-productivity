# GW-03. 會議手記整理

> 🔵 **方案需求**：Plus 起（Google Drive / Docs plugin）。讀本機 docx 🟢 Free 亦可。

**情境**：你在會議上手寫了一頁凌亂筆記，還有一段「我沒聽清楚」的待整理清單。現在要把它變成可以發給全體的正式會議紀錄。

---

## 📂 示範資料

[`2026_Q3營運檢討會_會議手記.docx`](./sample_files/2026_Q3營運檢討會_會議手記.docx)

**這份筆記刻意寫得很像真的手記**：

- 沒有標點、用箭頭代表結論、人名只寫名字
- 有 `→ 決議：` 標記，但也有沒標記卻其實是決議的
- 最後有「待整理」段落，是記錄者自己承認沒聽清楚的部分

---

## 🥇 練習一：區分四種狀態

```markdown
## Goal
把手記整理成正式會議紀錄。

## Context
- 來源：`sample_files/2026_Q3營運檢討會_會議手記.docx`
- 讀者：未與會的同仁

## Scope
- **嚴格區分四種狀態**：
  | 狀態 | 判準 |
  | 已決議 | 有明確拍板（含 `→ 決議：` 標記，或文中可確認的拍板） |
  | 討論中未定案 | 有討論但無結論 |
  | 待確認 | 需他人回覆才能推進 |
  | **記錄者未確認** | 手記「待整理」段落中的項目 |
- **不得補造手記中沒有的內容。**
- 人名只寫名字的，保留原樣，不要自行補全名。

## Verification
輸出結構：
1. 會議資訊
2. 決議事項（每項註明拍板者）
3. 行動項目（項目 / 負責人 / 期限）
4. **討論中但未定案**
5. **待確認問題**
6. **記錄者未確認事項**（這一段不可省略）
```

### 📝 解答對照（講師用）

| 內容 | 正確分類 | 依據 |
| :--- | :--- | :--- |
| 報表標「資料缺漏」不填 0 | ✅ **已決議** | `→ 決議：`＋「營運長拍板」 |
| 慧玲本週五前給鼎和案結案時程 | ✅ **已決議 + 行動項目** | `→ 決議：`＋負責人＋期限 |
| 北中區確定、南區週四回覆 | ✅ **已決議** | 「→ 柏宇：北中區確定 南區禮拜四回覆」 |
| 雙 11 彈性人力 10/15 前定案 | ✅ **行動項目** | 文豪確認，有期限 |
| **冷鏈車採購時程** | ⚠️ **討論中未定案** | 「維倫說採購在跑 但沒給時間 **→ 這個沒結論**」 |
| **東區扣除颱風的準時率** | 🔍 **記錄者未確認** | 手記自己標「這個數字要再確認」＋待整理段落 |
| **冷鏈車採購預算金額** | 🔍 **記錄者未確認** | 「好像有提到但我沒記到」 |
| **營運長「不要再有下次」的所指** | 🔍 **記錄者未確認** | 待整理段落 |

> [!WARNING]
> ### 最容易出錯的是「東區扣除颱風後有 96 左右」
> 手記寫「**扣掉的話有 96 左右 → 這個數字要再確認**」。
>
> 把它寫成「東區排除颱風後準時率為 96%」是**錯的**——記錄者自己都標了要確認。
> 正確做法：列入「記錄者未確認事項」，註明需向鄭以樂查證。
>
> **會議紀錄最嚴重的失真，就是把「可能」寫成「是」。**

## 🥈 練習二：處理「待整理」段落

```markdown
## Goal
把手記最後的「待整理」三個項目，轉成可執行的查證清單。

## Scope
- **不要嘗試回答這些問題**——你沒有答案。
- 只產出「該問誰、問什麼、什麼時候前要問到」。

## Verification
| 待確認事項 | 該問誰 | 具體要問什麼 | 期限 | 為什麼重要 |
```

> **「不要嘗試回答」是這題的重點。** 模型看到問題會想回答，但這三個問題的答案只存在於當事人腦中。

## 🥉 練習三：產出正式 docx

```markdown
## Goal
產出可發送的正式會議紀錄檔案。

## Scope
- **不要修改原始手記檔案。**
- 輸出 `output/2026-09-08_Q3營運檢討會_會議紀錄.docx`
- 語氣正式中立，不加入評價。
- **不要寫入營運長的情緒描述**（「臉色不好看」屬於個人觀察，不宜入正式紀錄）。

## Verification
- 六段結構完整
- 「記錄者未確認事項」有保留
- 附一段對照：你從手記中**刪除**了哪些內容、為什麼
```

### 該刪除的內容

| 手記原文 | 該不該入正式紀錄 | 為什麼 |
| :--- | :---: | :--- |
| 「營運長臉色不好看」 | ❌ | 個人情緒觀察，不是事實紀錄 |
| 「東區還是拖後腿」 | ❌ | 評價性用語，改為中性的數據陳述 |
| 「這個沒結論」 | ✅ 保留 | 這是重要事實 |
| 「我沒聽清楚」 | ✅ 保留但改寫 | 改為「記錄者未確認，待查證」 |

## 🏁 練習四：做成 Skill

```markdown
## Goal
把會議紀錄整理流程做成 skill。

## Verification
與 [Level4 會議秘書](../../Examples/Level4_Meeting_Secretary/SKILL.md)比較：
- 那個 skill 處理**逐字稿**（完整對話）
- 這個情境是**手記**（片段、含記錄者自述的不確定）

兩者的差異該怎麼反映在 SKILL.md 的 `description` 與流程中？
可以合併成一個 skill 嗎？還是該分開？請說明你的判斷。
```

> **沒有標準答案。** 這題練的是「skill 的邊界該畫在哪」。
