# GW-01. 髒資料任務追蹤表

> 🔵 **方案需求**：Plus 起（Spreadsheets plugin）。讀取本機 xlsx 部分 🟢 Free 亦可。

**情境**：各部門把待辦事項填進同一張表，但每個人填法都不一樣。你要把它整理成可以排序、可以篩選、可以自動提醒的樣子。

> **這是最貼近真實辦公室的練習**——真實資料永遠是髒的。

---

## 📂 示範資料

[`2026年度各部門待辦事項原始清單.xlsx`](./sample_files/2026年度各部門待辦事項原始清單.xlsx)

12 列資料，兩個工作表（「原始待辦清單」「欄位說明」）。

### 刻意埋的髒資料

| 欄位 | 問題 |
| :--- | :--- |
| **期限** | 混用 `2026/09/14`、`2026-09-30`、`已完成`、`盡快`、`2026/9/11`、**空白** |
| **優先度** | 中文「高／中／低」混入英文 `High`，另有未定義的「非常高」，以及空白 |
| **狀態** | 除了「未開始／進行中／已完成」，還冒出「待確認」「逾期」 |

---

## 🥇 練習一：先盤點，不要急著清理

```markdown
## Goal
盤點 `sample_files/2026年度各部門待辦事項原始清單.xlsx` 的資料品質。

## Scope
- **只讀取，不要修改，也不要產生新檔案。**
- 這一輪不要清理資料。

## Verification
輸出：
1. 每個欄位的**實際出現值**清單（不是「應該有的值」）
2. 不符合預期格式的儲存格位置（欄列座標）
3. **哪些問題可以自動修正、哪些必須人工判斷？**
4. 你**無法確定**該怎麼處理的項目
```

### 📝 解答對照（講師用）

| 問題 | 可自動修正？ | 為什麼 |
| :--- | :---: | :--- |
| `2026/09/14` → `2026-09-14` | ✅ | 純格式轉換，語意不變 |
| `High` → `高` | ✅ | 明確對應 |
| `2026/9/11` → `2026-09-11` | ✅ | 補零 |
| **「已完成」出現在期限欄** | ❌ | 這是狀態不是日期。原本的期限是什麼？**不知道** |
| **「盡快」** | ❌ | **不是日期**。換算成任何具體日期都是捏造 |
| **「非常高」** | ❌ | 未定義值。要新增優先度層級，還是併入「高」？**要問人** |
| **期限空白（第 6 列）** | ❌ | 備註寫「數量未定」，代表確實還沒定期限 |
| **狀態「待確認」「逾期」** | ❌ | 要擴充狀態定義，還是對應到既有值？**要問人** |

> [!WARNING]
> ### 「盡快」是這個練習的核心
> 模型很容易把「盡快」轉成「一週內」或某個具體日期。**那是捏造。**
>
> 正確做法：保留原值、標示為「未定期限」、列入需人工確認清單。
>
> 這條原則在 [Level4 會議秘書 skill](../../Examples/Level4_Meeting_Secretary/SKILL.md) 也出現過——**「盡快」不是期限**。

## 🥈 練習二：產出清理後的試算表

```markdown
## Goal
產出可用於排序、篩選與自動提醒的乾淨版任務追蹤表。

## Scope
- **不要修改原始檔案。** 輸出 `output/2026年度待辦事項_已整理.xlsx`。
- **可自動修正的才修正**；需人工判斷的一律保留原值並標記。
- 不可捏造任何日期。

## Verification
產出四個工作表：
1. **已整理**：格式統一的資料，首列凍結，含「原始值」欄位供追溯
2. **待人工確認**：無法自動處理的項目，含問題描述與建議選項
3. **修正紀錄**：| 列 | 欄 | 原值 | 新值 | 依據 |
4. **欄位規範**：整理後應遵守的格式定義

完成後在對話中回報：自動修正 N 筆、需人工確認 M 筆。
```

### 品質檢查

| 檢查 | 常見錯誤 |
| :--- | :--- |
| 「盡快」被轉成日期了嗎？ | ⚠️ 最常見的錯誤 |
| 「已完成」在期限欄怎麼處理？ | 應移到狀態欄並標記期限未知 |
| 有保留「原始值」欄嗎？ | 沒有的話無法追溯，出錯查不出來 |
| 「非常高」被自己決定了嗎？ | 應列入待人工確認 |
| 空白期限被填了嗎？ | 應保持空白 + 標記 |

## 🥉 練習三：加上自動提醒欄位

```markdown
## Goal
在已整理的表中加入「距今天數」與「風險等級」欄位。

## Context
- 今天：2026-09-08
- 風險等級規則：
  - 🔴 已逾期，或 3 天內到期且狀態非「已完成」
  - 🟡 7 天內到期
  - 🟢 其他
  - ⚪ **期限未知**（不可歸入任何顏色）

## Scope
- 期限未知的項目**一律標 ⚪**，不可推估。
- 不修改原始檔案。

## Verification
- 加上兩個欄位
- 回報各風險等級的筆數
- **⚪ 的項目要單獨列出**，說明為什麼無法評估
```

> **⚪ 這個類別是設計重點。** 沒有它，模型會被迫把「盡快」「空白」硬塞進紅黃綠，結果就是編造。

---

## 🏁 練習四：做成 Skill

這個清理流程每季都要做一次。

```markdown
## Goal
把清理流程做成 skill。

## Scope
- 建立 `.agents/skills/task-tracker-cleanup/SKILL.md`

## Verification
SKILL.md 需包含：
1. `description`：何時用、何時不用
2. **可自動修正 vs. 需人工判斷的明確判準**
3. 不可捏造日期的紅線
4. ⚪「無法評估」類別的定義
5. 輸出的四個工作表結構
```

## ✅ 驗收檢查清單

- [ ] 「盡快」沒有被轉成任何具體日期
- [ ] 「已完成」在期限欄的問題有被指出
- [ ] 「非常高」列入待人工確認，沒有自己決定
- [ ] 空白期限保持空白
- [ ] 有「原始值」欄可供追溯
- [ ] 風險等級有 ⚪「無法評估」類別
- [ ] 原始 xlsx 未被修改
