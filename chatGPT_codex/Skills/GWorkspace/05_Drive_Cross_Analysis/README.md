# GW-05. Drive 跨檔稽核

> 🔵 **方案需求**：Plus 起（Google Drive plugin）。

**情境**：內部稽核。你要確認「簡報上宣稱的數字」「原始資料」「會議紀錄的決議」三者是否一致——這是所有跨檔分析中最有價值、也最容易被跳過的工作。

> **這一章沒有新的示範檔案**，而是把前面章節產生的檔案交叉起來查。這正是真實稽核的樣子。

## 🥇 練習一：宣稱 vs. 事實

```markdown
## Goal
稽核簡報中的每一個數字，確認是否有原始資料支持。

## Context
- 宣稱來源：簡報 pptx
- 事實來源：兩份配送績效 CSV
- 目標來源：策略備忘錄的「年度目標」章節

## Scope
- **只讀取，不要修改任何 Drive 檔案。**
- **每一項稽核結論都必須指出證據位置**（哪個檔案、哪一頁／哪一列）。

## Verification
輸出稽核表：
| 簡報宣稱 | 頁次 | 原始資料 | 一致？ | 證據位置 |

判定只能是四種：
- ✅ **一致**
- ⚠️ **口徑不同**（數字不同但可解釋，例如計算基礎不同）
- ❌ **不一致**（無法解釋的差異）
- 🔍 **無法驗證**（原始資料中找不到對應依據）
```

> [!IMPORTANT]
> ### 「🔍 無法驗證」是這個練習的關鍵類別
> 稽核最重要的產出不是「找到錯誤」，而是**「找到無法驗證的宣稱」**。
>
> 一個數字沒有來源，不代表它錯——但它**不該出現在對外簡報上**。

## 🥈 練習二：三方交叉

```markdown
## Goal
比對「策略備忘錄的年度目標」「簡報的宣稱達成度」「會議手記的決議」三者。

## Scope
- 只讀取。
- **只評估有明確數字的目標**；純敘述性目標（如 G-8「顯著改善」）
  列在「無法量化評估」區。

## Verification
1. 目標達成對照表（目標 / 簡報宣稱 / 原始資料 / 判定）
2. **會議手記中的決議，有沒有在簡報中被正確反映？**
3. 「無法量化評估」清單
4. **三份文件之間的矛盾**（若有）
```

### 📝 應該找到的重點（講師用）

| 發現 | 說明 |
| :--- | :--- |
| **中區計算基礎不同** | 簡報有標註「僅 5 個月」——✅ 誠實。若沒標註就是 ❌ |
| **G-8「顯著改善」無法量化** | 策略備忘錄自己註明「暫以質化方式追蹤」 |
| **東區「扣除颱風後 96%」未出現在簡報** | ✅ 正確——會議手記標了「這個數字要再確認」，不該進簡報 |
| **決議「報表標資料缺漏不填 0」有被遵守嗎** | 簡報第 6 頁有資料說明頁 → ✅ 遵守 |

> **最後一項是好設計的展示**：會議上的決議（不填 0）確實反映在產出物（簡報第 6 頁）上。**稽核的價值就是確認這條鏈沒斷。**

## 🥉 練習三：圖與資料的一致性

```markdown
## Goal
檢查趨勢圖 png 上的數字，是否與 CSV 原始資料一致。

## Scope
- 先只看圖，還原數字。
- **再**讀 CSV 比對。
- 不要修改任何檔案。

## Verification
| 月份 | 圖上讀到 | CSV 實際 | 差異 | 可能原因 |

若有差異，判斷是：
- 你讀圖讀錯了
- 圖是用舊版資料做的
- 圖的口徑不同（例如含／不含離島）
- **無法判斷**
```

> **實務提醒**：簡報裡的圖表與原始資料對不上是**非常常見**的問題，通常因為做圖時用的是舊資料。稽核時務必查。

## 🏁 練習四：產出稽核報告

```markdown
## Goal
產出正式的內部稽核報告。

## Scope
- **不要修改 Drive 上的任何檔案。**
- 輸出 `output/2026H1_營運數據稽核報告.md` 與 `.xlsx`
- **陳述事實與證據，不做動機推測。**
  不寫「疑似灌水」「刻意隱瞞」這類指控。

## Verification
報告結構：
1. 稽核範圍與方法
2. 稽核結果彙總（✅ / ⚠️ / ❌ / 🔍 各幾項）
3. 逐項明細（含證據位置）
4. **需要澄清的項目**（🔍 無法驗證的部分）
5. 建議改善事項
6. **本次稽核的侷限**（你沒查到的、無法查的）

最後一段不可省略。
```

> **第 6 點是專業稽核報告的標誌。** 說清楚「我查了什麼、沒查什麼」，讀者才知道這份報告能支撐到什麼程度。
