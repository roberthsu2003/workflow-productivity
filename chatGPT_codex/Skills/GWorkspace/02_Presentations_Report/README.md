# GW-02. 營運回顧簡報

> 🔵 **方案需求**：Plus 起（Presentations plugin、Image inputs）。

**情境**：月檢討會前一天，你要把上半年數據做成 6 頁簡報，而且必須誠實呈現「中區有一個月沒資料」這件事。

## 🥇 練習一：讀圖（Image inputs）

先練「Codex 看得懂圖嗎」。

```markdown
## Goal
讀取 `sample_files/2026_上半年單量趨勢圖.png`，把圖上的資料還原成表格。

## Scope
- 只讀圖，不要參考其他檔案。
- **看不清楚的數字明說「無法辨識」，不要猜。**

## Verification
1. 還原的資料表（月份 / 數值）
2. 圖表的座標軸範圍與單位
3. **你無法從圖上確定的資訊**（例如：資料來源？是否含離島？）
```

### 進階：交叉驗證

```markdown
承上。現在讀取 CSV 原始資料，比對你剛才從圖上讀出的數字。

有沒有不一致？如果有，是你讀錯了，還是圖本身與資料不符？
```

> **這個練習有教學價值**：簡報裡的圖表**經常與原始資料對不上**（做圖時用的是舊版資料）。讓學員養成交叉驗證的習慣。

## 🥈 練習二：產出簡報

```markdown
## Goal
產出 2026 上半年營運回顧簡報，供月檢討會使用。

## Context
- 數據：`配送績效_2026Q1.csv` + `配送績效_2026Q2.csv`
- 聽眾：營運長與四區站長
- 時長：10 分鐘

## Scope
- **不要修改原始 CSV。** 輸出 `output/2026H1_營運回顧.pptx`。
- **中區 2026-06 資料缺漏。** 所有中區的平均值須以 5 個月計算並註明，
  不可用 0 代替，不可用鄰月推估。
- 一頁一主題，避免滿版文字。
- 不誇大績效；不確定的數據標「待確認」。

## Verification
6 頁結構：
1. 封面
2. 整體表現（對照年度目標）
3. 各區狀況
4. 待處理事項
5. 下半年重點
6. **資料說明**（缺漏與計算基礎）

**第 6 頁不可省略。** 沒有它，聽眾會以為所有數字的基礎都一樣。
```

### 📝 為什麼「資料說明頁」是必要的

> [!IMPORTANT]
> 中區只有 5 個月資料。如果簡報上並列四區的準時率而不說明，聽眾會直接比較——**但基礎不同，不能比。**
>
> 參考範例 pptx 的第 6 頁就是這個用途：
>
> > ⚠ 中區 2026-06 資料缺漏（WMS 系統移轉期間未落帳）
> > - 中區各項平均值以 5 個月為計算基礎，非 6 個月。
> > - 缺漏資料未以 0 或推估值填補。
> > - 跨區比較時請注意計算基礎不同。

## 🥉 練習三：口頭報告稿

簡報是給眼睛看的，講稿是給嘴巴用的。

```markdown
## Goal
為這份簡報產出 10 分鐘的口頭報告稿。

## Scope
- 每頁的講稿標明預估秒數，總計不超過 10 分鐘。
- **不要把投影片上的字唸一遍**——講稿要補充投影片沒寫的脈絡。
- 預留「營運長可能會問什麼」的問答準備。

## Verification
1. 逐頁講稿（含秒數）
2. **3 個最可能被追問的問題與建議回答**
3. 你**不建議主動提**但被問到要誠實回答的事項
```

> **第 3 點很實務**：例如「東區扣除颱風後的準時率」——這個數字目前還沒確認（見會議手記的「待整理」段落），不該主動宣稱，但被問到要說「還在確認」。

## 🏁 練習四：改用 Visualization

簡報的圖表是靜態的。如果會議上有人問「切到東區看看」呢？

```markdown
@Visualize

用同一份資料建立互動版本，可切換區域。

要求：
- 中區 6 月**線段斷開並標註「資料缺漏」**，不可畫成 0
- 含 95%（東區 92%）目標線

完成後說明：什麼情況下你會用簡報、什麼情況用互動視覺化？
```

> 見 [Visualizations 章節](../../../Visualizations/README.md)的四個出口比較。
