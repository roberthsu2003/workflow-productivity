> 🔵 **方案需求**：Automations 需 Plus 起。

追蹤所有送簽中的案件，**在卡關前提醒**。

---

## 🛠️ 建立

```bash
mkdir -p ~/.agents/skills/approval-tracker
cat > ~/.agents/skills/approval-tracker/SKILL.md <<'SKILLEOF'
---
name: approval-tracker
description: 追蹤送簽案件的進度，識別卡關與逾期風險。適用於已有簽核紀錄的案件清單；不要用於代為送簽、催辦，或推測簽核者未簽的原因。

# Approval Tracker

## 流程
1. 讀取簽核追蹤清單。
2. 對每案計算：**已送簽天數**、**目前卡在哪一關**、**距需求日剩幾天**。
3. 依下表判定風險。
4. **檢查「剩餘時間 vs. 後續所需時間」**——這是本 skill 的核心。
5. 產出報告。

## 風險判定
| 條件 | 風險 |
| :--- | :---: |
| 同一關卡停留 > 5 個工作天 | 🟡 |
| 同一關卡停留 > 10 個工作天 | 🔴 |
| **剩餘天數 < 後續關卡預估所需天數** | 🔴 **來不及** |
| 需求日已過但尚未完簽 | 🔴 |

## 後續關卡預估（用於判斷來不及）
| 關卡 | 預估天數 |
| 部門主管 | 2 |
| 營運長 | 3 |
| 總經理 | 5 |
| 採購下單至到貨 | 依料件而定，須由使用者提供 |

## 限制
- **不推測簽核者未簽的原因。** 只陳述「已停留 N 個工作天」。
- 不代為催辦、不代為送簽、不寄信。
- 「後續所需天數」若使用者未提供，標示「無法評估是否來得及」，**不要自行推估**。
- 工作天計算須排除週末（國定假日若使用者未提供則標註未排除）。

## 輸出
1. 🔴 **來不及的案件**（放最前面，含缺口天數）
2. 🟡 卡關案件
3. 正常案件
4. **無法評估的案件**（缺少後續時程資訊）
SKILLEOF
```

## ▶️ 測試

```text
$approval-tracker

| 案號 | 事由 | 送簽日 | 目前關卡 | 停留天數 | 需求日 |
| PO-2026-0915 | 冷鏈耗材採購 | 09-05 | 營運長 | 3 | 09-30 到貨 |
| TFL-BESS-2026-003 | 儲能建置 | 09-01 | 部門主管 | 12 | 12-31 完工 |
| HR-2026-0088 | 東區增員 | 08-25 | 總經理 | 14 | 10-01 到職 |

補充：PO-2026-0915 的料件交期 21 天。
```

### 📝 預期結果

**🔴 來不及**

| 案件 | 問題 |
| :--- | :--- |
| **PO-2026-0915** | 距需求日（9/30）剩 **22 天**，但「營運長簽核 3 天 + 交期 21 天 = 24 天」→ **缺口 2 天** |

**🔴 卡關**

| 案件 | 問題 |
| :--- | :--- |
| TFL-BESS-2026-003 | 部門主管停留 **12 個工作天** |
| HR-2026-0088 | 總經理停留 **14 個工作天**，且距 10/1 到職僅剩 23 天 |

---

## 🔑 核心設計：**「來不及」比「卡關」更重要**

> [!IMPORTANT]
> 大部分簽核追蹤只看「停留幾天」。
>
> 但**真正該預警的是「即使現在簽了也來不及」**——那時候催辦已經沒用，要改的是需求日或方案。
>
> PO-2026-0915 只停留 3 天（看起來很正常），**卻是最急的一件**。
