# Daily Ops Brief

把當日配送數據轉成 5 分鐘可讀完的營運簡報。

## 流程

1. **讀取資料**：讀取指定的配送績效 CSV。確認欄位包含：月份／日期、區域代碼、配送單量、準時率、平均配送時數、異常件數、客訴件數、備註。
2. **檢查資料完整性**：
   - 有任何欄位為空 → 標示「資料缺漏」，**不可用 0 或推估值填補**
   - 有備註欄內容 → 一律讀入，它通常解釋了異常的原因
3. **計算彙總**：全公司與各區的單量、準時率、異常件數。
   **計算平均時排除缺漏筆，並註明計算基礎筆數。**
4. **判定異常**，分三類（見下方判定標準）。
5. **套用範本**：使用 `templates/daily_brief_template.md` 的結構。
6. **產出**：寫入 `reports/YYYY-MM-DD_營運簡報.md`。

## 異常判定標準

| 分類 | 判準 | 處理 |
| :--- | :--- | :--- |
| 🔴 **真異常** | 準時率低於目標（全公司 95%、東區 92%），**且**備註欄無合理解釋 | 列入「需要處理」 |
| 🟡 **可解釋的波動** | 數值偏離常態，但備註欄有明確原因（檔期、天候、系統維護） | 列入「已知原因」，**不列為需處理** |
| ⚪ **資料問題** | 欄位為空或明顯不合理 | 列入「資料品質」，**不是營運問題** |

## 限制

- **不可修改原始 CSV。**
- **不可對缺漏值做內插、補 0 或用鄰期推估。**
- 數字必須與來源完全一致，不可四捨五入後再拿去計算。
- 沒有資料支持的推論，明確標示為「推測」。
- **不可因為數字難看就淡化，也不可因為想凸顯而誇大。**
- 若當日無任何異常，簡報照常產出，「需要處理」段落寫「無」——不要編造事項來填充。

## 輸出

依 `templates/daily_brief_template.md` 產出，並在對話中附上：

1. 產出檔的路徑
2. **你計算彙總時的資料基礎**（幾筆、排除了幾筆、為什麼排除）
3. 你對每個 🔴 判定所依據的證據

## 對外用語

若簡報會轉發給客戶或外部單位，內部術語須轉換：

| 內部 | 對外 |
| :--- | :--- |
| 異常件 | 延遲件 |
| 黑洞件 | 查詢中的包裹 |
| 爆倉 | 倉儲量能吃緊 |
| 末端延遲 | 最後一哩配送延遲 |
