# 延伸練習 08：每週簡報彙整（第四階：自動化專家）

> 🔵 **方案需求**：Automations 需 Plus 起。

把 [Level2 每日營運簡報](./Level2_Daily_Ops_Brief/SKILL.md)的邏輯**升級成每週自動執行**。

---

## 🛠️ 建立

```bash
mkdir -p ~/.agents/skills/weekly-brief
cat > ~/.agents/skills/weekly-brief/SKILL.md <<'SKILLEOF'
---
name: weekly-brief
description: 彙整一週的營運數據與程式碼變更，產出週報 .md。適用於已有該週原始資料時；不要用於月報、季報，也不要在資料不完整時以推估補足。
---

# Weekly Brief

## 流程
1. 判定週次區間（週一至週日），**明確寫出起訖日期**。
2. 讀取該區間的資料來源：
   - `data/` 底下該週的配送 CSV
   - `git log --since=<起> --until=<訖>`
   - 開放中的 PR 與 Issue
3. **檢查資料完整性**：該週應有 7 天資料，實際有幾天？缺哪幾天？
4. 彙整三段：已完成、風險、下週建議（最多 3 項）。
5. 寫入 `reports/YYYY-WW_週報.md`。**已存在則用 `_v2`，不覆蓋。**

## 限制
- **不要修改任何原始資料。**
- **資料缺漏標示「資料缺漏」，不可用 0 或推估值填補。**
- 計算平均時註明計算基礎天數。
- 「下週建議」最多 3 項，每項附理由與依據。
- **本週無事發生時，照常產出，「風險」段落寫「無」——不要編造。**

## 通知條件（供 Automation 使用）
只在符合下列任一時通知：
- 有測試失敗的 PR
- 有超過 7 天未更新的開放 PR
- 準時率低於 95%
- 資料缺漏超過 3 天

**其餘情況產出檔案但不通知。**
SKILLEOF
```

---

## ⏰ 接上 Automation

```text
每週一上午 9:00（Asia/Taipei）執行 $weekly-brief，彙整上週。

限制：
- 只讀取，不修改原始資料
- 不提交、不推送、不寄信
- 依 skill 的通知條件決定是否通知我
```

> 完整設定見 [Automations 範例 01](../../Automations/Examples/01_Weekly_Ops_Brief/README.md)。

---

## 🔑 第四階的重點：**通知條件寫進 skill**

> [!IMPORTANT]
> **把「什麼時候該通知」寫進 `SKILL.md`，而不是每次建立排程時重寫。**
>
> 好處：
> 1. 手動執行與排程執行的判準一致
> 2. 改判準只要改一個地方
> 3. 判準本身可以被 review 與版控

- [ ] 無事發生時「風險」寫「無」，**沒有編造**
