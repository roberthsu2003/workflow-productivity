# 會議類型與必要欄位

> 供 `meeting-secretary` skill 判斷不同會議類型需要記錄哪些欄位。

---

## 會議類型判別

依逐字稿內容判斷類型，**判斷不出來時預設用「一般會議」，不要猜**。

| 類型 | 特徵 | 額外必要欄位 |
| :--- | :--- | :--- |
| **例行週會／月會** | 固定議程、固定與會者、有「上次追蹤事項」 | 上次待辦的結案狀況 |
| **決策會議** | 有明確的待決事項、有表決或拍板 | **決議的表決／拍板方式**、反對意見 |
| **檢討會議** | 討論已發生的問題與原因 | 根本原因、改善措施、負責人 |
| **專案會議** | 圍繞單一專案的進度 | 里程碑狀態、風險、資源需求 |
| **客戶會議** | 有外部人員參與 | **對客戶的承諾事項**（需特別標示） |
| **一般會議** | 以上皆非 | — |

---

## 各類型的特別注意事項

### 決策會議

> [!IMPORTANT]
> **必須記錄反對意見與保留意見**，即使最後決議通過。
>
> 理由：日後回顧時，「當時有人反對嗎、反對什麼」是關鍵資訊。只記錄結論的會議紀錄，會讓後人以為當初是全體共識。

### 檢討會議

- **記錄事實與時序，不記錄責任歸屬。** 責任歸屬是主管的裁量，不是會議紀錄的功能。
- 改善措施必須有負責人與期限，否則歸入「待確認」。

### 客戶會議

> [!WARNING]
> **對客戶的任何承諾都要單獨列一段，並標示「已承諾事項」。**
>
> 這一段日後可能有合約意義。承諾的內容、日期、條件都要精確，**不可改寫或美化**。
>
> 若逐字稿中的承諾語意模糊（「應該可以」「我們盡量」），**保留原話並標示「語意模糊，需確認」**，不要自行判定為承諾或非承諾。

## 出席狀態

| 標示 | 意義 |
| :--- | :--- |
| 出席 | 全程參與 |
| 部分出席 | 中途離開或加入（**若逐字稿看得出來，須註明時段**） |
| 列席 | 非正式成員，受邀參與特定議題 |
| 請假 | 逐字稿中明確提及 |

**逐字稿中未提及的人，不要列入出席名單。** 寧可名單不完整，也不要憑空補人。

---

## 期限的記錄

| 逐字稿說法 | 記錄方式 |
| :--- | :--- |
| 「這週給我」 | 換算成具體日期，並標註「（依會議日推算）」 |
| 「月底前」 | 該月最後一個工作日，標註推算依據 |
| 「盡快」 | **不換算。** 記為「未定期限」，歸入待確認 |
| 「下次會議前」 | 若下次會議日期明確則換算，否則記為「下次會議前」 |
| 沒提到期限 | **不要補。** 歸入「待確認」 |

> **「盡快」不是期限。** 把它寫成任何具體日期都是捏造。

## 常見的失真模式

| 逐字稿原文 | ❌ 錯誤記錄 | ✅ 正確記錄 |
| :--- | :--- | :--- |
| 「你講得有道理」 | 決議：採納該建議 | 討論中未定案 |
| 「嗯，可以考慮」 | 決議：同意 | 討論中未定案 |
| 「我禮拜三問業務處」 | 決議：業務處負責處理 | 待確認：需業務處回覆 |
| 「這個我不能決定」 | （略過不記） | 討論中未定案，卡在權責 |
| 「大概八月中吧」 | 期限：8/15 | 期限：8 月中（未精確，待確認） |
| 「我們盡量」（對客戶） | 已承諾：會完成 | 語意模糊，需確認是否構成承諾 |
