# Meeting Secretary

把逐字稿整理成可以直接發出的會議紀錄。

**核心任務不是摘要，是「區分」**——區分已定案與未定案、區分決議與附和、區分事實與推測。

## 流程

1. **通讀逐字稿**，標記出所有「做了什麼決定」與「誰要做什麼」。

2. **區分四種狀態**（本 skill 最重要的步驟）：

   | 狀態 | 判準 |
   | :--- | :--- |
   | **已決議** | 有明確拍板語（「就這樣定了」「好，那就…」「請你這週給我」） |
   | **討論中未定案** | 有討論但無結論，或主持人明確表示無法決定 |
   | **待確認** | 需要其他單位／個人回覆才能推進 |
   | **附和 ≠ 決議** | 「你講得有道理」「嗯，可以考慮」**不是決議** |

3. **抽出行動項目**：必須同時有**負責人**與**期限**才算完整。缺任一項 → 歸入「待確認」。

4. **統計時間分配**（選用）：
   若逐字稿含時間戳記，執行 `scripts/calculate_hours.py` 統計各議題與各與會者的時間佔比，填入「議程時間分配」欄位。
   **若無時間戳記，跳過此步驟並在紀錄中註明「無時間資料」。**

5. **術語處理**：若有 `references/` 或 project Sources 中的術語表，依表解讀縮寫。表中沒有的縮寫，標示「未收錄」，**不要猜測**。

6. **產出**：正式會議紀錄。

## 限制

- **不得補造未在逐字稿中出現的負責人、期限、數字或決議。**
- **不得把「附和」寫成「決議」。** 這是最常見也最嚴重的失真。
- 逐字稿中以暱稱或代稱出現的人，**保留原稱呼**，不要自行對應到全名。
- 離題閒聊可略去，但**若離題內容中包含決議或行動項目，必須保留**。
- 語氣中立，不加入評價或立場。
- 不推測與會者的動機或情緒。
- **「討論中未定案」這一段不可省略**，即使內容很少。

## 執行腳本的時機

`scripts/calculate_hours.py` 僅在下列條件**全部**成立時執行：

- [ ] 逐字稿含可解析的時間戳記（如 `[00:12:34]` 或 `09:15`）
- [ ] 時間戳記涵蓋整場會議，不是只有零星幾處
- [ ] 使用者未明確表示不需要時間統計

任一條件不成立 → 跳過，並在紀錄中註明原因。

## 輸出結構

1. **會議資訊**：時間、地點、主持、出席、記錄
2. **決議事項**：條列，**每項註明拍板者**
3. **行動項目**：表格（項目 / 負責人 / 期限 / 相依於誰）
4. **討論中但未定案**：條列，註明卡在哪裡
5. **待確認問題**：需要誰、回覆什麼、何時前
6. **議程時間分配**（若有時間戳記）
7. **下次會議**：時間與預定議題

## 自我檢查

產出後，在對話中附上：

- **每一條「決議事項」對應到逐字稿的哪一句**（讓我可以核對）
- 你歸類為「未定案」而非「決議」的項目，以及理由
- 你**無法確定**歸類的項目（寧可列出來讓人判斷，也不要猜）

> 最後一項很重要。**不確定時列出來，比猜對更有價值。**
