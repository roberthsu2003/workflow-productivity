# 延伸練習 10：營運儀表板（第四階：自動化專家）

> 🔵 **方案需求**：Visualizations 或 Sites 需 Plus 起。

把前面所有 skill 的產出**匯聚成一個入口**。

---

## 🎯 這個練習的定位

前九個練習各自解決一件事。這一個練習的價值在於**串起來**：

```text
每日 → daily-ops-brief      → reports/YYYY-MM-DD_營運簡報.md
每週 → weekly-brief         → reports/YYYY-WW_週報.md
隨時 → approval-tracker     → 簽核卡關清單
隨時 → customer-crm         → 承諾追蹤與應升級案件
              ↓
        營運儀表板（一個入口）
```

---

## 🛠️ 建立

```bash
mkdir -p ~/.agents/skills/ops-dashboard
cat > ~/.agents/skills/ops-dashboard/SKILL.md <<'SKILLEOF'
---
name: ops-dashboard
description: 彙整既有的營運簡報、週報、簽核追蹤與客戶承諾紀錄，產出單一入口的營運儀表板。適用於已有這些產出檔時；不要用於重新計算原始數據，也不要在來源檔缺漏時以推估補足。
---

# Ops Dashboard

## 流程
1. 掃描 `reports/` 底下的既有產出。
2. **檢查新鮮度**：每個來源檔的最後更新時間。
3. 彙整四個區塊：
   - 🔴 **需要立即處理**（跨來源彙整所有 🔴 項目）
   - 📊 關鍵指標（準時率、單量、客訴）
   - ⏳ 卡關與逾期
   - 📈 趨勢
4. 產出視覺化或靜態報告。

## 限制
- **只彙整既有產出，不重新計算原始數據。**
  數字不一致時**指出來**，不要自行選一個。
- **每個數字標註來源檔案與該檔的產出時間。**
- 來源檔過期（超過 7 天未更新）時，**明確標示「資料可能過期」**。
- 來源檔缺漏時標示「無資料」，**不可用推估填補**。
- 資料缺漏在圖表上**斷線或標註**，絕不畫成 0。

## 輸出
1. 🔴 區塊（放最前面）
2. 各區塊內容
3. **資料新鮮度表**：| 來源 | 最後更新 | 距今 | 狀態 |
4. **無資料或過期的項目清單**
SKILLEOF
```

## 🔑 核心設計：**資料新鮮度**

> [!IMPORTANT]
> ### 儀表板最危險的失敗模式是「看起來是即時的，其實是三天前的」
>
> 彙整型產出必然有這個問題——它讀的是別人的產出，而那些產出各有各的更新頻率。
>
> **每個數字都要標註「這是什麼時候的資料」。**
>
> | ❌ | ✅ |
> | :--- | :--- |
> | 準時率 96.4% | 準時率 96.4%（來源：2026-09-06 日報，距今 2 天） |

---

## ⚠️ 數字不一致時

日報說準時率 96.4%，週報說 95.8%——**哪個對？**

> **正確做法：兩個都顯示，並指出不一致。**
>
> 錯誤做法：自己選一個、取平均、或只顯示比較好看的那個。
>
> 不一致本身就是一個發現——可能是計算口徑不同，也可能是某一份算錯了。

## ✅ 驗收

- [ ] 🔴 區塊在最前面，且跨來源彙整
- [ ] **每個數字都標了來源與時間**
- [ ] 有「資料新鮮度」表
- [ ] 過期資料有明確標示
- [ ] 數字不一致時**兩個都顯示並指出**
- [ ] 圖表上的缺漏資料是斷線或標註，**不是 0**

## 🎓 十個延伸練習的總結

| 階段 | 練習 | 核心能力 |
| :---: | :--- | :--- |
| L1 | 01 文案、02 待辦擷取 | **不編造事實** |
| L2 | 03 報價單、04 行動計畫 | **資訊不全就停下來問** |
| L3 | 05 交接、06 比價、07 CRM | **拿規範比對，發現使用者沒想到的問題** |
| L4 | 08 週報、09 簽核、10 儀表板 | **判準寫進 skill、通知條件、資料新鮮度** |

**貫穿全部十個的一條線**：**允許並要求 skill 說「我不知道」「這個要問人」「資料缺漏」。**
