# Remote：跨裝置交辦與雲端執行

> 🔵 **方案需求**：Plus 起。可用性依推出進度與工作區設定而定；Business / Enterprise 由管理員控管。

**Codex Remote 讓你從手機交辦任務，由你連線的電腦實際執行。** 你在手機上發起工作、即時看進度、核准它要求的動作，最後在手機上審查 diff 與測試結果。

> **對照 Claude**：這一章對應 Claude 的 **Dispatch**。目標相近，但 Codex 的操作單位是 **project、task 與 environment**。

---

## 🔀 Remote 與 Cloud：兩個不同的東西

這是本章最容易混淆的地方。

| | **Remote** | **Cloud** |
| :--- | :--- | :--- |
| 誰在執行 | **你自己的電腦** | OpenAI 的遠端環境 |
| 電腦要開著嗎 | ✅ **必須保持開機且連線** | ✗ 不需要 |
| 能存取本機檔案嗎 | ✅ 完整存取 | ✗ 只能存取已推送的內容 |
| 手機的角色 | 遙控器：發起、核准、審查 | 一樣可從手機發起 |
| 適合 | 需要本機環境、本機資料的工作 | 可重現、隔離的批次工作 |

兩者**互補**：Remote 專注於行動端的任務發起與核准，Cloud 處理分散式運算與持久化。

## 🔗 設定步驟

### Step 1：在電腦上開放連線

ChatGPT 桌面版 → `Settings` → `Connections`

### Step 2：用手機掃描 QR Code

用手機的 ChatGPT App 掃描桌面顯示的 QR code 完成配對。

### Step 3：驗證

兩台裝置各自完成核准步驟。**必須使用同一個 ChatGPT 帳號與同一個 workspace。**

### Step 4：從手機交辦

在手機 App 的 **Remote** 分頁選取已連線的電腦，描述任務。

## ⚠️ 前置條件

> [!WARNING]
> ### 你的電腦必須保持開機且連線
> 這是 Remote 最容易踩到的坑。筆電闔上休眠、Wi-Fi 斷線、系統自動更新重開機——任務就中斷了。
>
> **課堂或重要工作前請確認**：
> - [ ] 電源已接上
> - [ ] 系統休眠設定已調整（macOS：`caffeinate` 或系統設定的「防止自動進入睡眠」）
> - [ ] 網路穩定
> - [ ] ChatGPT 桌面版保持執行中

## 🔐 使用前的安全確認

Remote 執行的是**你電腦上的真實動作**，而你人不在電腦前。

- [ ] **權限模式**：維持 **Ask for Approval**——這樣它要跨界時會在手機上問你
- [ ] **工作目錄**：確認綁定的是正確的 project，不是你的家目錄
- [ ] **Git 狀態**：開始前已 commit，隨時可以 `git restore`
- [ ] **secrets**：透過安全設定提供，**不要寫進 prompt 或 repo**
- [ ] **本機同步**：任務不依賴尚未同步／尚未儲存的本機檔案
- [ ] **對外動作**：明確指定是否允許 push、開 PR、寄信或發佈

> [!IMPORTANT]
> **未授權時只產出草稿。** 手機上審查的資訊量遠少於桌機——不要在手機上核准你看不完整的變更。

## 📱 手機端能做的事

| 動作 | 說明 |
| :--- | :--- |
| **發起任務** | 描述工作內容與範圍 |
| **即時監看進度** | 看它正在做什麼 |
| **核准請求** | 它要跨出 workspace、要上網、要執行危險命令時會問你 |
| **審查結果** | 看 diff 與測試輸出 |
| **決定下一步** | 繼續、調整方向、或中止 |

## 🧪 適合 Remote 的任務型態

### ✅ 適合

| 情境 | 為什麼適合 |
| :--- | :--- |
| 通勤路上想到要修一個小 bug | 電腦在公司，環境齊全 |
| 出門在外要跑一次完整測試 | 測試需要本機環境 |
| 需要讀取本機的大型資料集 | 資料沒上雲 |
| 想先讓它做診斷，回家再修 | 只讀任務風險低 |

### ❌ 不適合

| 情境 | 為什麼不適合 |
| :--- | :--- |
| 大範圍重構 | 手機上審查不完 diff |
| 涉及對外發佈或寄信 | 核准的資訊不足以判斷 |
| 需要頻繁往返討論 | 手機打字效率低 |
| 電腦可能休眠的時段 | 會中斷 |

## 📝 適合 Remote 的 task 範本

```markdown
## Goal
診斷 tideflow-portal 的結帳頁在 Safari 上版面跑掉的原因。

## Context
- 重現：Safari 17，寬度 < 768px 時，運費列溢出容器
- 相關檔案推測在 `src/checkout/` 底下的樣式

## Scope
- **只診斷，不要修復。**
- 只讀取檔案與執行測試，不修改任何檔案。
- 不要 push、不要開 PR。

## Verification
輸出：
1. 根本原因（檔案 + 行號）
2. 支持判斷的程式碼片段
3. 建議的修法（我回到電腦前再決定）

**輸出請控制在手機可讀的長度——重點先講，細節放後面。**
```

> **課堂重點**：最後那句「輸出請控制在手機可讀的長度」很實用。遠端任務的產出要為小螢幕設計。

## ☁️ Cloud 環境的額外考量

若改用 Cloud 而非 Remote：

- [ ] Cloud 環境**能安裝依賴並執行測試**（先驗證一次）
- [ ] secrets 透過安全設定提供
- [ ] 任務**不依賴尚未推送的本機變更**
- [ ] 明確指定是否允許 push、開 PR、寄信或發佈

> [!WARNING]
> **Cloud 看不到你未 commit 的本機修改。** 最常見的失敗是：你在本機改了一半，交給 cloud 繼續做，結果它從 remote 的版本開始，做出來的東西對不上。**先 commit and push，再交給 cloud。**

## 🔄 與 Claude Dispatch 的對照

| 面向 | Claude Dispatch | Codex Remote |
| :--- | :--- | :--- |
| 方案 | Pro / Max Only（Beta） | 🔵 Plus 起（依推出進度） |
| 執行位置 | 你的電腦 | 你的電腦（Remote）或雲端（Cloud） |
| 配對方式 | 帳號連結 | **QR code 掃描 + 雙裝置驗證** |
| 操作單位 | 任務 | **project + task + environment** |
| 手機端能做 | 交辦、取回成品 | 交辦、**即時核准**、審查 diff 與測試 |
| 成品回傳 | 傳回手機 | 留在電腦上，手機審查 |

> **最大差異**：Dispatch 偏向「交辦 → 等結果」；Remote 是**全程可介入**——它要做危險動作時會在手機上問你，你可以即時擋下。

## 小結

| 要點 | 說明 |
|---|---|
| Remote vs Cloud | Remote 用**你的電腦**（要開機）；Cloud 用**遠端環境**（要先 push） |
| 設定 | `Settings` → `Connections` → 手機掃 QR code |
| 前提 | 電腦保持開機連線、同帳號同 workspace |
| 安全 | 維持 Ask for Approval；未授權只產草稿 |
| 適合 | 只讀診斷、小範圍修改、需要本機環境的工作 |
| 不適合 | 大範圍重構、對外發佈、需要頻繁討論的工作 |
