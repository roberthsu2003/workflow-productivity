# Tasks 與提示詞

Codex 中每一段工作是一個 task。不同專案或不相干目標應拆成不同 task。

```markdown
## 目標
要完成的可觀察結果。
## 背景
業務目的、使用者、相關檔案或既有行為。
## 範圍與限制
可以與不可修改的項目、技術或格式限制。
## 驗收
必須通過的測試或可觀察結果。
```

- 問答／檢視：要求只讀分析，不授權修改。
- 診斷：要求找出原因與證據；若不需修復，要明說。
- 建構／修改：Codex 可在範圍內改檔並測試。
- 長時間工作：一次性用 goal；週期性用 automation。

直接指出檔案、畫面、錯誤訊息或期望行為，通常不需要把整份程式碼貼進 Prompt。
