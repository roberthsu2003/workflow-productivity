# 排程範例 02：庫存監控

> 🔵 **方案需求**：Plus 起。

**類型**：掛在現有 chat（保留上下文）
**頻率**：每日 10:00 與 16:00（Asia/Taipei）
**授權**：唯讀

---

## 📂 示範資料

[`inventory_status.csv`](./sample_files/inventory_status.csv) — 8 個料號，欄位：料號、品名、目前庫存、安全水位、日均耗用、預估可用天數、狀態。

**資料中有三種狀況**：

| 料號 | 品名 | 庫存 / 安全水位 | 預估可用 | 狀況 |
| :--- | :--- | :--- | ---: | :--- |
| `BX-1003` | 冷鏈保溫箱 | 640 / 800 | 4.4 天 | **低於安全水位**（但還有幾天緩衝） |
| `TP-2002` | 易碎品標籤 | 180 / 500 | 1.9 天 | **低於安全水位，且 2 天內歸零**（最急迫） |
| `CL-4001` | 乾冰 | 240 / 200 | 2.0 天 | 庫存**高於**安全水位，但**2 天內歸零** |

> [!IMPORTANT]
> ### `CL-4001` 乾冰是這份資料最重要的埋伏
> 它的庫存 240 **高於**安全水位 200——只看「庫存 < 安全水位」的檢查會**完全漏掉它**。
> 但它的日均耗用高達 118，**2 天後就會歸零**。
>
> 這說明了為什麼排程要同時檢查**兩個條件**：庫存水位 **與** 預估可用天數。
> 只檢查其中一個，都會漏掉真正的風險。

---

## 為什麼用「掛在現有 chat」

庫存監控需要**記得上次通知過什麼**。否則冷鏈保溫箱低於水位的那一天，你會在 10:00 收到通知、16:00 又收到一次、隔天再兩次——同一件事被通知八次。

> 對照：[範例 01 週報](../01_Weekly_Ops_Brief/README.md)用「獨立任務」，因為每週都該從零開始。

---

## ⚙️ 排程設定

```text
在這個 chat 中，每天上午 10:00 與下午 4:00（Asia/Taipei）
檢查 `data/inventory_status.csv`。

## 檢查項目
1. 目前庫存 < 安全水位的品項
2. 預估可用天數 ≤ 3 天的品項
3. 相較上次檢查，**新出現**的問題品項

## 通知條件（只在符合時才通知）
- 出現**新的**低於安全水位品項
- 出現**新的**預估 3 天內歸零品項
- 已知問題品項的庫存**進一步惡化超過 20%**

## 不通知的情況
- 所有品項正常
- **已通知過的問題品項狀態沒有明顯變化**（避免重複轟炸）

## 通知內容
| 料號 | 品名 | 目前庫存 | 安全水位 | 日均耗用 | 預估耗盡日 | 這是新問題嗎 |

## 限制
- **只讀取 CSV，不要修改。**
- 不要建立採購單、不要寄信、不要通知供應商。
- 預估耗盡日以「目前庫存 ÷ 日均耗用」計算，**明確標示這是線性推估**。
- 日均耗用為 0 或空值時，標示「無法推估」，不要當成「永遠夠用」。
```

---

## 🔑 關鍵設計：「這是新問題嗎」

> [!IMPORTANT]
> **這一欄是整個排程的靈魂。**
>
> 沒有它，每天兩次通知會告訴你「冷鏈保溫箱庫存不足」——連續兩週。有了它，你只會在**狀態改變時**被打擾。

這也是為什麼要「掛在現有 chat」：它需要對話的歷史才知道什麼是「新」的。

---

## ⚠️ 線性推估的侷限

```text
預估可用天數 = 目前庫存 ÷ 日均耗用
```

這個算法有明確的侷限，**排程的產出必須說出來**：

| 侷限 | 影響 |
| :--- | :--- |
| 假設耗用速度不變 | 檔期（雙 11）會讓實際耗盡快得多 |
| 不考慮在途庫存 | 已下單未到貨的量沒算進去 |
| 不考慮採購前置期 | 「還有 3 天」但採購要 7 天，其實已經來不及 |

> **教學重點**：讓模型產出數字很容易，讓它**說出這個數字的侷限**才是有價值的設計。
>
> 在 prompt 中要求「明確標示這是線性推估」，就是在做這件事。

---

## 🚫 為什麼不讓它自動下採購單

技術上做得到，但**不應該**：

| 動作 | 排程可以做嗎 | 為什麼 |
| :--- | :---: | :--- |
| 讀取庫存、計算、通知 | ✅ | 可逆、無外部影響 |
| 產生採購單**草稿** | ✅ | 仍需人核可 |
| **送出**採購單 | ❌ | 不可逆、涉及金錢、供應商會真的出貨 |
| 通知供應商 | ❌ | 對外動作 |

> 排程執行時你不在旁邊，**沒有人可以按取消**。見 [Automations 主章節的授權分級](../../README.md#-寫入型任務的授權邊界)。
